# 移植対応表（VBA → Python Web）

対象の版: 梱包明細 VER 0.13.29(コイル梱包ツール 1.2.33)

VBA の手続き・変数と、移植先の関数・ファイル・画面の対応。
「どこを直せばよいか」を探すときはこの表から入る。

> **VBA の元ソースはリポジトリに無い。** この表は、移植したコードの注記（`VBA \`…\`` と書いた箇所）・
> `docs/変更履歴.md`・`README.md` から組み立てた。VBA 側の名前はすべて注記に出てくるもので、
> 注記に無い手続きは載せていない（あるはずだが名前が分からないものは `docs/03_不明点と要確認事項.md`）。
>
> - 注記は `grep -rn "VBA" meisai app` で拾える（`modules/packing_details/` で実行）。
> - パスは `modules/packing_details/` からの相対。`routes/` は `app/routes/`、`js/` は `app/static/js/`、`templates/` は `app/templates/`。
> - 「根拠」の欄は、その対応が書いてある注記の場所。
> - VBA の動き（何をしていたか）は `docs/01_VBA解析書.md`。

## 11. 外したもの（VER 0.13.23・現場の判断）

移植元 0.13.1（単体リポジトリ `packing-details-python-web`）までは移植してあった。注記はそちらにだけ残っている。

| VBA | 移植元 0.13.1 での移植先 | いま | 理由 |
|---|---|---|---|
| `chkSpecifyNo`（No指定） | `meisai_service.output` の `specify_no`、`js/meisai.js` の `chkSpecify` | **外した**。古い画面が `specify_no` を送っても読まない | 出し直しは「出力済み修正」で足りる。番号を手で打つと、打ち間違いで別の紙を上書きしうる（`meisai_service.py` 冒頭） |
| `SetCurrentSeq`（No指定で連番を引き上げる） | `meisai_service.output` → `history_repo.set_seq` | 外した（`set_seq` は残っている） | No指定と一緒に外した |
| `cmdClearDup_Click`（副番履歴クリア） | `POST /api/clear-history`（`routes/meisai.clear_history`） | **外した** | 副番履歴だけ消すと、No1〜No3 で使ったコイルを No4 へまた積めてしまう（`routes/meisai.py`「全クリア」の上の注記） |
| `ResetAllGimmickBUsed` | `Board.release_all_used` | 外した | 副番履歴クリアと一緒に外した |
