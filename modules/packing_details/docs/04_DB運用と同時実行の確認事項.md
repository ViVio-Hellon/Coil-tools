# DB 運用・長時間起動・同時実行の確認事項

対象の版: 梱包明細 VER 0.13.30(コイル梱包ツール 1.2.42)

Access → SQLite の置き換え、長時間の起動、複数 PC からの同時書き込みについて、
**いまの作り・決まりの値・残る確認事項**をまとめる。
根拠の場所を各所に書く（パスは `modules/packing_details/` からの相対。`common/` はリポジトリ直下）。

---

## 0. 前提 ― どのファイルを、誰が、どう使うか

VBA は仕掛台帳（Access）を ADO ＋ ACE で **直接** 開き、作業の記録はブックの隠しシート「副番履歴」に持っていた
（`docs/01_VBA解析書.md` §3・§7）。移植版はこれを次のように分けた。

| ファイル | 中身 | 置き場所 | 読み書き | 共有 |
|---|---|---|---|---|
| 仕掛台帳 `SIKALOT` / `SIKAHIKI` / `SIKAODR` | ロット情報・引当・受注 | 共有（`\\nlmsrvngy03\Read\【New】仕掛\台帳`） | **読むだけ**（手元へ写してから） | 全 PC が読む |
| 梱包課共有の仕掛 `LS4LOT`（名前は変えられる） | 縦割数・横割数 | 共有（`…\梱包課\梱包課共有\仕掛`） | **読むだけ**（同上） | 全 PC が読む |
| 手元 DB `packing_details.db` | 取り込んだ台帳の写し・副番履歴・途中経過・出力した明細・送る前の明細の履歴 | `%LOCALAPPDATA%\PackingDetails\data\` | 読み書き | **しない**（PC ごと） |
| 梱包資材マスタ `梱包資材マスタ.sqlite3` の表「梱包明細打ち出し」 | 紙面の右上の文字（正） | 共有（梱包資材マスタのフォルダ） | 読む（写してから）・ID=1 の行の 1 列だけ書く | 全ライン |
| 打ち出し json `梱包明細打ち出し.json` | 右上の文字の控え・管理者パスワード（撹拌済み） | 同上（場所は変えられる） | 読み書き | 全ライン |
| 履歴 DB `梱包明細履歴.sqlite3` | 明細の履歴（全ライン・3 年） | 同上（場所は変えられる） | 手元から送って書く・読む | 全ライン |
| この PC の設定 `user_config.json` | 置き場所・自動取り込み・共有の値の写し | `%LOCALAPPDATA%\PackingDetails\data\` | 読み書き | しない |
| 写し（一時フォルダ） | 取り込み元・マスタを読むための写し | この PC の一時フォルダ（`cpt_src_…`） | 読むだけ | しない |

根拠: `meisai/config.py`、`meisai/schema.sql`、`meisai/shared_settings.py` 冒頭、`meisai/slip_history.py` 冒頭、`common/source_copy.py` 冒頭。

**画面と業務の処理は手元の表しか見ない。** 共有へ触るのは、取り込み・右上の文字・明細の履歴・マスタ管理のときだけ（`meisai/data_sync.py` 冒頭）。

## 1. Access → SQLite（取り込み元）

### 1.1 VBA との違い

| | VBA | 移植版 | 根拠 |
|---|---|---|---|
| 取り込み元の形式 | Access（`SIKALOTNOW.accdb` 等） | sqlite3（`SIKALOT.sqlite3` 等。上流が sqlite3 化された） | `config.LOT_DB_FILES` |
| 経路 | ADO ＋ ACE で直接開く | 標準ライブラリの `sqlite3` だけ。**手元へ取り込んでから**引く | `README.md`、`data_sync.py` |
| 追加の部品 | ACE が要る | 要らない（ラインの PC に追加ライブラリを入れられない） | `README.md`「必要環境」 |
| SQL | `SELECT TOP 1` | `LIMIT 1` | `lot_repo.py` 冒頭 |
| 列名 | 半角カナ（`ﾛｯﾄ番号` `ｵｰﾀﾞｰ板丈`） | 全角へ寄せる（対応表 `import_specs.IMPORT_SPECS`） | `import_specs.py` 冒頭 |
| 待ち | `ConnectionTimeout = 10秒` | 取り込み元は `busy_timeout` 10 秒 | `source_db.BUSY_TIMEOUT_MS` |

### 1.2 取り込みで数へ直す（移植の要点）

取り込み元は **全列 TEXT**（LS4LOT は型宣言すら無い）。そのまま引くと VBA の条件が 1 件も一致しない（`import_specs.py` 冒頭、`README.md`）。

| 列 | 取り込み元の実値 | そのまま引くと | 直したあと |
|---|---|---|---|
| `ｵｰﾀﾞｰ板丈` | `'0.0'`（`'0'` ではない） | `= '0'` も `= 0` も 0 行（全 13,624 行中） | `to_real` → `= 0` で 7,826 行 |
| `当工程設計_縦割数` | `'2'` | `= 2` が 0 件 | `to_whole` → 整数 |

- 板厚・板幅は VBA の `Val` と同じ読み方（`import_specs.vba_val`）。
- 縦割数・横割数は整数でなければ 0（`to_whole`。→ `docs/03_不明点と要確認事項.md` A-2）。
- VBA が読む列だけを取り込む。仕掛ロットは 196 列あるが、使うのは 10 列と抽出条件の 1 列（`IMPORT_SPECS` の注記）。

### 1.3 取り込みの流れ

`data_sync.import_all`。

```
1. 置き場所を引く      config.lot_db_dir() / konpo_db_dir() / lot_db_dir2()
2. ファイルを探す      find_sources()   (.sqlite3 → .db の順。共有に届かなければアプリのフォルダの写しも探す)
3. 手元へ写して読む    source_db.read_table() → common/source_copy.local_copy()
4. 総入れ替え          表ごとに DELETE → INSERT(1 まとまり)
5. 取り込み記録        いつ・どのファイルから・何件(取り込み記録 表)
```

| 決まり | 内容 | 根拠 |
|---|---|---|
| 総入れ替え | 取り込み元はキーを持たないスナップショットで、差分の手掛かりが無い | `data_sync.py` 冒頭 |
| 1 表が失敗しても続ける | 「全部止まる」より「入るものは入る」 | 同上 |
| 鍵の列が無ければ入れない | 空の鍵で総入れ替えすると、それまで使えていたデータまで消える | `data_sync.import_table` |
| 変わっていないファイルは飛ばす | 元ファイルの更新時刻が前回より 1 秒を超えて新しいときだけ読む（共有は秒未満の精度が落ちる） | `data_sync.needs_import` |
| 一度も取り込んでいなければ読む | 分からないのに「変わっていない」と答えない | 同上 |
| 画面の「取り込み」・設定の「保存して取り込み」 | `force` で、変わっていなくても読む | `app/static/js/meisai.js`・`settings.js` |
| 起動時の自動取り込み | 既定は「する」。変わったファイルだけ読む。配布設定を読んだあとに始める | `__init__.py` `initialize` / `_start_auto_import` |
| 鮮度の記録 | 表の名前で引く（パスで引くと、共有に届かない PC で「未取込」と出る） | `schema.sql`「取り込み記録」 |

### 1.4 手元へ写してから読む（`common/source_copy.py`）

統合 1.2.28（梱包明細 VER 0.13.27）から、取り込み元は **読む前に必ずこの PC の一時フォルダへ写す**。共有の上のファイルは直接開かない（現場の指示）。

| 決まり | 内容 |
|---|---|
| なぜ | 上流（仕掛台帳を作る仕組み・マスタを差し替える人）を待たせない／共有（SMB）の上の sqlite3 は WAL・ロック・URI の書き方しだいで開けない／読んでいる途中で上流が書き換えても、読み始めた時点の中身でそろう |
| 写すもの | 本体と `-wal` / `-journal`。`-shm` は写さない（手元で作り直される） |
| 書き換わったら | 写す前と後で大きさ・更新時刻を比べ、違えば写し直す（`RETRIES` = 3 回、`RETRY_WAIT_SEC` = 0.5 秒）。3 回とも書き換わっていたら「上流が書き込み中かもしれません」で断る |
| 同じなら | 大きさ・更新時刻が前と同じなら写し直さない |
| 写しの名前 | 毎回別の名前（前の写しを誰かが開いていても止まらない） |
| 写しの後片付け | アプリが終わると一時フォルダごと消す |
| 開き方 | 写しを `query_only` で開く（`source_db._try_copy`） |
| 書くとき | 写しへは向けない（共有のファイルをそのまま開く。マスタの右上の文字の書き換えなど） |

**取り込み元へは 1 バイトも書かない**（VER 0.3.1 で確かめた。`-wal` / `-shm` も作らない）。

### 1.5 第1パス・第2パス・LS4LOT の形式

置き場所の決まりは `docs/05_設定ガイド.md` §2、ファイルの形式と列は、リポジトリ直下の `docs/仕掛ファイルの仕様.md`。

- 第1パスに無いファイルは第2パスから読み、第1パスに無いロット・受注は第2パスから足す（両方にあれば第1パス）。
- LS4LOT は名前で形式が変わる（`LS4LOT` ならいままでの形式、それ以外は実績の形式。実績の形式は **取り込んだ時点の年月の行だけ**）。

### 1.6 文字コード

取り込み元の文字が UTF-8 か CP932 かを **ファイル単位で 1 つに決めてから** 読む（`source_db.sniff_encoding`）。
値ごとに試すと、CP932 のバイト列が UTF-8 としても読めてしまう場合に黙って化けるため。

## 2. 手元 DB（`packing_details.db`）

| 項目 | 値・決まり | 根拠 |
|---|---|---|
| 置き場所 | `%LOCALAPPDATA%\PackingDetails\data\packing_details.db`（環境変数 `PACKING_DETAILS_DB_PATH`） | `config.DB_PATH` |
| 共有に置かれたら | UNC パス・ネットワークドライブなら、起動ログとバージョン情報に理由を出す（起動は止めない） | `config.db_path_problem` |
| 接続 | 要求ごとに開いて閉じる（常駐接続を持たない） | `db.py` 冒頭 |
| ジャーナル | WAL（読み取りが書き込みに待たされない） | `common/sqlite_toolkit.enable_wal` |
| ロック待ち | `busy_timeout` 4 秒（`db.BUSY_TIMEOUT_MS`） | `db.py` |
| まとまり | 1 操作 = 1 トランザクション（`BEGIN IMMEDIATE`）。全部書けるか、1 行も書かないか | `db.transaction` |
| やり直し | まとまりごとに 2 回まで。最悪 4.0 + 0.5 + 4.0 + 1.0 + 4.0 = **13.5 秒** で返す | `db.TX_MAX_RETRY` / `TX_RETRY_WAIT_SEC` |
| 書けなかったら | `db.WriteError` → 画面に 503 と理由（`write_failed`） | `db.write`、`app/__init__.py` |
| 書く要求の順番 | プロセスの中で 1 つずつ（`_WRITE_LOCK`）。心拍・`/api/history/`・`/api/master/` は入れない（共有を待つことがあるため） | `app/__init__.py` |
| 画面からの送り方 | 押した順に 1 つずつ。押した画面のロットを `X-Screen-Lot` に付け、いまのロットと違えば 409 `lot_changed` | `meisai.js` の `queued`、`routes/meisai._refuse_other_lot` |
| 連番の採番 | 条件付き更新（`UPDATE … WHERE 現在連番 = ?`）。8 本同時でも重複なし | `history_repo.next_seq`、変更履歴 VER 0.3.1 |
| 壊れていたら | 横へ退けて（`packing_details.壊れていた_日時.db`。消さない）作り直し、起動を続ける。`database is locked` は壊れたとみなさない | 変更履歴 VER 0.13.14、`common/db_recover.py` |
| 列を足すとき | 業務の記録の表は作り直さず `ALTER TABLE` で足す（`db._ADDED_COLUMNS`） | `db.py` |

> **以前の不具合（VER 0.3.1）**: 失敗を戻り値で返す関数の結果を捨てていて、1 行も書けていないのに
> 「出力しました」と出ていた。業務の記録はすべて `db.write()` / `db.transaction()` を通す（`README.md`「書き込みの決まり」）。

## 3. 共有のファイル（全ライン）

### 3.1 梱包資材マスタの表「梱包明細打ち出し」（右上の文字の正）

| 決まり | 内容 | 根拠 |
|---|---|---|
| 読む | ID=1 の行の `設定文字列`。ID の列に型が無いので、`1` と `'1'` を同じに扱う | `shared_settings._read_master` |
| 書く | `設定文字列` の 1 列だけ。ID=1 が無ければ 1 行足す。**表を作らない・形を変えない・ほかの表に触らない** | `shared_settings.py` 冒頭 |
| ID=1 が 2 行 | 上の行を使い、変えるときは両方書き換え、設定画面とログにそう出す | 同上、変更履歴 VER 0.9.0 |
| 読めないとき | 控えの JSON で刷り、紙面の画面にそう出す。**変えるほうは断る**（JSON にだけ書くと、次にマスタが読めたとき黙って古い値に戻る） | `shared_settings.py` 冒頭 |
| ジャーナル | マスタは **DELETE** で置く（WAL だと共有の上では読めず、書けない） | `README.md`「全ラインで共有する設定」 |

### 3.2 打ち出し json（`梱包明細打ち出し.json`）

| 決まり | 内容 | 根拠 |
|---|---|---|
| 中身 | `format` / `qa_mark`（控え）/ `admin_password`（PBKDF2 で撹拌した値）/ `updated_at` / `updated_by`（PC 名 / 利用者） | `shared_settings.py` 冒頭 |
| 書き方 | 別名で書いてから置き換える（`os.replace`）。読む側は書きかけを見ない | 同上 |
| 置き換えが断られたら | ほかの PC が読んでいる最中。0.1 秒おきに 20 回まで | `REPLACE_TRIES` / `REPLACE_WAIT_SEC` |
| 読む上限 | **2 秒**（紙面を開くたびに読むので短く）。待ちきれなければこの PC の写しで刷る | `READ_TIMEOUT_SEC` |
| 写し | 最後に読んだ値を `user_config.json` に持つ。どの共有から読んだかも持つ（置き場所を変えたら前の共有の写しは使わない） | `CACHE_KEY` |

### 3.3 履歴 DB（`梱包明細履歴.sqlite3`）

**共有へ直接書かない。** 手元の DB に先に書いて（出力と同じまとまり）、裏で送る（`slip_history.py` 冒頭）。

```
手元の DB (この PC)          明細履歴 / 明細履歴_副番      … 出力と同じまとまりで先に書く
  ↓ 送る(出力・書き足し・紙面を開いたらすぐ。届かなければ 5 分ごと)
共有 梱包明細履歴.sqlite3     明細履歴 / 明細履歴_副番 / 整理記録 … 全ライン
```

| 決まり | 値・内容 | 根拠 |
|---|---|---|
| 送る間隔 | すぐ（`kick`）、届かなければ **300 秒** ごと | `config.HISTORY_SEND_INTERVAL_SEC` |
| 1 回に送る枚数 | **500 枚** まで（共有を長く掴まない） | `SEND_BATCH` |
| 同時に送るのは | 1 プロセスで 1 本だけ | `_send_lock` |
| 二重にしない | 1 枚ごとに一意の `送信ID`（共有では主キー）。`INSERT OR IGNORE` のあと、変わる列だけ `UPDATE`（UPSERT はラインの PC の古い SQLite で通らないため使わない） | `_write_rows` |
| 送ったあとに変わった行 | 読んでから送るまでに書き足しがあれば、送れたことにしない（`変更回数` で比べる） | `_send` |
| ロック待ち | 共有の SQLite は **10 秒** | `SHARED_BUSY_SEC` |
| ジャーナル | このアプリが **DELETE** で作る（`PRAGMA journal_mode=DELETE`。DELETE にならなければ断る） | `_open_shared` |
| 無ければ作る | ファイル・表が無ければ作る。手で作った表で列が足りなければ足す。足せない列（送信ID など）が無い表には触らずに断る | `ensure_shared`、VER 0.12.0 |
| 残す年数 | **3 年**。それより前は共有も手元も **1 日 1 回** 整理（共有は `整理記録` に日付を残す）。`VACUUM` はしない | `config.HISTORY_KEEP_YEARS`、`_purge_shared` / `_purge_local` |
| 読む | 共有のファイルを `mode=ro` で開く（**写さない**。→ D-5）。届かなければこの PC の分だけで探し、そう出す | `slip_history._read_only`、`search` |
| 列「モード」 | テストモードで出した紙だけ「テストモード」（VER 0.13.30。手元・共有とも最後の列）。前の版の手元の表は `db._ADDED_COLUMNS`、共有の表は `_repair_shape` が列を足す（行は消さない） | `record_output`、`SHARED_DDL` |

### 3.4 鍵ファイル（共有へ書くのを 1 台ずつにする）

共有の 2 つ（打ち出し json・履歴 DB）は、横に鍵ファイルを置いてから書く。**ファイルごとに別の鍵**（右上の文字を変えるのと、履歴を送るのとを互いに待たせない）。

| 鍵 | 守るもの |
|---|---|
| `梱包明細打ち出し.json.lock` | 打ち出し json（とマスタの表の書き換え） |
| `梱包明細履歴.sqlite3.lock` | 履歴 DB（送る・作る） |

| 決まり | 値 | 根拠 |
|---|---|---|
| 取り方 | 「無ければ作る（あれば失敗）」（`os.open` に `O_CREAT` と `O_EXCL`）。ネットワークの共有でも効く、いちばん古いやり方 | `shared_settings._locked` |
| 待つ上限 | **5 秒**。過ぎたら「ほかの端末が共有の設定を書き換えています」 | `LOCK_WAIT_SEC` |
| 残った鍵 | **30 秒** より古い鍵は、書いた PC が落ちて残ったものとみなして外す | `LOCK_STALE_SEC` |
| アクセス拒否 | Windows で、ほかの PC が鍵を消している最中に作ると拒否される。**2 秒** まで繰り返す（それ以上なら本当に書けない） | `LOCK_DENIED_SEC`、VER 0.13.13 |
| 中身 | 書いた PC・利用者・日時 | `_locked` |

### 3.5 作業の記録・資材マスタの編集履歴（VER 0.13.30）

| 何を | どこへ | 決まり | 根拠 |
|---|---|---|---|
| 作業の記録 | この PC の `records\梱包明細記録_YYYY-MM.csv`（いつも。形式は設定で CSV／JSONL／両方）と、設定があれば `<記録の保存先フォルダー>\<PC名>\` | 1 行足すだけ（消さない・書き換えない）。PC ごとのファイルなので鍵は取らない。Excel で開いていて書けない間は「追記待ち」に足し、次に書けたときに書き足す。書けなくても出力は止めない | `work_record.append` |
| 資材マスタの編集履歴 | 梱包資材マスタの表「資材マスタ編集履歴」（ペナラベルと同じ表） | 右上の文字・管理者パスワードを変えたあとに 1 行足す（表・列が無ければ作る）。パスワードの値は書かない。書けなくても変更は止めない | `edit_history.write` |

## 4. 長時間起動

### 4.1 DB の接続を持ち続けないか → **持たない**

- 手元 DB は要求ごとに開いて閉じる。40 回操作しても DB のファイルハンドルは 0（変更履歴 VER 0.3.1）。
- 取り込み元・マスタは、読み終えたらすぐ閉じる（`source_db._reading`）。Python 3.11 から、使い終えた接続がガベージコレクションまでファイルを掴んだままになり、Windows ではその間ほかの人がマスタを差し替えられなかった（VER 0.13.12）。

### 4.2 古いデータのままにならないか

| 場面 | ふるまい | 根拠 |
|---|---|---|
| 台帳が上流で更新された | 次の取り込み（起動時・「取り込み」）まで手元は前のまま。上の帯に「いつ時点の台帳か」を出す | `data_sync.stamps`、`SourceStamp.as_of_short` |
| 取り込んだとき、ロットを開いていた | **開いているロットは古いまま**。そう知らせる（黙って読み直すと手入力した前工程実績数が消える） | `routes/meisai.run_import` |
| 右上の文字がほかのラインで変わった | 紙面を開くたびに共有を読む。開いたままの紙面は、前に戻ったときに聞き直す | `report._QA_SCRIPT`、`/report/qa-mark` |
| 途中経過 | 前工程実績数は途中経過の値で上書き（台帳が変わっても作業中の数を変えない。VBA のまま） | `session._restore` |

### 4.3 ブラウザを放置・裏に回した・スリープした

自動終了の見張りは統合アプリに 1 つ（`common/idle_exit.py`。`meisai/idle_exit.py` はその置き換え）。

| 値 | 意味 |
|---|---|
| `HEARTBEAT_MS` = 20,000 | 画面が心拍を送る間隔 |
| `IDLE_SEC` = 90 | 心拍が途切れてから終わるまで |
| `GRACE_SEC` = 8 | 「閉じました」を受けてから終わるまで（再読込で戻ってくるぶんを待つ） |
| `WAKE_GAP_SEC` = 15 | 見張りの刻み（2 秒）がこれ以上飛んだら、スリープから戻ったとみなす |

- **裏に回っても・スリープしても終わらない。** 画面は裏に回るとき合図を送り、サーバはその間の心拍の途切れを数えない（VER 0.5.1、`README.md`）。
- 帳票を開いた別のタブがあるあいだは止まらない（統合版。変更履歴「統合版への組み込み」）。
- タブを閉じてプロセスが終わっても、作業は途中経過として DB にある（3 つの時点で書く）。同じロットを入れ直せば続きから。
- アプリが開き直されたあとに古い画面で操作すると、トークンが通らず 401（「この画面は無効になりました。アプリを開き直してください」）。

### 4.4 日付・月をまたぐ

| 場面 | ふるまい | 根拠 |
|---|---|---|
| 業務の判断 | 日付を使っていない（記録の日時だけ） | 変更履歴 VER 0.3.1 |
| 明細の履歴の整理 | 1 日 1 回（3 年前の今日より前）。今日が 2 月 29 日なら、3 年前の 2 月 28 日を境にする | `slip_history.cutoff` |
| 実績の形式（LS4LOT の名前が LS4LOT 以外） | **取り込んだ時点の年月** の行だけを手元に入れる。月が替わっても、取り込み直すまで前の月の行のまま | `common/ls4_source.pick_rows`、→ D-4 |

## 5. 複数 PC・同時書き込み

### 5.1 どこへ、誰が書くか

| 書く先 | 書く PC | 同時に書くと | 守り |
|---|---|---|---|
| 手元 DB | その PC だけ | 起きない（プロセスの中で 1 つずつ） | `_WRITE_LOCK`・トランザクション |
| `user_config.json` | その PC だけ | 起きない | 読み書きを 1 つずつ・別名で書いて置き換え（`user_settings.py`） |
| 打ち出し json | 全ライン | 起きうる | 鍵ファイル・別名で書いて置き換え |
| マスタの表「梱包明細打ち出し」 | 全ライン（と梱包資材総合ツール） | 起きうる | 鍵ファイル（このアプリどうし）。総合ツールとの重なりは実機未確認（→ D-2） |
| 履歴 DB | 全ライン | 起きうる | 手元に先に書く・鍵ファイル・送信ID・DELETE |
| 取り込み元 | 書かない | ― | 写してから読む |

### 5.2 手元 DB は共有しない（副番履歴・連番は PC ごと）

- **このアプリは複数 PC で 1 つの DB を共有しない**（変更履歴 VER 0.3.1）。VBA がブック 1 つで閉じていたのと同じ（`docs/説明書.md` §8）。
- そのため、**ほかの PC で出した副番は、この PC の重複確認には出てこない**（→ D-3）。
- 手元 DB を共有フォルダに置いてはいけない。SQLite はネットワーク越しのファイル共有だとロックが正しく効かず、複数台から同時に使うと壊れることがある（`config.py`、`README.md`）。

### 5.3 読み取り中に別の PC が書く

| 読むもの | ふるまい |
|---|---|
| 取り込み元・マスタ | 写しを読む。写している間に書き換わったら写し直す（§1.4） |
| 打ち出し json | 置き換えで書くので、古い中身か新しい中身のどちらかを読む |
| 履歴 DB | `mode=ro` で開く。ロックは 10 秒まで待つ。読み取りは画面を長く待たせない（状態は 3 秒、「いま送る」は 15 秒、マスタ管理は 15 秒まで） |
| 手元 DB | WAL なので、裏で取り込んでいても読み取りは待たされない（実測 0.000 秒。VER 0.3.1） |

### 5.4 副番履歴・連番をライン間で共有したくなったら

`README.md` は、ファイルを共有するのではなく **サーバを 1 台に寄せて** 各 PC がブラウザで繋ぐ形を勧めている
（書き込みが 1 プロセスに集まるので、ロックの競合そのものが起きない）。

ただし、**いまの作りのまま 1 台に寄せると、同時に使える画面は 1 枚だけ** になる。

- 作業の状態（開いているロット・条番号・積み上げ）は **プロセスに 1 つ**（`meisai/session.py`）。
- 2 枚目の画面は業務の画面を出さず、操作は 409 で断る（`meisai/screen.py`、§6）。
- 連番・現在ロット番号・印刷済も 1 行だけ（`明細出力状態`。`ID = 1`）。

→ D-1。寄せるなら、ライン（または PC）ごとに作業の状態を分ける作り直しが要る。

## 6. 画面は 1 枚だけ

`meisai/screen.py`・`app/static/js/screen.js`（VER 0.3.0）。

**なぜ**: 作業の状態はプロセスに 1 つ。2 枚開くと同じ盤面を奪い合い、先に開いた画面のロットが、触った瞬間にもう 1 枚のロットへ化ける（実際に確かめた）。現物と紙が食い違う事故になる。

| 決まり | 内容 |
|---|---|
| プロセスの多重起動とは別 | `launch_guard` が見るのは「Python が 2 つ走っていないか」。タブを 2 枚開くのは止められない |
| 見分け | 再読込（F5）と 2 枚目はサーバからは見分けられない（ブラウザは古いページを畳む前に次の要求を送る）。見分けは `sessionStorage`（タブごとの名前）と `BroadcastChannel`（ほかのタブが居ないか）で行い、サーバは名乗り（`/api/screen/claim`）を断る |
| 本当の歯止め | API 側。持ち主でない画面の操作は 409（`screen_taken`）。例外は `/api/screen/*` と `/report/*`（帳票は別のタブで開くため） |
| 持ち主が居なくなった | 心拍が **50 秒** 途切れたら居ないものとして扱う（`GRACE_SEC`。心拍 20 秒の 2 回ぶん。1 回の取りこぼしでは奪わない） |
| 裏に回った持ち主 | 心拍が止まっても居るものとして扱う。持ち主の心拍はどれだけ遅れても受ける |
| スリープから戻った | 止まっていた時間を数えない（`note_wake`） |
| 明示的に移す | 「この画面で使う」で前の画面から移す（2 枚にはしない）。前の画面は次の操作で「この画面は引き継がれました」 |
| タブを閉じた | すぐ空く（`/api/screen/release`） |

### 解決済み

| 内容 | 結果 | 根拠 |
|---|---|---|
| 書けていないのに「出力しました」と出ていた | `db.write()` を足し、書けなければ例外・503 | VER 0.3.1 |
| 出力が 1 まとまりになっていなかった | `db.transaction()`（出力・ロット切替の片付け・途中経過の保存） | 同上 |
| ロックで無言のまま 90 秒以上固まっていた | まとまりごとにやり直し、最大 13.5 秒 | 同上 |
| 手元 DB が共有に置かれても気づけなかった | 起動ログとバージョン情報に理由 | 同上 |
| 取り込み元のファイルを掴みっぱなしにしていた | 読み終えたらすぐ閉じる | VER 0.13.12 |
| 2 台がほぼ同時に共有へ書くと、まれに「共有フォルダに書けません」 | 鍵を消している最中の拒否は 2 秒まで繰り返す | VER 0.13.13 |
| 手元 DB が壊れていると画面が 500 | 退けて作り直し、起動を続ける | VER 0.13.14 |
| 出力は書けたのに途中経過の保存で失敗すると、同じコイルで次の No が出せた | 盤面を先に進め、保存の失敗は知らせにとどめる。開き直したら紙のコイルは使用済みに戻す | VER 0.13.26 |
| 開く前の画面で打った重量が、開いたロットに入った | `X-Screen-Lot` で断る（409 `lot_changed`） | VER 0.13.26 |
| 共有の上で開けない取り込み元があった | 読む前に必ず写す | VER 0.13.27 |
