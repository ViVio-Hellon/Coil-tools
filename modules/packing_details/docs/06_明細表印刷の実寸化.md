# 明細表の印刷 ― Excel の紙面をどう印刷フォーマットへ持ち込むか

対象の版: 梱包明細 VER 0.13.28(コイル梱包ツール 1.2.30)

根拠のファイル（`modules/packing_details/` からの相対）: `meisai/report.py`（紙面）・`meisai/printing.py`（印刷用 HTML の仕組み）・
`meisai/meisai_service.py`（書き足し）・`meisai/slip_history.py`（履歴）・`app/routes/meisai.py`（帳票の経路）、`README.md`、`docs/変更履歴.md`。
VBA の紙面は `docs/01_VBA解析書.md` §8。

## 0. 結論（先に）

**行の高さ・列の幅は Excel の実ブックの比率をそのまま写す。ただし mm ではなく百分率で持ち、
紙の端から 5mm 内側の箱に収める。余白は `@page` ではなく紙面の中で取る。**

| | 値 |
|---|---|
| 用紙 | **A4 横**（297 × 210mm）。明細 1 枚につき用紙 1 枚 |
| 明細の場所 | **左半分**（148.5 × 210mm）。右半分は空ける（現場で切り取る） |
| 文字・罫線の位置 | 紙の端から **5mm 以上内側**（上下左右。切り目の側も） |
| 明細の箱 | 約 **138.0 × 199.5mm**（5mm ＋ 線 1px を両側から引いた残り） |
| 行・列 | 実ブックの比率（行 595.5pt・列 70.75）を **百分率** で |
| `@page` | `size: A4 landscape; margin: 0`。5mm は `@page` の余白に頼らない |
| VBA との差 | 明細が幅で約 7%・高さで約 5% 小さい（比率は実ブックのまま） |
| 印刷のしかた | ブラウザの印刷（Ctrl+P / 紙面の「印刷する」）。A4 横・余白なし・倍率 100% |

> **実機での確認はまだ**（E-1）。5mm の内側に収まることは、ブラウザの中で印刷の見え方を撮って測った
> ところまで（§6）。`report.py` も「実機で確かめるまでは『欠けないはず』」と書いている。

## 1. VBA の紙面（採寸結果）

根拠: `report.py` 冒頭、`README.md`、変更履歴 VER 0.5.0。

### 1.1 ページ設定

```
.Orientation = xlLandscape / .PaperSize = xlPaperA4 / 余白 0
.FitToPagesWide = 1 / .FitToPagesTall = 1 / .Zoom = False
(中央寄せの指定なし → 左に寄る)
```

`FitToPages` は **縮めるだけで引き伸ばさない**。1 面（A1:F20）は等倍のまま A4 横の左半分に出て、右半分が空く。

### 1.2 行の高さ・列の幅（実ブックの値）

| 行 | 高さ（pt） | 列 | 幅（Excel の単位） |
|---|---|---|---|
| 1（表題） | 23.25 | A | 10.375 |
| 2〜4（小ラベル貼付。3 行を 1 つに） | 42 × 3 = 126 | B | 12.375 |
| 5（見出し） | 18.75 | C〜F | 12 × 4 = 48 |
| 6〜20（データ 15 行） | 28.5 × 15 = 427.5 | | |
| **合計** | **595.5pt** | **合計** | **70.75** |

- 行の合計 595.5pt は A4 の高さちょうど（`README.md` は 210.06mm と書いている。1pt = 25.4/72mm で換算すると約 210.08mm）。
- 列の合計 70.75 は A4 横の幅の半分にあたる（`README.md`、`report.py`）。

### 1.3 過去の誤り

| 版 | 書いていたこと | 正しくは |
|---|---|---|
| VER 0.2.0 | VBA は 1 面を A4 いっぱいに引き伸ばしていた。実ブックが A〜F / H〜M の 2 面で保存されていたので 2 面付けにした | `FitToPages` は引き伸ばさない。実ブックの 2 面は運用の形ではなかった（VER 0.5.0 で取り消し） |
| VER 0.2.0・0.5.0 | `margin:0` でも数ミリ削られるが、割合で持っているので削られた分だけ全体が縮む | **縮まない**。ブラウザはプリンタの刷れない幅を知らないので、紙の端まで描いて、刷れない所はそのまま欠ける（VER 0.6.0） |

## 2. 紙面の作り

### 2.1 用紙と面付け

| 決まり | 実装 | 根拠 |
|---|---|---|
| 1 枚の紙 = A4 横 | `.page{ display:grid; grid-template-columns:1fr 1fr; width:100%; height:210mm; max-height:100vh }` | `report._sheet_css` |
| 左半分に明細 1 枚 | `.half` の 1 つ目に明細、2 つ目（`.half.blank`）は空 | `report._page` |
| 右半分は何も置かない | 別の明細を並べない（その運用はしていない）。同じ明細を写さない（明細表は 1 梱包に 1 枚貼るもので、2 枚出ると貼り間違いの種） | `report._page` の注記 |
| まとめて刷る | 1 枚ずつ別の用紙（`.sheet{ page-break-after: always }`） | `printing.BASE_CSS`、`report.build_report` |
| まとめたときの並び | **No の順**（押した順ではない。切ったあとの並べ替えが要らない） | `routes/meisai.sheets` |
| 真ん中の線 | 引かない（VBA の紙面に線は無い） | 変更履歴 VER 0.5.0 |

### 2.2 紙の端から 5mm 以上内側

**プリンタは紙の縁から約 4mm の所には印刷できない。** プレビューは紙の端まで描くので画面では収まって見えるが、
VER 0.5.0 の紙面（左の端から 1.8mm・上の端から 0mm に枠線）は、**刷ると左と上が欠けた**（現場の実機。余白なし・100%）。

| 決まり | 値・実装 | 根拠 |
|---|---|---|
| 内側に置く量 | `SAFE_MARGIN_MM` = **5.0mm**（約 4mm より内。機種ごとの差を見込む） | `report.py` |
| 右も 5mm | 右半分は切り取るので、真ん中の切り目も紙の端。手で切ってずれても枠線にかからない | 同上 |
| 線の太さぶん | `.half{ padding: calc(5mm + 1px) }`。外枠の線は表の箱から少しはみ出して描かれる（実測で右に 0.1mm）ので、**インク** が 5mm 内に収まるよう 1px 足す | 同上 |
| 明細の箱 | 幅 148.5 − 2 ×（5 ＋ 0.265）＝ **137.97mm**、高さ 210 − 2 ×（5 ＋ 0.265）＝ **199.47mm** | `report._qa_fit_mm` と同じ計算 |
| はみ出させない | `.half{ overflow:hidden }` | `report._sheet_css` |

VBA は余白 0・等倍（1 面 ＝ 148.5 × 210mm）で刷っていた。5mm ずつ内に寄せたぶん、明細が **幅で約 7%・高さで約 5% 小さく** なる
（行と列の比率は実ブックのまま）。刷れない所に線や文字を置かないための変更（VER 0.6.0）。

### 2.3 行の高さ・列の幅の計算（百分率）

`report._col_percents` / `_row_percents`。実ブックの値（§1.2）を合計で割る。

**列**（`<col>` の `width`）:

| 列 | 計算 | 百分率 | 箱 137.97mm のとき |
|---|---|---|---|
| A | 10.375 ÷ 70.75 | 14.664% | 約 20.2mm |
| B | 12.375 ÷ 70.75 | 17.491% | 約 24.1mm |
| C〜F（各） | 12 ÷ 70.75 | 16.961% | 約 23.4mm |

**行**（各行の `height`）:

| 行 | 計算 | 百分率 | 箱 199.47mm のとき |
|---|---|---|---|
| 1（表題） | 23.25 ÷ 595.5 | 3.904% | 約 7.8mm |
| 2〜4（小ラベル貼付） | 126 ÷ 595.5 | 21.159% | 約 42.2mm |
| 5（見出し） | 18.75 ÷ 595.5 | 3.149% | 約 6.3mm |
| 6〜20（データ。1 行あたり） | 28.5 ÷ 595.5 | 4.786% | 約 9.5mm |

- 試験 `tests/test_meisai_service.py` の `test_寸法は実ブックの比率` が「行の合計が 595.5pt・列は 100%」を確かめる。
- データ行は **必ず 15 行**（`config.SHEET_ROWS`）。空いた行も枠だけ出す（VBA と同じ。`report.build_slip`）。

**なぜ百分率か**: 行・列を mm の固定値で組むと、箱の大きさを変えたとき（5mm の内側に収めたとき）に全部を計算し直すことになる。
百分率なら箱の大きさだけで決まり、実ブックの比率が保たれる（`report.py` 冒頭「寸法は割合で持つ」）。
ただし「割合だから刷れない所で縮む」は誤り（§1.3）。

### 2.4 なぜ `@page` の余白を使わないか

印刷用 CSS は `@page { size: A4 landscape; margin: 0mm; }`（`printing.PageSetup.to_css`。`report.build_report` が `margin_mm=0`）。
5mm は `@page` の余白ではなく、**紙面の中**（`.half` の `padding`）で取る。

- 現場は印刷ダイアログで **「余白なし」** にして刷る。
- そうすると `@page` の余白は 0 に上書きされる。
- `@page` の余白に頼ると元に戻ってしまう（刷ると欠ける）。

根拠: `report._sheet_css` の注記、`README.md`、変更履歴 VER 0.6.0。

印刷ダイアログで余白を入れると、そのぶん全体が少し小さく刷られる（`docs/説明書.md` §2）。

### 2.5 紙面の中身と文字

| 位置 | 中身 | 文字 | 根拠 |
|---|---|---|---|
| 1 行目 A〜D | `<ロット番号>-No<N>  梱包明細表`（空白 2 つを `white-space:pre` で畳ませない） | 9pt・太字・中央 | `report._sheet_css`、`TITLE_SUFFIX` |
| 1 行目 E〜F | 右上の文字（既定 `NLM.NAGOYA.QA`） | 赤（`#ff0000`）・太字・**8pt**。長ければ 5pt まで縮める（§2.6） | `QA_FONT_PT` / `QA_MIN_FONT_PT` |
| 2〜4 行目 A | 「種類質別 / 寸法 / 検番」 | 9pt・中央・行の高さ 1.7 | `.r-label .cap` |
| 2〜4 行目 B〜C | 書き足し（空・サイズ・LOTNO）（§3） | 9pt・太字・中央 | `.r-label .hand` |
| 3 行目 D | 「小ラベル添付」 | 橙（`#ff6600`）・**8pt**・中央 | `.r-label .paste` |
| 2〜4 行目 E〜F | 空（現物のラベルを貼る） | ― | `build_slip` |
| 5 行目 | 「コイル副番」「重量(Kg)」 | 9pt・太字・中央 | `.r-head` |
| 6〜20 行目 | 積んだ順の副番 / 重量（`<小数1桁>Kg`） | **11pt**・中央 | `.r-data` |

- **副番も重量も中央。** VBA は A〜C・D〜F を `MergePut` で結合して `xlCenter` にしてから値を入れている。VER 0.6.0 より前は副番を左・重量を右に寄せていて、VBA と違っていた。
- 2〜4 行目の B〜F は罫線を引かない（現物を手で貼る場所）。
- 文字の大きさのうち、VBA の値が注記に出ているのは D3 の 9pt だけで、移植版の 8pt と食い違う（E-3）。

### 2.6 右上の文字を欄に収める

右上の文字は設定で変えられる（20 文字まで。全ラインで共有）。長い文字も欄からはみ出させない。

| 決まり | 値・実装 | 根拠 |
|---|---|---|
| 欄の幅は **紙の上の値** で持つ | 明細の幅 137.97mm × E〜F 列の割合（24 ÷ 70.75）− セルの左右の余白 1.5mm × 2 − 線や丸めのぶん 1mm ＝ **約 42.8mm** | `report._qa_fit_mm` |
| 画面の幅では測らない | 紙面の画面はウィンドウの幅に合わせて伸び縮みするので、画面で収まっていても紙では収まらないことがある | 同上 |
| 縮め方 | 文字の幅を測り、42.8mm を超えるなら字を小さくする（8pt から、5pt まで）。字の大きさは pt なので、狭い窓で開いても同じ大きさで刷られる | `report._QA_SCRIPT` |
| いつ測るか | 開いたとき・フォントが揃ったとき・印刷の直前（`beforeprint`） | 同上 |
| 最後の囲い | `.qa{ overflow:hidden }`（5mm の内側を越えて刷らない） | `report._sheet_css` |
| 開いたままの紙面 | 同じ PC で変えたら画面から知らせて差し替える（`BroadcastChannel`）。ほかのラインで変えたときは、前に戻ったときに聞き直す（`/report/qa-mark`） | `report._QA_SCRIPT` |

全角 20 文字を 8pt で刷ると収まらないので、全角 20 文字ではおよそ 6pt になる（変更履歴 VER 0.7.0）。

## 3. 書き足し（サイズ・LOTNO）

**VBA は紙が Excel のシートだったので、刷る前にセルへ打ち込めた。** 移植版は紙面が HTML なので、
同じことを紙面の上でできるようにした（流用元の `printing.editable`。VER 0.4.0）。

```
A列          B〜C列             D列            E〜F列
種類質別     (空けたまま)
寸法         サイズ   ← 書き足し  小ラベル添付(D3)
検番         LOTNO    ← 書き足し
```

| 決まり | 内容 | 根拠 |
|---|---|---|
| 置き場所 | **B〜C 列**（幅 約 47.5mm）。D〜F 列は現物のラベルを貼る場所で、上に貼れば隠れる。「小ラベル添付」は VBA の `Cells(3, 4)` ＝ D3 のまま | `report.py` 冒頭 |
| 行の揃え | A2:A4 は 3 行を 1 つに結合して中央寄せなので、「寸法」「検番」の文字は 2 行目・4 行目の真ん中には無い。書き足しも同じ文字の大きさ・行の高さ（1.7）で 3 行組んで中央に置くと、横に揃う（実測で差 0〜1px） | `report.py`、変更履歴 VER 0.4.0 |
| 長さ | 1 欄 **20 文字まで**（`HAND_MAX_LEN`）。9pt の太字で半角 20 字ほどが B〜C 列に入る。超えると理由を出して受けない | `meisai_service.HAND_MAX_LEN` |
| 空なら | 何も印字しない（VBA の紙面と同じ） | `report.py` |
| 点線・案内 | 画面のときだけ（`@media screen`）。紙には出ない | `printing._EDIT_CSS` |
| 送るとき | 打って 0.6 秒たったら・欄を離れたとき・Enter のとき、`POST /report/<ロット>/edits` へ | `printing._EDIT_SCRIPT` |
| 貼り付け | 文字だけにする（太字や色が付いてくると、刷った紙と保存した中身が食い違う） | 同上 |
| 改行 | 入れさせない（1 行の欄。入ると印刷でずれる）。改行・タブは空白にする | 同上、`tests/test_hand_edit.py` |
| 残り方 | その明細（`明細出力` の `手入力サイズ` / `手入力ロット番号`）に残り、刷り直しても出る。ロットを切り替えると明細ごと消える（明細の履歴には残る） | `meisai_service.save_hand_edits`、`schema.sql` |
| まとめて開いたとき | 欄の名前を `<管理番号>.size` / `<管理番号>.lotno` にして、明細ごとに分ける。**1 枚でも書けなければ 1 枚も書かない** | `meisai_service.save_hand_edits` |
| 画面の持ち主 | 紙面は別のタブなので画面を持っていない。書き足しは画面の持ち主でなくても受ける（トークンは要る） | `routes/meisai.save_edits` |

## 4. 作り直し

「作り直し」には 2 つある。

### 4.1 出力済み修正で明細を作り直したとき

出力済みの 1 枚を同じ No のまま積み直して出し直すと（VER 0.13.23）、`明細出力` の行が **作り直されて `管理番号` が変わる**
（`meisai_service.output_edit`）。

| 決まり | 内容 |
|---|---|
| 書き足し | 前の明細のサイズ・LOTNO を新しい明細へ引き継ぐ |
| 古い紙面 | 開いたままの古い紙面から書き足すと **409**「この明細は作り直されたか、もうありません。紙面を開き直してください。」。前の明細への書き足しが新しい明細へ紛れ込まない |
| 前の紙の履歴 | 消さずに「作り直し」の印 |
| 刷り直し | 要る（画面に「刷り直してください（印刷）」） |

### 4.2 履歴から紙面を作り直す

画面の「履歴」で選んだ紙を、**明細の履歴に残した中身のとおりに** 組み直す（`report.render_history`、`/report/history?ids=…`。VER 0.11.0）。

| 決まり | 内容 |
|---|---|
| 中身 | 積んだ順・重量・書き足したサイズ / LOTNO・**そのとき刷った右上の文字**（紙面を開いたときに記録した文字） |
| 右上の文字の記録が無い紙 | いまの文字で刷り、画面にそう出す |
| 作り直し・取り消しの紙 | 開ける。「このあと作り直されています（同じNoの新しい紙が履歴にあります）」「このあと全クリアで取り消されています（この紙は使いません）」と画面の上に出す |
| 読むだけ | 書き足しはできない。履歴も明細も書き換えない。開いたままの紙面でも、いまの右上の文字へ差し替えない |
| 枚数 | 一度に 20 枚まで（`slip_history.LOAD_LIMIT`） |
| 紙面 | 出力したときと同じ組み方（`report.build_report`）。表題・右上の文字・書き足し・15 行の副番と重量が 1 字も違わないことを試験で確かめている（`tests/test_history_slip_matches.py`。VER 0.13.10） |

## 5. 使い方

1. 画面の「出力済み」でチェックを入れ、「印刷」を押す（押した時点で印刷済を記録してから、別のタブで紙面を開く）。
2. 必要ならサイズ・LOTNO を書き足す。
3. 紙面の上の **「印刷する」** か **Ctrl+P**。
4. 印刷ダイアログで、用紙が **A4 横**・余白が **なし**・倍率 **100%** になっているかを見る（ブラウザの設定に左右される）。
5. 刷れたら右半分を切り取る。

- 作業の画面（統合画面）で Ctrl+P を押すと、作業の画面が刷られる（外枠は刷られない。変更履歴「統合版への組み込み」）。明細表は紙面のタブで刷る。
- **左や上が欠けていたら**、まず倍率が 100% かを見る。それでも欠けるなら知らせる（`docs/説明書.md` §2）。

## 6. 確かめたこと

| 確かめたこと | 結果 | 根拠 |
|---|---|---|
| 印刷の見え方（Chromium）で、色が付いた画素の位置を数えた（1 枚・2 枚まとめて、どの用紙も同じ） | 紙の端から 左 5.29mm・上 5.29mm・下 5.29mm・右（切り目 148.5mm から）5.16mm。右半分に色の付いた画素は 0 | 変更履歴 VER 0.6.0 |
| 文字の中心と欄の中心のずれ | どの欄も 0.1mm 未満 | 同上 |
| 用紙の大きさ | 297.0 × 209.9mm（1 枚） | 変更履歴 VER 0.4.0 |
| 書き足しの位置 | 「寸法」「検番」の文字と横に揃う（差 0〜1px）。「小ラベル添付」は D3 の位置（以前は B〜F の中央で、ずれは 0.4mm） | 同上 |
| 履歴から作り直した紙面と、出力したときの紙面 | 4 通り（書き足しあり・何枚まとめて・送ったあとの書き足し・あとで右上の文字を変えた）で 1 字も違わない | 変更履歴 VER 0.13.10 |

試験（`tests/test_meisai_service.py` の `ReportTest`）: 紙は必ず 15 行・用紙は A4 横で余白 0・明細 1 枚は左半分で右半分は空ける・
まとめて刷っても 1 枚ずつ別の用紙・右半分に線を引かない・紙の端から 5mm 内に置く・副番と重量は中央・どの文字も端に寄せない・
寸法は実ブックの比率。このほか `tests/test_hand_edit.py`（書き足し）・`tests/test_qa_mark.py` の `QaFitTest`（右上の文字の欄の幅）。

## 7. 寸法を変えたいとき

| 変えたいもの | 直す所 |
|---|---|
