# 統合ツール 仕様

対象の版: コイル梱包ツール 1.2.55(梱包明細 VER 0.13.33 / ペナラベル 1.5.51 / 資材計算 0.2.34)

この文書は「統合ツール(外枠)」の仕様です。外枠とは、3 つの機能(梱包明細・ペナラベル・資材計算)を
**1 つのプロセス(動いているプログラム 1 つ)・1 つの画面**にまとめて動かす部分のことです。
各機能の中身(計算・取り込み・帳票)は、それぞれの機能の文書(11〜33)を見てください。ここでは「つなぎ方」だけを書きます。

---

## 1. 目的と範囲

| 項目 | 内容 |
|---|---|
| 目的 | 3 機能を、1 つの起動・1 つの画面のタブ切り替えで使えるようにする |
| しないこと | 3 機能の計算・入力チェック・DB 処理・帳票を 1 つにまとめること(どれも移植元のまま、別々に動く) |
| 外枠が受け持つもの | 起動・停止・多重起動の防止・待ち受け・待機画面・統合画面(上の帯・タブ・iframe)・自動終了・ログとエラーの記録・画面の色・説明書・版の表示・閉じる前の確認・印刷のつなぎ |
| 外枠が持たないもの | 各機能の設定画面と設定値・マスタ管理・画面の見張り(2 枚目の画面を断る仕組み)・断りの形(HTTP 番号・本文) |

## 2. 構成

### 2.1 プロセス

```
ブラウザ版                                     デスクトップ版
Start.vbs / start.bat                          コイル梱包ツール.exe(外枠の窓。src-tauri/)
  └─ start_app.py                                └─ bridge.py(子として起動。標準入出力でやりとり)
       ├─ launch_guard.py(多重起動・ポート)          └─ start_app.start_bridge
       ├─ server.py + boot_server.py(待ち受け)
       └─ app.py(統合 Flask アプリ)  ← どちらも同じものを組み立てる
            ├─ /details   梱包明細   (modules/packing_details)
            ├─ /pena      ペナラベル (modules/packing_pena_label)
            └─ /material  資材計算   (modules/packing_material_calculation)
```

- 3 機能は**同じ 1 つの Python プロセス**の中で動きます。起動トークン(起動ごとに作る合言葉の文字列)・準備完了の印・
  自動終了の見張り・止め方は、プロセスに 1 つだけ持ちます(`app.py` の `create_app`)
- 表示名・版・アプリ ID は、機能ごとにそれぞれの `config/app.json`(ペナラベルは `app/config.py`)のままです

### 2.2 画面(統合画面)

`templates/base.html`(外枠)・`templates/index.html`(タブと iframe)・`static/js/shell.js`・`static/css/shell.css`。

| 部分 | 中身 |
|---|---|
| 上の帯 | 表示名・統合ツールの版(押すと版の一覧)・画面の色(自動/ライト/ダーク)・説明書・ログ・接続表示・終了 |
| タブ | 横一列。並びは `app.all_modules()` の順(梱包明細 → ペナラベル → 資材計算)。名前の右に機能の版。← → キーでも移れる |
| 中身 | 機能ごとに 1 つの iframe(画面の中に別の画面をはめ込む仕組み)。**3 つとも最初に開き、タブ切替は隠すだけで外さない** |
| 帯の下の知らせ | 「バックエンドと通信できません」(赤)・「アプリが開き直されています」(赤。読み込み直すボタン)・「終了しました」 |
| ダイアログ | ログ(`/log` を開く)・説明書(`/manual/<機能>` を開く) |

- 最初に見せるタブ: URL の `#キー` → 前回のタブ(同じタブの sessionStorage)→ 先頭
- iframe の中身の URL は各機能の `HOME`(`/details/meisai` `/pena/` `/material/calc`)に `?t=<トークン>` を付けたもの

### 2.3 3 機能の載せ方と URL の入口

| 機能 | 入口 | 最初の画面 | 載せ方 |
|---|---|---|---|
| 梱包明細 | `/details` | `/details/meisai` | 機能の `register(app)` が入れ子の Blueprint を登録 |
| ペナラベル | `/pena` | `/pena/` | 同上(移植元の `http.server` を Flask の取り次ぎに置き換え) |
| 資材計算 | `/material` | `/material/calc` | 同上 |

- 移植元はどれも `/` `/api/health` `/static/…` などを自分の根に持っていたので、入口を切り、その下に**移植元の経路をそのまま**置いています
- 統合アプリは、3 機能の HTML に次のスクリプトを差し込みます(各機能のコードは触りません。`app.py`)

| 差し込むもの | どの画面に | 役目 |
|---|---|---|
| `static/js/tab_alive.js` | 3 機能の画面(末尾) | **別のタブ(いちばん外の窓)で開いたときだけ**心拍を送る。iframe の中では何もしない |
| `static/js/error_report.js` | 3 機能の画面(末尾) | 画面の JavaScript のエラーを `/api/client-log` へ送り、番号を画面の隅に出す |
| `static/js/theme.js` | `<html>` のあるすべての画面 | 画面の色の切り替えを受ける。開いた瞬間の色はサーバが `<html data-theme>` で付ける |
| `static/js/desktop.js` | **デスクトップ版のときだけ**、すべての画面(`<head>` の直後) | 別窓・アプリの外のリンク・窓を閉じるを外枠に頼む |

ペナラベルの「中身だけ返す」要求(`?pane=1`)には差し込みません。

## 3. 起動と停止

### 3.1 起動の入口

| 入口 | 中身 | 戻り |
|---|---|---|
| `コイル梱包ツール.exe` | デスクトップ版。窓を出し、Python(`bridge.py`)を子として起こす | 窓を閉じるまで動く |
| `Start.vbs` | ブラウザ版の通常起動。`start_app.py` があるか・`python`・`pythonw` があるかを確かめ、作業フォルダを `%TEMP%` にして `pythonw start_app.py` を**引数なしで**起こし、すぐ戻る | 失敗はメッセージの窓で知らせて 1 |
| `start.bat` | ブラウザ版の診断起動。`python start_app.py --check` のあと `python start_app.py %*`(引数をそのまま渡す)。止まるまで戻らない | 0 / 1 |
| `run.py` | `start_app.main` を呼ぶだけ(`start_app.py` と同じ) | 同左 |

`start_app.py` の引数: `--no-browser`(ブラウザを開かない)・`--check`(環境の確認だけ)・`--diagnostic`(3 機能とも DEBUG まで残す)。
`--mode` は隠し引数で、何を渡しても `main` になります(`common/modes.py`)。

### 3.2 ブラウザ版の起動の流れ(`start_app.py`)

1. **環境の確認**(`run_environment_checks`): Python 3.9 以上 → Flask・waitress がある → 統合アプリの手元の領域に書ける →
   `__pycache__` の書き先を手元の領域の `pycache\` へ向ける → 3 機能の手元の領域に書ける → `config/app.json` が読めるか(読めなければ既定値で続け、ログに残す)
2. **起動の記録**: 配布設定(共通)を先に読み込み、ログに起動の 1 枚(Python・アプリの場所・4 つの版・3 機能の置き場所)を書く。古いログを片付ける
3. **起動の順番待ち**(`launch_guard.startup_gate`)の中で:
   1. 多重起動の判定(`check_existing`)。同じ版が動いていれば**合流**(ブラウザを開いて 0 で終わる)
   2. 統合前の単体版が動いていれば起動しない
   3. デスクトップ版が動いていれば起動しない
   4. ポートを選ぶ(8740〜8743)。全部ふさがっていれば起動しない
   5. 待ち受けを始める(この時点では待機画面だけ)。最大 15 秒、`/api/health` に答えるか確かめる。TCP でもつながらなければ起動しない
   6. ロック(`runtime\main.lock`)を書く
4. ブラウザで `http://127.0.0.1:<ポート>/?t=<トークン>` を開く
5. 本体(統合アプリ + 3 機能)を組み立て、待ち受けを開き直さずに差し替える(`boot_server.Handover`)
6. 自動終了の見張りを立て、3 機能の重い初期化(取り込み)を順に呼ぶ。全部終わるか **150 秒**たったら準備完了
7. 止まるまで待つ。終わるときは 3 機能の片付け(ペナラベルの状態 DB を閉じる。最大 3 秒)をしてロックを消す。
   消すのは**自分の PID が書いたロックだけ**です(`remove_lock(mode, pid=自分)`。統合 1.2.26。置き換えで先に新しい版がロックを書いていても消さない)

本体を組み立てられなかったときは、待機画面に理由を出したまま残ります。待機画面が **120 秒**だれにも見られなければ
自分で終わります(`_watch_failed_boot`)。`start_app.py` の戻り値は、ふつう・合流が 0、起動できないときが 1 です。

起動できないときは、コンソールに理由を出し、ブラウザに「起動できませんでした」の HTML
(手元の領域の `work\起動エラー.html`)を開きます(`--no-browser` のときは開かない)。

### 3.3 停止の流れ

| 止め方 | 流れ |
|---|---|
| 統合画面の「終了」・資材計算の帯の「終了」 | 画面が 3 機能に保存していない入力を訊く(§8)→ `POST /api/shutdown`(`screens_ready: true`)→ 途中の処理があれば「中断して終了しますか」→ OK なら `force: true` で送り直す |
| `stop.bat`(→ `process_manager.py`) | ロックを読む → `/api/health` で本人か確かめる → `POST /api/shutdown`(画面に確かめを頼む)→ 応答しないときは **`--force` のときだけ** PID で止める(統合 1.2.26。`--force` が無ければ「終了要求に応じません」と返して落とさない) |
| デスクトップ版の窓の × | 画面の「終了」を押したのと同じ流れ(§6) |
| 自動終了 | §5 |

止めると決めたら、応答を返してから **0.4 秒**後に止めます(`SHUTDOWN_DELAY_SEC`)。止める要求から **6 秒**で待ち受けが終わらなければ、
片付けをしてからプロセスを落とします(`_hard_exit`)。

### 3.4 `process_manager.py`(`stop.bat`)の戻り値

| 戻り値 | 意味 |
|---|---|
| 0 | 止めた(または動いていなかった・残っていたロックを片付けた) |
| 2 | 止めなかった ── 途中の処理がある(busy)・画面で「閉じない」が選ばれた(refused)・画面で確かめ中のまま 15 秒たった(asking) |
| 1 | 止められなかった ── デスクトップ版が動いている・応答しない(`--force` が無ければ PID で落とさない。統合 1.2.26)・応答せず PID でも止められない・本人と確かめられない など |

- 止めなかった理由は**行の頭に**出します(例「止めませんでした: …」)。業務ツール統合ランチャーはこの 1 行目を理由として見せます
- デスクトップ版が動いているときは止めずに 1 を返し、窓を前に出します(exe をもう一度起こす。Windows だけ)。`--force` のときは前に出しません
- PID で止める前に「本当にこのアプリか」を確かめます: アプリ自身の答え(app_id・mode・pid がロックと合う)か、
  コマンドラインにアプリの場所(または `start_app.py`)が入っていること。どちらも確かめられなければ止めません
- 「終了しました」は**プロセスが居なくなったのを確かめてから**言います。残っていれば「まだ動いています」と出してロックも残します。
  居なくなったかを確かめられない PC では「(待ち受けは閉じました。プロセスが居なくなったかは確かめられませんでした)」を添えます
- 引数: `--force`(途中の処理を中断してでも止める・PID で止まらなければ強制終了)・`--status`(状態を見るだけ)。
  `--all` `--any` は隠し引数(`--any` は 1.2.4 の名残りを読み捨てるため)
- **`stop.bat` 自身の戻り値は 0 か 1** です。`process_manager.py` が 0 以外(1 でも 2 でも)なら理由を出して一時停止し、1 を返します

## 4. 多重起動・ポート・ロック

### 4.1 ロックと印のファイル(手元の領域の `runtime\`)

| ファイル | 中身・使い方 |
|---|---|
| `main.lock` | JSON: `app_id` `mode` `pid` `port` `url` `started_at` `python` `app_root` `token`。待ち受けが始まってから書き、終わるときに消す。`stop.bat` とランチャーが止めるときのトークンをここから読む |
| `main.start` | 起動の順番待ちの印(OS のファイルロック)。ロック本体とは別のファイル |
| `desktop.lock` | デスクトップ版の exe が動いているあいだ握る OS のファイルロック |
| `desktop-python.lock` | デスクトップ版の Python が動いているあいだ握る OS のファイルロック |

### 4.2 多重起動の判定(`launch_guard.check_existing`)

| 状態 | 動き |
|---|---|
| ロックが無い | 起動する |
| ロックの PID が居ない | ロックを消して起動する |
| PID は居て、そのポートを待ち受けているが `/api/health` に答えない | **別物と決めつけず合流する**(統合 1.2.26。重い処理の途中かもしれない。以前はロックを消して 2 つ目を立て、同じ手元の DB を 2 つで開くことがあった) |
| PID は居るが答えず、ポートも閉じている(終わりぎわ) | PID が居なくなるのを 10 秒まで待ってから、ロックを消して起動する |
| PID は居るが、そのポートの `/api/health` が同じ `app_id` と `mode` を返さない | 別物とみなし、ロックを消して起動する |
| 同じアプリが動いていて、版の組(`version_set`)が同じ | 起動せず、そのプロセスの画面をブラウザで開く(合流) |
| 同じアプリが動いていて、版の組が違う | 古いほうに止める要求(`force` なし)を送り、**プロセスが居なくなるまで** 10 秒まで待って起動し直す(待ち受けが閉じただけでは終わったとしない。統合 1.2.26)。途中の処理があって止まらない・10 秒で終わらなければ合流する |

- **起動の順番待ち**: 判定からロックを書くまで(1 秒弱)を 1 つずつしか通しません。2 つ目は最大 15 秒待ってから判定をやり直します。
  締められない環境では理由をログに残して通します(まれに 2 つ立つほうが、開けないより害が小さいため)
- **排他の待ち受け**(Windows): `SO_EXCLUSIVEADDRUSE` を付けたソケットを自分で作ってから waitress に渡します(`server.bind_exclusive`)。
  判定に取りこぼしがあっても、同じポートを 2 つ目が掴むことはありません

### 4.3 ポート

- `config/app.json` の `server.roles.main.port`(既定 8740)から `port_retry`(既定 3)個先まで、8740〜8743 を順に試します
- 待ち受けは `127.0.0.1` だけ(ほかの PC からは届かない)
- デスクトップ版はポートを使いません。ポート欄は 0 になり、各機能の画面では「なし（デスクトップ版）」と出ます

### 4.4 同時に動かさない組み合わせ

| 動いているもの | 後から起動 | 動き |
|---|---|---|
| ブラウザ版 | デスクトップ版 | 窓に「ブラウザ版のコイル梱包ツールが動いています」と出して起動しない |
| デスクトップ版 | ブラウザ版 | 「デスクトップ版のコイル梱包ツールが動いています」で起動しない(`desktop.lock` か `desktop-python.lock` が握られている) |
| 統合前の単体版 | どちらでも | 「統合前の単体版が動いています: …」で起動しない。単体版は自動では止めない |

単体版の見分け方(`launch_guard.find_legacy_instances`): 単体版が残す記録(梱包明細 `meisai.lock`・資材計算 `main.lock`・ペナラベル `instance.json`)の
ポートか、既定のポート(梱包明細・資材計算 8733、ペナラベル 8731)の起動確認が、単体版のアプリ ID を返すか。
見分けられないときは起動を止めません(ログに残す)。

## 5. 自動終了の決まり(ブラウザ版)

見張りはプロセスに 1 つ(`common/idle_exit.py`)。デスクトップ版は窓を閉じたら外枠が終わらせるので、見張りを立てません。

| 決まり | 値・中身 |
|---|---|
| 心拍の間隔 | 20 秒(`HEARTBEAT_MS`)。送り手: 統合画面の外枠(`shell.js`)・梱包明細と資材計算の画面・別のタブの画面(`tab_alive.js`) |
| 心拍が途切れたら | 90 秒(`IDLE_SEC`)で「誰も見ていない」 |
| 閉じた合図(`sendBeacon`)が来たら | 8 秒(`GRACE_SEC`)待つ。そのあいだに心拍が戻れば取り消す(読み直しのため) |
| 生き死にの数え方 | **画面ごと**(名乗り `client` ごと)。1 枚でも生きていれば終わらない。名乗らない画面は全部で 1 枚。覚える上限 64 枚 |
| 裏に回った画面 | 裏に回る合図(`state: hidden`)のあとは、心拍の途切れでは終わらない。**閉じた合図は裏でも効く** |
| 印刷の画面を開いているあいだ | 開く前に「裏に回った」と同じ合図を送り、閉じたら戻す(統合 1.2.20) |
| 処理中 | 資材計算の取り込みなど、途中で止めると困る処理があれば待つ(`app.busy`) |
| 1 度もつながっていない | 終わらない(`--no-browser` で立てておく使い方を巻き添えにしない) |
| スリープから戻った | 見張りの刻み(2 秒)が壁時計か単調時計で 15 秒以上飛んだら、どの画面も数え直す |
| タブが捨てられて読み直された | 開き直した画面が前の名乗り(`replaces`)を言い、見張りはそれを忘れる |

裏に回ったままブラウザが落ちると閉じた合図が来ないので、プロセスは残ります。次の `Start.vbs` はそのプロセスに合流し、止めたいときは `stop.bat` を使います。

## 6. デスクトップ版の違い

作りの詳細は `docs/デスクトップ版.md`。

| 項目 | ブラウザ版 | デスクトップ版 |
|---|---|---|
| 入口 | `Start.vbs` → `start_app.py` | `コイル梱包ツール.exe` → `bridge.py` → `start_app.start_bridge` |
| 画面の宛先 | `http://127.0.0.1:<ポート>/` | `http://app.localhost/`(Windows)/ `app://localhost/`(ほか)。ネットワークを通らない |
| 要求の渡し方 | waitress が待ち受ける | 外枠が標準入力へ渡す(1 件 = 見出し 1 行の JSON + 本文)。CSS・JS・画像は外枠が直接返す |
| Python | PATH の `python` / `pythonw` | `python.exe` → `py.exe -3` の順に探す(`COIL_PACKING_TOOLS_PYTHON` で指定可)。UTF-8 モードでは起動しない |
| 要る部品 | Flask・waitress | Flask だけ |
| 多重起動 | ロック + 版の照合 + 排他の待ち受け | 2 つ目は起動せず、開いている窓を前に出す。`desktop.lock` でも止める |
| 自動終了 | あり(§5) | なし。窓を閉じたら終わる |
| 終了の確認 | 「終了」で §8 | 窓の × でも「終了」と同じ流れ。画面が 3 秒受け取らなければそのまま終える。統合画面が出る前(起動中・起動できない画面)はそのまま終える |
| 外からの停止 | `stop.bat` / `POST /api/shutdown` | 窓に「閉じて」と頼む(× と同じ)。`stop.bat` は止めない |
| 帳票・印刷ビュー | 新しいタブ | 新しい窓(1100×900)。アプリの外のリンクは既定のブラウザ |
| 起動できないとき | 「起動できませんでした」の HTML | 窓に理由・次にすること・ログの場所 |

- 統合アプリの中では `BRIDGE` の印が立ち、`PORT` は 0、Host の確認に `app.localhost` を足します
- exe を止めると標準入力が閉じるので、Python も終わります(外枠は最大 8 秒待ち、終わらなければ止める)
- Windows 実機での次の動きは、文書(`docs/デスクトップ版.md`)のとおり人の目では見ていません(未確認):
  印刷の窓から紙が出ること・2 つ目の起動で窓が前に出ること・閲覧システムが既定のブラウザで開くこと

## 7. 置き場所と環境変数

### 7.1 置き場所

| もの | 置き場所 |
|---|---|
| 統合アプリの手元の領域 | `%LOCALAPPDATA%\CoilPackingTools\`(`runtime` `logs` `pycache` `cache` `work` `backup` `data`) |
| ログ | `<出力パス>\coilpacking\coilpacking_<PC名>_YYYYMMDD.log`(3 機能で 1 つ。日付で切る。出力パスの既定は `%LOCALAPPDATA%\CoilPackingTools\logs`)。1.2.53 から日報複合ツールの決まり(ツールIDのフォルダ・`<ツールID>_` で始まり PC名入りの名前)。前の名前・前の置き場所の自分のログも読めて、残す日数で消える(消すのはこのツールの・この端末の物だけ) |
| エラーの記録 | `<出力パス>\coilpacking\incidents\coilpacking_なぜなぜ_<PC名>_E<日付>-<時刻>-<記号>.md`(1 件 1 ファイル) |

## 8. 閉じる前の「保存していない入力」の確認

- 統合画面は終了の前に、3 機能の画面(と開いているログの画面)の `window.cptUnsaved()` を呼び、保存していない入力の名前を集めます
- あれば「まだ保存していない入力があります: … 閉じると、この入力は消えます。閉じますか?」を 1 つ出します。キャンセルなら止めず、その機能のタブを見せます
- 同じ中身に「閉じてよい」と答えてから 2 分のあいだは、続けて訊きません
- **外からの停止**(`stop.bat`・ランチャー。ブラウザ版): 入口は、毎秒たずねに来る統合画面に「閉じる前の頼み」を出し、3 秒だけ返事を待ちます(`common/close_ask.py`)

| 画面の返事 | 入口の答え |
|---|---|
| 全部「閉じてよい」・画面が無い | 止める(200) |
| どれかが「閉じない」 | 409 `refused` |
| 3 秒で済まない | 409 `asking`。あとで「閉じてよい」がそろえば入口が自分で止まる(頼みは 2 分で取り下げ) |

閉じた合図が届かなかった画面は、最後の声から最大 75 秒「居る」とみなします。デスクトップ版の画面はこの頼みを受けません(外からの停止は窓の × で来るため)。
機能ごとに訊く入力の一覧は `docs/ランチャー連携.md` の表のとおりです。

| 場面 | 動き |

## 10. 版の管理

| 版 | 出どころ | いま |
|---|---|---|
| 統合ツール | `config/app.json` の `version`(exe の `src-tauri/tauri.conf.json`・`src-tauri/Cargo.toml` もそろえる) | 1.2.21 |
| 梱包明細 | `modules/packing_details/config/app.json` | 0.13.21 |
| ペナラベル | `modules/packing_pena_label/app/config.py` の `APP_VERSION` | 1.5.28 |
| 資材計算 | `modules/packing_material_calculation/config/app.json` | 0.2.22 |
| 移植元 | 各機能の `__init__.py` の `PORTED_FROM`(変えない) | 0.13.1 / 1.5.0 / 0.2.0 |

- 統合ツールの版は**配るたび**に上げます。機能の中身を変えたら、その機能の版と統合ツールの版の両方を上げます(決まりは `docs/変更履歴.md`)
- 版は「数字.数字.数字」。違う形なら `/api/health` の `version_problem` に理由が出ます(起動は止めない)
- 起動時の入れ替え判定は版の組(`version_set`。例 `app=1.2.21;details=0.13.21;material=0.2.22;pena=1.5.28`)で比べます(`common/versions.py`)
- 静的ファイルの URL には「版-中身の指紋」が入るので、版を上げ忘れても古い CSS・JS は使われません

## 11. 主な HTTP の口(統合アプリ自身のもの)

| 口 | トークン | 中身 |
|---|---|---|
| `GET /` | 要らない | 準備中は待機画面、準備完了なら統合画面。`?go=1` なら準備中でも統合画面 |
| `GET /api/health` | 要らない | `app_id` `display_name` `version` `versions` `version_set` `version_problem` `app_root` `mode` `port` `pid` `ready` `stage` `stage_key` `startup_error` `uptime_sec` `job` `modules` |
| `POST /api/alive` | 要らない | 心拍。本文 `client`(名乗り)`state`(visible/hidden)`leaving`(閉じた)`replaces`(前の名乗り)`page`(ブラウザ版の統合画面だけ) |
| `POST /api/shutdown` | 要る | 本文 `force` `screens_ready`。200 `stopped` / 409 `busy` `refused` `asking` / 401 トークン違い / 501 止め方が無い |
| `GET /api/close-ask` / `POST /api/close-answer` | 要る | 外からの停止の頼みと、画面の返事(`working` `ok` `refused`) |
| `GET /log` | 要らない(中の操作は要る) | ログとエラーの記録の画面 |
| `GET /api/log/status` `/api/log/incidents` `/api/log/incidents/<番号>` `/api/log/recent` | 要る | ログの様子・エラーの記録の一覧と中身・今日のログ |
| `POST /api/log/settings` | 要る | 出力先・残す日数(`check` / `save` / `reset`) |
| `GET/POST /api/log/distribution` | 要る(POST は管理者パスワードも) | 配布設定(共通)の様子・書き出す・読み込み直す・消す |
| `GET /api/theme` / `POST /api/theme` | GET は要らない / POST は要る | 画面の色 |
| `POST /api/client-log` | 要る | 画面のエラーの報告(1 分 60 件・1 件 16KB まで) |
| `GET /manual/` `/manual/<キー>` | 要らない | 説明書(キーは `shell` `details` `pena` `material`) |
| `GET /favicon.ico` | 要らない | 中身なしの 204 |

- トークンはヘッダ `X-Tool-Token` か `X-App-Token`、または `?t=`。3 機能とも同じ値です
- 待機画面の時間帯(本体を組み立てる前)は `boot_server.BootApp` が `/`・`/api/health`(`ready: false`)・`POST /api/shutdown` だけに答え、ほかは 503 `starting` を返します
- 準備中に `/details` `/material` の入口を開くと、統合アプリの待機画面(`/`)へ回します(ペナラベルは回さない)
- 機能の停止口(`/details/api/shutdown` など。資材計算の帯の「終了」が使う)も、取り込み中なら 409 `busy` で断ります(`force` で中断)。
  `/api/shutdown` と同じ判定(`app._shutdown_refusal`)を通るので、**ほかの画面に保存していない入力があれば 409 `asking` で確かめます**(統合 1.2.26。以前は機能の停止口だけ確かめずに止めていた)。断りの返事には `ok: false` が付きます

## 12. 断り方・エラーの扱い

| 場面 | 扱い |
|---|---|
| Host が `127.0.0.1` `localhost`(デスクトップ版は `app.localhost` も)以外 | 400 `bad_host` |
| GET 以外の要求が別のページから(`Sec-Fetch-Site` が same-origin / none 以外) | 403 `cross_origin` |
| 3 機能の断り(401 か 403 か・本文の形) | 各機能のまま(画面の JS がその形を見ている) |
| 予期しない例外 | エラーの記録を作り、「処理中にエラーが起きました(エラー番号 E…)…」を返す(JSON か HTML) |
| 断り・失敗(400・500 番台) | 画面に出した文言をログに残す |
| ログの 1 行 | `[要求 R-xxxxxx]` の印つき。心拍などの数秒ごとの要求は DEBUG |
| エラーの記録の中身 | なぜなぜ分析の順(何が起きたか・直接の原因・エラーまでの流れ・そのときの状態・なぜ 1〜5 の記入欄)。パスワード・合言葉・トークンは伏せる |
| 統合画面の接続確認 | 15 秒ごとに `/api/health`。2 回続けて失敗で「接続なし」と赤い帯。pid が変わっていれば「アプリが開き直されています」 |
| 待機画面 | `app_id` が違えば「別のアプリが同じポートを使っています」。`startup_error` があれば「起動できませんでした」と「このまま終了する」。25 回続けて応答が無ければ「バックエンドに接続できません」 |
| CORS | ヘッダを一切返さない |
