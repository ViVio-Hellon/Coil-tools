# ペナラベル 思想とモード

対象の版: ペナラベル 1.5.39(コイル梱包ツール 1.2.38)

この文書は、ペナラベルが **なぜこの作りになっているか**(設計の考え方)と、ツールの中にある **モード・状態** をまとめたものです。
考え方の根拠は、コードのコメントと `modules/packing_pena_label/docs/` の文書です。根拠の場所を各項目に書いています。

---

## 0. 移行の経緯

もとの VBA は **ハードコード(コードの中に値を直接書いたもの)が多かった**。現場の担当がそれを少しずつ外へ出したり
変数(定数)にしたりして整理し、そのうえで Python への移行に踏み切った(VBA の元ソースは
`modules/packing_pena_label/docs/VBA元ソース/`。2026-10-22 受領)。Python 側もこの方針を引き継ぎ、
値はコードに埋めずに外へ出す(サイズ構成 `data/size_master.json`、資材の単重は資材マスタ、追加サイズは資材マスタの表、
印刷位置の補正・参照先は設定)。

## 1. 設計の考え方

### 1.1 VBA と 1 対 1 に対応させる

もとの Excel VBA の手続き 1 つに、移植先の関数・画面 1 つを対応させています。

- 風袋計算は「計算式・分岐・丸めは VBA と 1 対 1 に対応させている」(`app/services/tare_calc.py` の先頭)。関数名の対応表も先頭に書いてあります(`SetCoilDimensions` → `set_coil_dimensions()` など)。
- API は「VBA のボタン処理に 1 対 1 で対応させる」(`app/routes/api.py`)。重量反映 = `CommandButton1`、重量計算_DB = `CommandButton16` などです。
- 定数も VBA と **同じ名前** にそろえています(`CHIP_THICKNESS_MM` など)。突き合わせやすくするためと、片方だけ直してずれるのを防ぐためです(`docs/03` の A-1c)。
- 「どこを直せばよいか」は `docs/02_移植対応表.md` から引けるようにしています。

**わざと移さなかったもの** もあります。Excel のシートの表示切替、日報ブックを開くボタン、引数に誤りのある旧経路の重量計算(`CommandButton6`)などです(`docs/02` の 8 章)。

### 1.2 丸めと型を VBA に合わせる

「移植で最も事故が起きやすいのが『丸め』と『型』であるため、業務ロジックからは必ずこのモジュール経由で丸め・書式化を行う」(`app/services/vba_compat.py`)。

| VBA の動き | 移植での合わせ方 |
|---|---|
| `Dim TA As Single` | 単精度に丸める `single()`。エサフォームの「0.82 を超えるか」を単精度で比べるので、境目で結果が変わりうる |
| `Format(x, "0.0")`・`WorksheetFunction.Round` | 0 から遠い方への四捨五入。Python の `round()`(偶数への丸め)は使わない |
| 丸める前の数の見方 | 有効数字 15 桁の 10 進で見る(2 進の誤差で 8.445 が 8.44 になるのを防ぐ。統合 1.2.12) |
| `Val(本数 × 重量)` | 掛けた値をいったん 15 桁の文字にしてから読む。これを飛ばすと NW が 0.1 違うことがあった(統合 1.2.6) |
| 計算式の欄の `&` 連結(`CStr`) | 倍精度は 15 桁、単精度は 7 桁で文字にする。マスタの値は文字のまま出す(係数 "1" を "1.0" にしない) |
| `GetUnitMassAndCoefficient` が見つからないと空 | 0kg で続ける(下の 1.4) |

### 1.3 値は勝手に変えない。変えるときは確かめてから

「いずれも現行の計算結果を変えずに移植している。確認のうえ『直す』判断が出たものだけを、設定または個別対応で変更する」(`docs/03_不明点と要確認事項.md` の先頭)。

確認を経て変えたものは、次のように記録してあります。

| 変えたもの | 根拠 |
|---|---|
| 高さの計算を 1 つにまとめた(ハードボード側の誤りを正した) | `docs/03` A-1。VBA 側も同じに直した |
| 羅列計算を風袋計算と同じ計算にした(EX-DRY 込み・ハードボード厚み込み) | A-2 / A-3 |
| 積み高さ計算の巾を 53.5mm にそろえた | A-4(設定で戻せる) |
| 検査番号の 3 文字目も確かめる | B-2(判定は一番最後に置き、これまでの文言は変えない) |
| サイズ名の表記をそろえた(`73mm` → `73.0mm`) | C-5(計算には影響なし) |

VBA の **文言・判定順** はそのまま残しています(`app/services/validation.py`。全サイズの「おちつけシートがねぇぞ」も VBA のまま)。

### 1.4 0kg で続けるが、黙らない

マスタに無い資材名を引くと、VBA は静かに 0kg で計算を続けていました。移植でも結果(0)は同じにし、**どの資材が見つからなかったかを記録して画面とログに残します**(`app/repositories/material_repo.py` の先頭)。結果を変えずに、気付けるようにするという考えです。

係数が 1 以外になったときも診断画面に出るようにしています(係数の意味がコードから読めないため。`docs/03` C-3)。

### 1.5 出荷ラベルなので、古い値を黙って刷らない

ラベルの検番・重量は「重量反映」で、本数・高さ・NW・GW は「重量計算_DB」でしか書き換わりません。VBA も同じです。入力を変えて重量反映だけすると、1 枚のラベルに別々のコイルの値が混ざります(`docs/03` A-6)。

「出荷ラベルなので、黙って古い値を刷るのは避けたい一方、値を勝手に作り替えるのも避けたい」という判断で、**値は VBA のまま、食い違っている間は印刷そのものを止める** ことにしました。ボタンを消すだけでは Ctrl+P で刷れてしまうので、紙に出る中身も止めています(`app/routes/pages.py` の `label_print()`)。

### 1.6 作業状態は 1 組、入力画面は 1 枚

作業状態(検査番号・重量・本数・計算結果)はサーバ側に **1 組** しかありません(状態DB の `form_state` は利用者を区別しない 1 件)。入力できる画面を 2 枚開くと両方が同じ 1 組を書き換え、「画面に出ている検査番号と、刷られる検査番号が食い違います」(`app/templates/_layout.html` の画面ガードの文、`app/static/js/app.js`)。

そこで入力画面(指定サイズ・全サイズ・設定)は同時に 1 つだけにし、2 枚目は開くこと自体を断ります。VBA は UserForm が 1 つだけだったので、同じ状況は起きませんでした(`docs/04` D-3)。表示だけの画面と印刷用のタブは数に入れません。

操作も **押した順に 1 つずつ** サーバへ送ります。続けて押して返事の順が入れ替わると、あとの結果を前の返事で上書きすることがあったためです(`app.js` の `post()`。統合 1.2.20)。

### 1.7 共有のマスタは読むだけ、状態はこの PC に

| | 置き場所 | 読み書き |
|---|---|---|
| 資材マスタ | 共有(全ライン) | **読むだけ**(SQLite は読取専用で開く) |
| 作業状態 | この PC(`%LOCALAPPDATA%`) | 読み書き |

書き込みが 1 か所でも混ざるとロックの問題が始まるので、「読むだけ」を崩さないことが要になります(`docs/04` §3)。例外は、合言葉を入れてするマスタ管理とサイズを足すだけで、書く前に控えを取ります。

状態DB のパスは設定できません。共有フォルダーに置けないので、複数の PC から同じ状態DB へ書く事故が起きません(`docs/04` §6)。

### 1.8 マスタを直したら、刷る前に必ず届く

「マスタを直したのに古い内容で刷られた」は、コイルに違う型番のラベルが貼られることなので、取りこぼしを許さない扱いにしています(`docs/04` §7)。

- 「重量計算_DB」を押した瞬間は、鮮度チェックの間隔に関係なく資材マスタを確かめる(`load(check_now=True)`)。
- ラベル台紙を開くたびに、ラベル台紙一覧と足したサイズを読み直す(`Workflow.label_view()`)。
- 一方で、共有フォルダーへ届かないときは前に読んだ内容で続けます。ネットワークの瞬断でラインを止めないためです。そのときは全画面の右上の札を赤くして「（古い内容）」と出します(`docs/04` D-8)。

### 1.9 図は計算しない

風袋計算の「図で見る」は、「計算はしない。描くのは風袋計算の結果そのもの。数は画面・印刷の表と同じ文字を使う(図と表で数が食い違わない)」(`app/services/tare_figure.py` の先頭)。図のために丸める前の風袋・GW を結果に残すようにしました(統合 1.2.21)。図は画面だけに出し、印刷の紙面は VBA のシートと同じ表のままです。

断面図は包装仕様書(7C1175)の「内装」「前」「横」の図に合わせ、左半分を外から見た所(ピン=樹脂製丸棒・PET バンド)、右半分を断面(積み方・外周を包む物)にしています(1.5.35。それまではピンをパレットの角に、バンドを縦だけに描いていて、現場の写真・仕様書と違っていた)。高さは寸法どおりの縮尺ですが、チップボール(0.7mm)とハードボード(2.35mm)は薄すぎて見えないので、そこだけ最低の太さで描き、寸法は数で添えています。

### 1.10 紙面は実寸で描く

「Excel の行高・列幅は写さない。台紙の実寸を『データ』として外へ出し、mm 絶対配置で描く」(`docs/06_ラベル印刷の実寸化.md`)。

- Excel の段の間隔はばらついていましたが、これは手で詰めた跡で、現場の答えも「シールの範囲内に入ればいいぐらい」だったので、等しい間隔で作り直しました。
- 台紙の寸法は `data/label_stock.json` にあり、台紙を替えるときにコードを直さずに済みます。
- プリンターは紙の縁 約 4mm に刷れないので、文字・罫線・バーは紙の端から 5mm 以上内側に置き、試験で毎回確かめています。

### 1.11 現場に計算をさせない

位置合わせは「現場に計算をさせない。『どっちへ何 mm ずれているか』をそのまま入れてもらい、補正はこちらで足し引きして保存する」(`pages.py` の `label_calibration()`)。いまの補正も「X +2.50mm」ではなく「右へ 2.5mm」のように言葉で出します。

### 1.12 合言葉はうっかり防止

「秘密を守る仕組みではなく、うっかり防止のための手掛かり」(`app/services/settings.py`)。参照先を変えたりマスタを直したりすると全員の計算・印刷に影響するので、そのときだけ確かめます。プリンターの癖を吸収するだけの位置合わせには要りません。

### 1.13 そのほか

- **設定は 2 層。画面の保存はこの PC だけ** … アプリ本体を共有フォルダーに置いても、そこへ書き戻さない(書込権限が無くて失敗する・他の人の設定まで変わるため。`docs/05`)。
- **読み直さずに状態を出す** … 操作のあとはページを読み直さず、`data-live` の付いた部分だけ差し替えます(`app.js` の `pplRefresh`。統合 1.2.11)。
- **サイズはデータで持つ** … VBA はサイズを `Select Case` に書いていましたが、`data/size_master.json` に出し、新しいサイズは共有マスタの表に足せるようにしました。

## 2. モード・状態

### 2.1 丈1・丈2・丈1丈2同時(OB モード / CB モード)

VBA のフォームでは、丈を 1 つずつ選ぶ OptionButton(OB)と、丈1・丈2 をまとめて選ぶ CheckBox(CB)が排他になっていました。移植も同じ 2 つのモードを持ちます(`app/models/__init__.py` の `FormState`)。

| | OB モード(丈1 / 丈2) | CB モード(丈1・丈2 同時) |
|---|---|---|
| 画面 | 「まとめてやりたい場合チェックon」を外す。サイズごとに「丈1」「丈2」 | チェックを入れる。サイズごとに「丈1・丈2 同時」 |
| 持つ値 | `selected_ob`(台紙番号 1〜14、足したサイズは 15〜) | `selected_cb`(1〜6、足したサイズは 100 番台)か `named_cb`(0.8mm×53.5mm) |
| 台紙 | 奇数 = 丈1、偶数 = 丈2 の 1 枚 | 丈1 と丈2 の 2 枚の組(`cb_to_pair()`。0.8mm×53.5mm は 13・14) |
| 重量の確かめ | 選んだ丈の重量が要る | 丈1・丈2 とも要る |
| 重量反映 | 1 枚に書く(VBA `ExecuteWrite`) | 2 枚に書く(VBA `チェック入力`) |
| 小ラベル印刷 | 1 枚(「サイズ名 　丈N を印刷しますか？」) | 2 枚(「サイズ名 　丈1,2 を印刷しますか？」) |

- 画面の下の案内も「丈1 または 丈2 を個別に処理します(VBA の OptionButton モード)」「丈1・丈2 を同時に処理します(VBA の CheckBox モード)」と切り替わります。
- チェックを入れ外しすると、モードに合わない選択は外れます(VBA の排他と同じ考え方)。
- 0.8mm×53.5mm は VBA で名前付きのコントロール(`ck_08_53` / `lblSpec_08_53_1`・`_2`)だったので、別の扱い(`named_cb`)になっています。

### 2.2 take1 / take2 の表示

VBA の `Take1.Visible` / `Take2.Visible` は、移植では **選択から導いて** 決めます(`take1_visible` / `take2_visible`)。

| 選び方 | 丈1 の欄 | 丈2 の欄 |
|---|---|---|
| CB モード | 出す | 出す |
| OB モードで奇数(丈1) | 出す | 薄くして入れられない |
| OB モードで偶数(丈2) | 薄くして入れられない | 出す |
| 何も選んでいない | 薄い | 薄い |

- 薄い丈では、新重量の欄と積み本数(丈1 は 1・2梱包目、丈2 は 3・4梱包目)が入れられません(`app.js` の `applyTakeVisibility`)。
- NW は表示している丈の重量でだけ計算します(表示していない丈は 0)。
- VBA では表示がサイズ選択と別のプロパティだったので、「両方隠れているのにサイズは選ばれている」状態が作れ、無言で止まることがありました。移植は選択から導くので、この食い違いは起きず、止めるときは「コイルサイズが選択されていません」と理由を出します(`validation.validate_settings()`)。

### 2.3 資材マスタの読み元のモード

| モード | 右上の札 | 起きること |
|---|---|---|
| SQLite | SQLite | 本命。設定してあれば最初に読む。マスタ管理・サイズを足すができる |
| Access | Access(ACE) | 「旧 Access(.accdb) も試す」がオンで、SQLite が読めないとき。`cscript` 経由 |
| CSV | CSV | 上が読めないとき、設定で指定した CSV を読む(空なら読まない)。サイズは足せない |
| 止める | (計算すると理由が出る) | どれも読めず前の内容も無い。「資材重量なし」と、何が読めなかったかを出して止める(同梱のサンプルへは落ちない。統合 1.2.31) |
| 古い内容 | 「（古い内容）」付き(赤) | 読み元へ届かず、前に読んだ内容で計算している |
| 未読込 | 未読込 | まだ一度も読んでいない。計算すると「資材重量なし」 |

型番マスタにも「表『型番』(SQLite)」と「型番マスタ CSV」の 2 つの読み元があり、DB が先です。

### 2.4 バーコードの描き方(SVG / フォント)

設定「バーコードの出し方」(`barcode_mode`)で選びます(`app/services/barcode39.py`、`label_sheet._barcode_html()`)。

| モード | 中身 | よい点 | 気を付ける点 |
|---|---|---|---|
| `svg`(既定) | Code39 のバーを自分で描く | フォントを入れて回らなくてよい。字形の差でバー幅が変わらない。静止帯を確実に取れる | 現行の読取機での実機確認はまだ(未確認) |
| `font` | `assets/fonts/` の Code39 フォントの字形で出す。横だけ引き伸ばして枠いっぱいに使う | Excel と同じ字形 | フォントは同梱していない。無いと赤い警告が出て、`*…*` の文字がそのまま刷られる |

`font` 以外の値はすべて SVG として扱います。どちらでも、バーコードにする文字は VBA と同じ(`*型番*`・`*検番コイル番号 重量*`)です。全サイズの印刷も同じ描き方です。

### 2.5 印刷ビューと画面

同じ中身でも、どこで開くかで出方が変わります(`pages.py` の `_shell()`)。

| 出し方 | 経路の例 | 中身 |
|---|---|---|
| 画面(起動ページの中) | 左のタブを押す(`?pane=1` で中身だけ取って差し替える) | 指定サイズの入力をそのまま残して、表示だけ替える |
| 画面(1 枚のページ) | `/tare` などを直接開く | 外枠つきのページ |
| 印刷用のタブ | `/labels/print` `/tare/print` など | 左のタブを出さず、「印刷する」「このタブを閉じる」の帯だけ。入力画面の数に入れない。図・案内は紙に出さない |

- 印刷用のタブのうち、風袋計算・羅列計算・ラベル台紙(確認用の一覧)・全サイズは開くとすぐ印刷の窓を出します。小ラベルと位置合わせは出しません(ボタンで刷る)。
- デスクトップ版では、印刷用のタブが別の窓で開きます(変更履歴 1.5.13 による。統合アプリ側のコードは(未確認))。
- 画面は統合画面の「画面の色」(自動・ライト・ダーク)に従いますが、紙・ラベル・印刷用のタブ・バーコードはどれを選んでも白地に黒です(変更履歴 1.5.12)。

### 2.6 計算済み / 入力が変わった状態

`Workflow.calc_is_stale()` が、計算したときの入力の控え(`tare_inputs`)といまの入力を比べます。

| 状態 | 条件 | 印刷 |
|---|---|---|
| まだ計算していない | 控えが無い(一度も計算していない・クリアした) | 止めない |
| 計算済み | 控えといまの入力が同じ | 刷れる |
| 入力が変わった | サイズ・チップボール・検番・重量 丈1・丈2・本数のどれかが控えと違う | 止める(「印刷する（停止中）」、一覧の印刷リンクを出さない、Ctrl+P でも理由だけを刷る)。風袋計算の印刷も同じ(1.5.30) |

重量計算_DB を押し直すと控えが新しくなり、「計算済み」に戻ります。

### 2.7 足したサイズ

| | 同梱のサイズ | 足したサイズ |
|---|---|---|
| 定義の場所 | `data/size_master.json`(この PC のアプリ) | 共有の資材マスタの表「ペナラベル追加サイズ」 |
| 台紙番号 | 1〜14 | 15 から(丈1 が奇数) |
| 同時の番号 | CheckBox1〜6 / `ck_08_53` | 100 番台 |
| ハードボードの固定物の判定 | VBA の決まり(サイズの名前と本数) | 巾と本数(巾 53.5mm の 11 本 / 10 本) |
| 直せるもの | — | 型番・記号・備考だけ(サイズ名・巾・番号は台紙と結び付くので直させない) |
| 画面の印 | — | ラベル台紙の一覧に「追加」、備考は赤字 |

同じ番号・同じ寸法なら同梱が先で、共有の表で同梱のサイズを上書きさせません(`SizeMaster.apply_extra()`)。

### 2.8 そのほかのモード・状態

**入力画面の使用権**(`app/services/screen_guard.py`、`app.js`)

| 状態 | 画面 |
|---|---|
| 確かめ中 | 「画面を確認しています…」(操作できない) |
| 使える | 覆いが消える。5 秒ごとに生存を知らせる |
| 開けない | 「この画面は開けません」(先に開いた画面がある)。相手が裏に回っていればそれも出す。「この画面で使う」で移せる |
| 取られた | 「この画面は使用中ではなくなりました」(別の画面で「この画面で使う」が押された) |

生存の知らせが 20 秒途切れたら空きとみなします。ただし裏に回ると知らせた画面は 12 時間空きにしません(ブラウザが裏のタブのタイマーを間引くため。`docs/04` §6 ④)。誰も使っていないだけなら、警告を出さずに黙って取り直します。

**ハードボードの数え方** … 固定物 HB590(巾 53.5mm・11 本)/ 固定物 HB530(10 本)/ 標準(外周 + 700mm × 積高)。フラグが立っても結果が変わるのは巾 53.5mm の 10・11 本だけで、ほかは将来のための枠です(`tare_calc.judge_hb_flag()`)。

**エサフォームの周回** … コイル高さ 820mm 以下は 1 周、超えると 2 周。

**全サイズの副番** … 2ケタ(例 1-1。重量は丈ごとに 1 つ)/ 3ケタ(例 2-2-1。上下の段で重量を分ける。3ケタのときだけ「重量 1-2-?」「重量 2-2-?」の欄が濃くなる)。

**進み具合** … 重量計算_DB が 0.3 秒より長くかかるときだけ棒を出します(すぐ終わるときにちらつかないため)。

**羅列計算** … タブから外した状態です。計算のコードと API は残っており、ナビに 1 行足せば戻せます(`docs/03` 0 章)。羅列計算の画面(`/list`)の注記は、計算(`list_calc.build_list()`)のとおり「風袋計算と同じ 9 項目・ハードボード厚み込み」と書いています(1.5.29 で、古い「EX-DRY を含まない 8 項目」の注記から直しました)。

**統合版と単体** … 統合版では経路に `/pena` が付き、API に起動トークンが要り、「使用ポート」は設定画面に出しません(`settings.integrated()`)。入口が無いとき(単体で動かす試験)は従来どおりです。

**試験の印** … 環境変数 `COIL_PACKING_TOOLS_E2E_NO_AUTOPRINT=1` があると、印刷ビューを開いても印刷の窓を自動で出しません(デスクトップ版の通し試験用。ふだんは使いません)。
