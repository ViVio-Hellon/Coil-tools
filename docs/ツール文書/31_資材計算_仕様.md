# 資材計算 仕様

対象の版: 資材計算 0.2.33(コイル梱包ツール 1.2.53)

この文書は「資材計算(コイル梱包資材計算ツール)」が**何をするか**を、コードで確かめた範囲で書いたものです。
コードの場所は、とくに断りがなければ `modules/packing_material_calculation/` から見た道で書きます
(例: `coil_tool/stack_service.py` は `modules/packing_material_calculation/coil_tool/stack_service.py`)。

## 1. 目的と範囲

アルミコイルの梱包に使う資材の数を出し、倉庫へ出す発注票まで作る機能です。

- **パレット**(コイルを載せる台)の種類・サイズ
- **積数**(1 台のパレットに積むコイルの本数)と**台数**(要るパレットの数)
- **リプラ**(再生プラスチック製のスペーサー。コイルの下とコイルどうしの間に敷く棒)の長さと本数
- **緩衝材**(HB = ハードボードなど)の枚数

元は Excel の VBA(フォーム `UF_Material`・バリ揃え用の `UFalmo`)でした。それを Python に移したものです
(`docs/VBA解析.md`・`docs/移植計画.md`)。
扱う包装仕様 No は `1C1xxx`(コイル)です。板・ザラ板(`1P1xxx`)は扱いません。

流れ:

    LotNo(7桁) → 受注番号の候補 → 受注情報の展開 → 検入数・コイル外径を入れる
      → 計算Start(パレット種類 → パレットサイズ → 積数・台数 → リプラ)
      → チェックリスト(15行)へ積む
      → 発注票(リプラの角サイズごと)を作る → 印刷 → 発注済みとして記録(履歴)

範囲に入らないもの: 担当者の名簿を直すこと(日報ツール側。ここでは読むだけ)・仕掛台帳を書き換えること(読むだけ)・包装仕様書そのものを見ること(閲覧システムを開くだけ)。

## 2. 画面構成

統合画面の **資材計算** タブの中で動きます。経路の前に `/material` が付きます(`__init__.py` の `PREFIX`)。

### 2.1 上の帯

版(`VER0.2.22`。押すと 設定 → 「このアプリ」)・マスタの取り込み日時と「古い」の札(`data_sync.stale_reason`)・
ライン(LS4 / NS1)・担当者(班員名簿のうち担当ラインが「機側」の人。`coil_tool/staff.py`)が出ます。ライン・担当者は選んだ時点で保存します。

### 2.2 左のタブ(レール)

`app/shell.py` の `PAGES`。この並びが仕事の順番です: **資材計算**(`/calc`)→ **チェックリスト**(`/checklist`)→ **発注票**(`/order`)→ **設定**(`/settings`)。

### 2.3 計算画面(`app/templates/calc.html`)

**1. ロットと受注** … 打つ欄(ほかより大きな字): LotNo(7桁)・受注番号(選ぶ)・検入数(本)・コイル外径(mm)。
ボタン: **計算Start** / **単重再計算** / **はじめから**。展開される欄: 厚・幅・受注材質・受注調質・用途ｺｰﾄﾞ・用途名・包装仕様No(押すとコピーして閲覧システムを開く)・
製品単重・再計算した単重・取引先・納入先・梱包単位 重量・梱包単位 枚数・外径 MIN/目標/MAX・内径 目標・営業納期・比重・工場用コメント

**2. 計算結果** … パレット種類・パレットサイズ・パレット名称・積数(本/台。**手で直せる欄**)・台数・
別枠 積数 / 台数(1 本積み不可で分けたときだけ出る)・総高さ・コイル間・ﾘﾌﾟﾗｻｲｽﾞ・緩衝材・HB枚数・**ﾘﾌﾟﾗ総本数**(発注する数)。

「最下部(パレットの上)」の枠(長 / 短 を列にした長さ・本数の表、本数(マスタ)、リプラ種類)と「コイル間」の枠(長さ・本数・リプラ種類。
1C1282 のときだけ IMI 中間 長さ・本数)、「ｻｲｽﾞ確定品」のチェック、**チェックリストへ積む**、**バリ揃え梱包…**。

**3. バリ揃え梱包** … 計算結果の右下の「バリ揃え梱包…」で開く窓(`<dialog>`)です。上バリ(本)・下バリ(本)を **−** **＋** か打ち込みで入れ、
**計算Start** で上台数・下台数・台数を出し、**結果転送** で本体へ送ります。**閉じる** で戻ります。

### 2.4 計算結果の印(フラグ)

計算は「どの規則で決まったか」を `flags` として返し、画面はそれを写すだけです(`coil_tool/models.py`、`app/static/js/views/calc.js`)。
色だけに頼らず、見出しに ● も付けます(`app/static/css/coil.css` の `.f--why`)。

| フラグ | 意味(VBA の色) | 画面の出方 |
|---|---|---|
| `weight` | 重量で決まった(`F重量` 赤) | 「梱包単位 重量」の見出しが赤字+● |
| `count` | 枚数で決まった(`F枚数` 赤) | 「梱包単位 枚数」の見出しが赤字+● |
| `height` | 高さで取り直した(`F高さ` 赤) | 「総高さ」の見出しが赤字+● |
| `spec` | 包装仕様 No 別の規則が動いた(`F包装仕様` 赤) | 重量・枚数の見出しが赤字+● |
| `no_single` | 1 本積み不可の品(`FM` 水色枠) | 別枠の値を青い枠で囲む |
| `single_split` | 1 本積み不可で台数を分けた(`FM` 赤枠) | 同上 |
| `spacer_differs` | 最下部とコイル間でリプラ種類が違う | 両方の「リプラ種類」の見出しが赤字+● |

## 3. 入力と出力

### 3.1 読むもの(取り込み元)

| もの | 置き場所(既定) | 読む表 | 使い道 |
|---|---|---|---|
| 梱包資材マスタ `梱包資材マスタ.sqlite3` | 共有フォルダ(設定で変えられる) | 包装仕様 / パレット / リプラサイズ / 班員名簿 | 判定の入口・パレットの適合範囲・定尺・担当者 |
| 仕掛台帳 `SIKAHIKI.sqlite3` | 共有フォルダ(設定で変えられる) | 仕掛(→ 手元の「仕掛引当」) | LotNo → 受注番号・出荷日 |
| 仕掛台帳 `SIKAODR.sqlite3` | 同上 | 仕掛(→ 手元の「仕掛受注」) | 受注番号 → 計算に要る値 |
| 第2パス(仕掛台帳) | 空でよい | 同上(ファイル名も変えられる) | 第1パスに無いファイル・ロット・受注を足す(両方にあれば第1パス) |
| 実績の形式の LS4 ファイル(統合 1.2.29) | 梱包課共有の仕掛フォルダ。**名前が LS4LOT 以外のときだけ**読む | 要る列をそろえた表(いまの年月の行だけ → 手元の「コイル実績」) | **コイル外径 = BOX実績_ｺｲﾙ内径 + 2 × BOX実績_ｺｲﾙ肉厚**。無ければ受注の外径 MAX(`coil_tool/coil_results.py`。[`docs/仕掛ファイルの仕様.md`](../仕掛ファイルの仕様.md)) |

- 取り込み元は**この PC(一時フォルダ)へ写してから、写しを読み取り専用で**開きます(統合 1.2.28・現場の指示。`coil_tool/source_db.py` → `common/source_copy.py`)。共有の上のファイルは直接開きません(書き戻し=マスタ管理だけは共有のファイルへ書き、書いたあとは写し直します)。`SIKALOT.sqlite3` は取り込みません(VBA も開いていない。起動時の診断にだけ名前が出ます。`coil_tool/config.py`)。
- 包装仕様 No は**先頭 6 桁**だけを使います(`coil_tool/lot_service.py`)。
- 取り込み元に同じ番号の行が 2 つあるときは**先の行を残し**、飛ばした番号を取り込みの結果に出します(`docs/不明点.md` Q21)。

| 作業用DB `coil_tool.db` | `%LOCALAPPDATA%\CoilMaterialTool\data\` | 取り込んだ写し(包装仕様・パレット・リプラサイズ・班員名簿・仕掛引当・仕掛受注)、発注チェックリスト、発注履歴、取り込み履歴(`coil_tool/schema.sql`) |

### 3.3 書くもの

| もの | 書き先 | いつ |
|---|---|---|
| 発注チェックリスト | 作業用DB の表 `発注チェックリスト` | 「チェックリストへ積む」・消す |

| 梱包資材マスタ(包装仕様・パレット・リプラサイズ) | **共有フォルダの元のファイル** | マスタ管理で直したとき(合言葉が要る)。書いた表だけ取り込み直す |
| 配布設定 `設定.json` | 統合アプリのフォルダの `配布設定\packing_material_calculation\` | 配布設定を書き出したとき |

- 「書き出し先」(CSV を出す場所)の欄は 0.2.23 で設定・配布設定から外しました。移植元から欄だけがあり、そこへ書く処理が
  どこにもありませんでした。前の設定に値が残っていても使いません(`config.export_dir` は将来書き出す機能を足すときのために残っています)。

### 3.4 取り込みの決まり

- **起動時に自動で取り込み**ます(設定で切れる)。元ファイルの更新時刻を覚えていて、変わっていない表は飛ばします(`data_sync.auto_import`)。
  起動の待ちは最長 120 秒で、過ぎたら画面を先に開き、取り込みは裏で続けます(`__init__.py` の `IMPORT_WAIT_LIMIT_SEC`)。
- 設定の **いま取り込む** は全部を取り込み直します(`data_sync.import_all`)。1 つ失敗しても残りは続けます。
- **日付が変わっても自動では取り込み直しません。** 取り込んだ日と今日が違えば帯に「古い」を出します(理由: `not_imported` まだ取り込んでいない / `date_changed` 取り込んだ日から日付が変わった)。

### 3.5 マスタ・台帳が変わったとき(0.2.31)

- 起動時の自動取り込みは、取り込み元の目印(本体・`-wal`・`-journal` の大きさ・更新時刻 ns。読む前に取る)が前と**一致するか**で決めます(以前は「更新日時が前の取り込みより新しいか」で、WAL・更新日時を保った差し替え・バックアップへの戻しを取りこぼした)。
- 動いている間も、画面を開いたとき・計算Start・積数の手直し・マスタ管理を開いたときに目印を確かめます。梱包資材マスタの4表とコイル実績が変わっていればその場で取り込み直し、仕掛台帳は帯に「共有の仕掛台帳が更新されています [いま取り込む]」を出します。帯は「写した日時」と「確かめた日時」を分けて出します。取り込み中は計算Start を断ります。
- 計算Start・積数の手直しの前に受注番号から受注を引き直し、違えば「受注の内容が取り込み直しで変わりました(項目: 前 → 後)」と出します(外径・検入数は変えない)。
- 計算結果は計算したときの取り込みの世代を持ち、マスタ管理・取り込みのあとの古い結果はチェックリストへ積めません(「「計算Start」で計算し直してください」)。発注票はチェックリストの指紋を持ち、チェックリストを変えたら捨てます(印刷・記録も断る)。
- マスタ管理で、プログラムの規則が優先される品番(特別ルール)の行に「規則が優先」の札を出します。

## 4. 計算の決まり

`calc_service.calculate`(VBA `CommandButton5_Click`)が、ソフトクリア(計算結果だけ消す)→ パレット種類 → パレットサイズ →
積数・台数 → リプラ の順に呼びます。**前の段が書いた値を次の段が読む**ので、順番は変えません。

ソフトクリアは**断る前に**します。断ったときに前の結果が残ると、そのままチェックリストへ積めてしまうためです(統合 1.2.26)。
検入数・外径を入れ直したときも、前の計算結果を消して「検入数・外径が変わったので前の計算結果を消しました。「計算Start」で出し直してください」と出します(値として同じ — 900 と 900.00 — なら消しません)。

### 4.1 ロットと受注(`coil_tool/lot_service.py`)

- LotNo は英数字だけを通し、小文字は大文字にします。画面は 7 桁そろうと自動で探します。
- 候補は**仕掛引当と仕掛受注の両方にある受注番号だけ**(重複は落とす)。候補が 1 つなら画面が自動で選びます。
- 候補は作業状態にも持ちます(統合 1.2.30)。ほかの面へ移って戻ったとき(画面を読み直したとき)も、選択肢と選んだ受注番号を出し直します。以前は画面だけが持っていて、戻ると受注番号の欄が「—」になりました。
- 実績の形式の LS4 ファイルにそのロットがあれば、コイル外径(内径 + 2 × 肉厚)と、検入数が空なら検入数(BOX実績_枚本数。無ければ 横割数 × 縦割数)を入れます(`docs/仕掛ファイルの仕様.md`)。第1パスの行で外径・検入数が出せなければ、第2パスの同じロットの行で空の項目だけ埋めます(0.2.30・現場の指摘)。
- 受注の値の 0 は、文字列 **「データなし」** にします(梱包単位_重量・梱包単位_枚数・外径 MAX/目標/MIN・内径)。
  以降の判定は「数として読めない = 指定なし」と読みます(VBA の `IsNumeric` と同じ)。
- 書式: 板厚は小数 3 桁、板幅は小数 1 桁、製品単重は小数 2 桁(有効数字 15 桁で見て四捨五入。VBA の `Format` と同じ)。
  そのほかの数は小数を切り捨てずにそのまま。
- コイル外径の欄には、外径 MAX が「データなし」でなければその値を入れます(打ち直せます)。外径の入力は小数 2 桁にそろえます。検入数・積数は整数で、小数を打つと断ります(`not_integer`)。

### 4.2 パレット種類(`pallet_service.pallet_type`)

1. 包装仕様マスタの「パレット」列がそのまま種類になります。
2. 「サイズ」列に値があれば**指定パレットフラグ**(`PFlag`)、「種類」列に値があれば**特殊フラグ**を立てます。
3. 最後に外径によるパレット種類の上書き(0.2.32・現場の指示: マスタ優先)。共有の梱包資材マスタに表
   **「パレット種類_外径条件」**(包装仕様No・順番・外径_以上・外径_以下・パレット種類・備考)があれば、その包装仕様No の行を
   順番どおりに見て、`以上 <= 外径 <= 以下`(空は制限なし)に最初に当たった行のパレット種類にします。当たらなければ包装仕様の
   値のまま。表があるときはコードの規則は使いません。**表が無ければ取り込みのときに共有へ自動で作ります**(0.2.33)。
   いまの規則と同じ2行(1C1103: 〜799.99 → 全面、800〜990 → 強度UP)が入ります。共有に書けなくて作れないときは次の取り込みで
   また作ります。マスタ管理の「表を作る(1C1103 の今の規則を入れて)」(パスワードが要る)でも作れます。
   表がまだ無いときだけ、コードの規則(`coil_tool/special_rules.py`。VBA の 外径 800 未満 → 全面 / 780〜890 → 強度UP /
   890〜990 → 強度UP / 990 超 → マスタのまま。先に当たった条件が勝つので、780〜799 は「全面」。`docs/不明点.md` Q1)で動きます。

包装仕様 No がマスタに無いときは「包装仕様No … がマスタに登録されていません」と出し、計算を断ります(`spec_not_found`)。

### 4.3 パレットサイズ(`pallet_service.pallet_size`)

パレットマスタの同じ種類の行から、外径が収まる行を選びます。

| パレット種類 | 収まる条件 |
|---|---|
| スカシ / 全面 | 巾下限 ≤ 外径 ≤ 巾上限 **かつ** 丈下限 ≤ 外径 ≤ 丈上限 |
| 強度UP | 巾下限 ≤ 外径 ≤ 巾上限(丈は見ない。2024.3.4 の暫定) |
| それ以外(EXPS・ｸｰﾗｰﾌｨﾝ・ﾎｲｰﾙ など) | Ｗ ≥ 外径 |

- 収まる行のうち**Ｗがいちばん小さいもの**を選び、その「新記号」をパレット名称、Ｗをパレットサイズにします。
  同じＷの行がいくつかあれば、**最後の行**を採ります(VBA と同じ)。
- そのあと指定パレットフラグで上書きします。
  - 数のとき: そのＷの行に決め打ち。数でも「外径指定」でもない文字のときは何もしない
  - 「外径指定」のとき(1C1258): 外径 700–780 → 800 / 781–880 → 900 / 881–980 → 1000 / 981–1080 → 1100 /
    1081–1180 → 1200 / 1181–1249 → 1300 / 1250–1330 → 1350。どの段にも当たらなければ最小選定のまま(`docs/不明点.md` Q2)
- 収まる行が無いとき: 「外径 … が収まる「…」のパレットがマスタにありません」と出します。
  - **ﾎｲｰﾙ**は計算を断ります(`no_pallet_fits`。`REFUSE_WITHOUT_PALLET`。VBA は負の台数を出していた。`docs/不明点.md` Q24)
  - ほかの種類は VBA と同じく、パレット欄を空のまま計算を続けます

### 4.4 積数(`stack_service._decide_stack`)

先に断る条件:

| 条件 | 文言 | reason |
|---|---|---|
| 検入数が空 | 検入数を入力してください | `no_inspection_count` |
| 検入数が 1 未満 | 検入数には1以上を入れてください | `bad_inspection_count`(VBA は台数 0・負のままチェックリストへ積めた。統合 1.2.26) |
| 包装仕様 No が空 | ― | `no_spec_no` |
| 包装仕様がマスタに無い | 包装仕様No … がマスタに登録されていません | `spec_not_found` |
| オーダーの梱包単位_重量・枚数が両方「データなし」 | 引当データなし。計算ができません | `no_allocation_data` |

**5 段の優先順位**(上から見て最初に当たったもの。オーダー情報が包装仕様マスタより強い):

| 段 | 条件 | 積数 | 印 |
|---|---|---|---|
| 1 | オーダーの梱包単位_重量が数 | 切り捨て(重量 ÷ 製品単重) | `weight` |
| 2 | オーダーの梱包単位_枚数が数 | 切り捨て(枚数。`count_stack`)。枚数範囲が「1不可」なら 1 本積み不可 | `count`(+`no_single`) |

### 4.5 1 本積み不可の振り分けと台数(`stack_service._split_for_no_single`)

    x = 銀行丸め(検入数 ÷ 積数)      ← VBA の Round(…, 0)。0.5 は偶数の側へ

| 条件 | 台数 | 積数 | 別枠 |
|---|---|---|---|
| 1 本積み不可 かつ 検入数 − x × 積数 = 1 かつ x = 1 | 2 | 検入数 ÷ 2(小数は切り捨て) | 使わない |
| 1 本積み不可 かつ 検入数 − x × 積数 = 1 かつ x ≥ 2 | x − 1 | そのまま | Re_積数 = 切り捨て((検入数 − (x−1) × 積数) ÷ 2)、Re_台数 = 2 |
| それ以外 | 切り上げ(検入数 ÷ 積数) | そのまま | ― |

振り分けたときは `single_split` と `spec` の印が付きます。チェックリストの台数は **台数 + Re_台数** です。

検入数が 1 本で 1 本積み不可のときは、どう分けても 1 本の台ができるので、「検入数が1本のため、1本積み不可の振り分けができません。積数を手で入れてください」で断り、積数・台数を空にします(`no_single_one_coil`。VBA は台数 -1 を出していた。統合 1.2.26)。

### 4.6 高さの制限(`stack_service._apply_height`)

包装仕様 No 別の規則が動いたとき、またはオーダーの梱包単位_枚数が数のときは**飛ばします**(取引先の指定なので高さで動かさない)。
そのときは 1C1281 ﾐﾔﾏｾｲｺｳ だけ、総高さ = 積数 × リプラサイズ + 積数 × 幅 + 210 を「mm」付きで出します(`spec`・`height` の印)。

それ以外で、包装仕様に**梱包総高さ**があるとき(`_height_from_spec`):

| 高さ範囲 | 上限の高さ |
|---|---|
| 以下 / 程度 / max | 梱包総高さ − 210(パレットの上下ぶん) |
| 蓋除き | 梱包総高さ − 80(上ぶんだけ) |
| パレット除き | 梱包総高さ そのまま |

- 重量で決めた(`weight` の印がある)ときだけ、`積数 × (リプラサイズ + 幅)` が上限を超えたかを見て、超えていれば
  `積数 = 切り捨て(上限 ÷ (リプラサイズ + 幅))`、台数も取り直します(`height` の印)。総高さ = 積数 × (リプラサイズ + 幅) + 210(切り捨てない)。
- リプラサイズが「可変」の品は、超過の判定では厚みを 0 として読み、判定で取り直さなかった場合も最後に厚み 30mm で必ず取り直します(VBA の `GoTo LineSkip` の順のまま)。
- 「パレット除き」で、リプラサイズが数の品は、コードの字面では取り直しの経路に入りません。`docs/VBA解析.md` §4.2 の表とは読み方が違い、
  どちらが VBA の実際と同じかは試験で固定されていません(未確認)。

梱包総高さが無く、**重量で決めた**とき(`_height_from_pallet`。2022.07.25):

    上限 = パレットサイズ − (リプラ厚み + 幅)      ← リプラサイズ「可変」は 30mm
    (リプラ厚み + 幅) × 積数 > 上限 なら 積数 = 切り捨て(上限 ÷ (リプラ厚み + 幅))

高さで取り直した積数が 0 以下なら「高さの制限に収まる積数がありません」で断ります(`zero_stack_by_height`)。

**積数の欄に書く値**: 最後に積数の欄へ積数を書きます。**1本積み不可の振り分けで 2 台へ均等に分けたときだけ**書かず、振り分けで書いた
「検入数 ÷ 2」を残します。重量で決めて梱包総高さが無い品は、上の「パレットの幅で抑える」段で書き終えています。

VBA は `If Not x = 1 Then 積数 = StackC` で、x(検入数 ÷ 積数 の偶数丸め)が 1 なら**均等に分けていなくても**書かなかったため、
検入数 5・積数 4 のようなふつうの品で、台数 2 なのに積数の欄が空・ﾘﾌﾟﾗ総本数 0 になっていました。**VBA のバグ**と現場で確認し、
0.2.23 で直しました(`stack_service.py`。VBA の画面を写した照合表 `docs/検証/VBA実績.csv` の L7134G0・Q1271A0 は「既知の違い」に理由を書いています)。

### 4.7 リプラ(`coil_tool/ripla_service.py`)

マスタの値をそのまま画面へ写します: コイル間 = コイル間スペーサー、ﾘﾌﾟﾗｻｲｽﾞ、最下部本数 = 下本数、緩衝材、間リプラ種類、最下部リプラ種類。
コイル間スペーサーと最下部スペーサーが違えば `spacer_differs` の印。1C1188 ｼﾏﾉ は角サイズを上書きします(0.8×260 → 40、それ以外 → 30)。

途中で抜ける条件(どれもリプラ総本数は **0**。VBA の戻り値の既定値と同じ):

| 条件 | 出すもの |
|---|---|
| コイル間スペーサーが「リプラ」「LVS」以外(チップ・外装紙・クラフトなど) | HB枚数 = 台数 × 2 |
| 積数が空 | ― |
| リプラサイズ(マスタ)が 80 | HB枚数 = 台数、総本数 = 積数 × 2 × 台数(長さを持たない固定品) |
| 定尺(リプラサイズの表)が 1 つも無い | ― |

**長さ**(`MaxVal` = 表「リプラサイズ」の長さのうち、パレットサイズ以下で最大のもの。無ければ 0):

| パレット種類 | 最下部の長さ | コイル間の長さ |
|---|---|---|
| 全面 | パレットサイズ | 最下部 − 100 |
| EXPS | パレットサイズ | 最下部 − 350 |
| それ以外(スカシ・ｸｰﾗｰﾌｨﾝ・ﾎｲｰﾙ など) | MaxVal | 最下部 − 100 |

コイル間の長さが 800 以上なら、その長さ以下で最大の定尺に選び直します(倉庫でのカットを避ける)。
最下部の「短」の長さは、コイル間の長さと同じ値を出します。

**本数**:

    1台あたりのコイル間 = (積数 − 1) × 2
    台の合計            = 台数 + Re_台数
    最下部の長い本数    = 台の合計 × 最下部本数(EXPS は 1)
    最下部の短い本数    = 台の合計 × 0(EXPS は 2)

    コイル間の本数:
      検入数 ÷ 台数 が割り切れる、または Re_積数 がある → 1台あたり × 台数
      割り切れない → 1台あたり × (台数 − 1) + (検入数 − (台数 − 1) × 積数 − 1) × 2
      Re_積数 がある → さらに (Re_積数 − 1) × 2 × Re_台数 を足す
                       (Re_積数 は**割ったままの値**。2.5 なら (2.5−1)×2×2 = 6本 = 3本の台 4 + 2本の台 2。
                        画面の Re_積数 は切り捨てた 2 を出すが、それで数えると 2本少なかった。統合 1.2.32)

    HB枚数     = 台の合計
    ﾘﾌﾟﾗ総本数 = コイル間 + 最下部の長い + 最下部の短い

特別な品:

| 条件 | 決まり |
|---|---|
| ｺｲﾙ間は間紙入 = 「〇」(協豊製作所向け) | コイル間の長さ・本数を空にし、緩衝材を「外装紙」に。総本数 = 下本数 × 台数。VBA はここで「型が一致しません」で止まるが、移植は続けて計算する(`docs/不明点.md` Q23) |
| 1C1282 ｱｲｴﾑｱｲｶﾊﾞｰ | コイル間 800 / 最下部の短 600 / 中間 950 に固定。中間本数と短い本数 = 台の合計 × 2。総本数に中間本数を足す。チェックリストへ 2 行 |
| 1C1297 ｺﾄﾌﾞｷｾｲﾐﾂ | チェックリストへ 2 行(間リプラ種類の行・最下部リプラ種類の行) |

### 4.8 積数を手で直したとき(`calc_service.recalculate_from_stack`)

画面が先に積数を `/api/calc/input` で送り(整数でなければ断る)、続けて `/api/calc/restack` を呼びます。

パレット種類・サイズを引き直し(ﾎｲｰﾙで収まらなければ断る)、積数が 0 以下なら「積数には1以上を入れてください」(`zero_stack`)で断り、
**台数 = 切り上げ(検入数 ÷ 積数)** を出してリプラを計算し直します。積数の規則(5 段・包装仕様 No 別・高さ)は通しません。

**手で入れた積数のほかは、前の計算結果(別枠 Re_積数・Re_台数、印、断り、リプラ)を全部消してから**出し直します(`CalcState.clear_results(keep_stack=True)`)。
高さの規則は通しません(手で入れた積数が最後の答え)。

**1 本積み不可の品は、手で入れた積数でも最後の台を 1 本にしません**(統合 1.2.27・現場の指示)。
「1 本積み不可か」は計算Start と同じ決まり(`stack_service.no_single_by_rule`。5 段の 2 段目・4 段目で枚数範囲が「1不可」)で見て、
最後の台が 1 本になるなら §4.5 と同じ振り分け(`_split_for_no_single`)をします。

| 例(1 本積み不可) | 手で入れた積数 | 台の中身 | 台数(チェックリスト) |
|---|---|---|---|
| 検入数 13 | 4 | 4・4 + 別枠 3・2(1 台戻して 2 台に分ける) | 2 + 2 = **4** |
| 検入数 13 | 5 | 5・5・3(1 本の台が出ないので分けない) | **3** |
| 検入数 5 | 4 | 3・2(2 台ぶんしかないので均等に) | **2** |
| 検入数 1 | 2 | ― 断る(`no_single_one_coil`) | ― |

分けたときは「1本積み不可のため、最後の台が1本にならないように分けました(…)」と出します。1 本積み不可でない品は、手で入れた積数のまま切り上げます(4・4・4・1 も可)。

> **VBA のバグを直しました(統合 1.2.26・現場で確認)。** VBA `積数_AfterUpdate` は前の計算の別枠と印を消さずに計算し直していたため、
> 1 本積み不可で分けたあとに積数を直すと、チェックリスト・HB・リプラで台数を二重に数えていました
> (検入数 13・枚数 4・1不可 → 2 台 + 別枠 2 台(4・4 + 3・2)に分かれたあと、積数 5 に直すと 5・5・3 の 3 台のはずが、
> 別枠 2 台が残って 5 台)。

- 積数が空なら「積数を入力してください」(`no_stack`)、検入数が空・1 未満なら §4.4 と同じ断り。
- 断ったときは前の結果も残りません(積めない)。
- `units` を渡すとその台数を使います(バリ揃え梱包の結果転送。§4.9)。

### 4.9 バリ揃え梱包(`coil_tool/burr_split.py`)

上下の本数は検入数を超えないように詰めます(上が先、超えたぶんは下を詰める)。残り検入数 = 検入数 − 上 − 下。

積数の決め方(本体と**枝の入れ子が違う**ので、別に書き写してある):

| 条件 | 積数 |
|---|---|
| オーダーの梱包単位_重量が数 | **切り上げ**(重量 ÷ 単重)… 本体は切り捨て(`docs/不明点.md` Q5。VBA のまま) |
| オーダーの梱包単位_枚数が数 | その枚数を小数点第 1 位で切り捨て(本体と同じ `count_stack`。以前は切り捨てず、枚数 2.5 で台数がずれた。統合 1.2.26) |
| 包装仕様の梱包単位_重量が数 | 本体の 3 段目と同じ(切り捨て) |
| 包装仕様の梱包単位_枚数が数 | 枚数範囲「以下」「max」ならその枚数(切り捨て)、ほかは 0 |
| どれも無く単重 > 500kg | 1 |

    上台数 = 切り上げ(上本数 ÷ 積数)    下台数 = 切り上げ(下本数 ÷ 積数)    台数 = 上台数 + 下台数

断る条件: 製品単重が空(`no_unit_weight`)、検入数が空・1 未満(`no_inspection_count`)、包装仕様が無い(`spec_not_found`)、積数 0 以下(`zero_stack`)。
計算だけでは本体は変わりません。**結果転送**で積数と台数を本体へ書き、§4.8 と同じ道(`recalculate_from_stack(units=台数)`)でパレット・リプラを出し直します。
前の計算の別枠・印は消します(残すとチェックリストで台数を足してしまう。統合 1.2.26)。

### 4.10 単重再計算(`coil_tool/coil_weight.py`)

    重量(kg) = π/4 × (外径² − 内径²) × 比重 × 幅 ÷ 10⁶      ← 小数 2 桁で切り捨て

外径は入力欄、内径は内径 目標、幅は受注板幅、比重は材質_比重。どれかが無い・0 なら「指定項目に入力がありません(内径、外径 …)」で断ります(`missing_values`)。結果は「再計算した単重」の欄に出すだけで、**製品単重は書き換えません**(計算にも使いません)。

### 4.11 数の丸め(`coil_tool/vba.py`)

| VBA | ここ | 決まり |
|---|---|---|

| `RoundUp(x, 0)` | `round_up` | 0 から遠いほうへ。有効数字 15 桁で見てから(1640 ÷ 65.6 = 25 のまま) |
| `RoundDown(x, 0)` | `round_down` | 0 に近いほうへ。有効数字 15 桁で見てから(1760 ÷ 70.4 = 25 のまま) |
| `Format(x, "0.00")` | `fmt` | 有効数字 15 桁で見て四捨五入(106.475 → 106.48) |

## 6. 発注票

`coil_tool/order_sheet_service.py`、`coil_tool/order_history.py`、`app/routes/order.py`。

### 6.1 作る

1. チェックリストを行番号順に読みます(空の行は飛ばす。チェックリストを印刷したかどうかとは関係しない)。
2. **コイル間が「リプラ」「LVS」の行だけ**を明細にします。ﾘﾌﾟﾗ長さ・ﾘﾌﾟﾗ本数に改行があれば 2 件に分けます(無ければ 1 件)。
3. 角サイズ+長さが同じものは本数を足し、LotNo は出てきた順のまま重複を落として空白で並べます。
4. 種類(リプラ → LVS)ごと、角サイズ(出てきた順・最大 3 種)ごとに 1 票。
5. 長さの行は**梱包資材マスタの表「リプラサイズ」の長さ**(小さい順・重なりなし)+ 書き足し用の空欄 4 行。
   表が空のときだけ設定 `stock_lengths`、それも無ければ原紙の 8 種(700 / 800 / 900 / 950 / 1000 / 1050 / 1100 / 1150)。
6. 定尺に無い長さは空欄の行へ書き足します。**5 件以上あれば作りません**(`too_many_extra_lengths`「発注リストにないサイズが多すぎます」)。
   80×80 は長さを持たないので、枠だけの票になります。0 本は空欄にします。

断る条件: 担当者が未選択(`no_worker`)、票にできる行が無い(`nothing_to_order`)、書き足しが 5 件以上。

### 6.2 重複の確かめ(2 週間)

- 票に載る LotNo ごとに、発注履歴を `LotNo LIKE %ロット%`(部分一致)で引き、**登録日時が今日から 0〜14 日前**のものがあれば知らせます(1 ロットにつき最新の 1 件)。
- **止めはしません。** 票の中身を見せたうえで「このまま作る」「やめる」を選ばせます。「このまま作る」は確かめを飛ばして作り直します(`確認済み`)。文面: 「ロット「…」は N日前(mm/dd)に発注済みです。担当者／登録内容(サイズ / 数量本)」。

### 6.3 履歴に残す

- 作った票は**サーバのメモリ**に持ちます(`_pending`。プロセスに 1 つ)。閉じると消えます。
- **発注済みとして記録** を押すと、長さ・LotNo・数量がそろった行だけを発注履歴へ追記します
  (処理日 `mm/dd`・担当者・品名(リプラ / LVS)・サイズ・長さ・LotNo・数量・単位「本」・登録日時)。
- 同じ票の 2 度目は断ります(`already_committed`、409)。作り直せばまた記録できます。
- 票を作る前に記録しようとすると「先に発注票を作ってください」(`nothing_pending`)。記録した発注は、発注票の画面の下の **発注の履歴**(新しい順に 200 件まで・LotNo で絞れる)で見られます(0.2.23 で足しました。以前は履歴を返す口 `/api/order/history` だけがあり、見る画面がありませんでした)。

## 7. 印刷

`coil_tool/printing.py`、`coil_tool/reports.py`。HTML と印刷用の CSS で紙面を作り、ブラウザの印刷で刷ります。

| 帳票 | 経路 | 紙 | 決まり |
|---|---|---|---|
| チェックリスト | `/report/checklist` | A4 横・1 ページ | 紙の端から 6mm 内側。15 行ぶんの枠を必ず出す。はみ出すぶんだけ縮めて 1 枚に収める |
| 発注票 | `/report/order` | A4 横 1 枚につき 1 票 | 票は紙の左半分。真ん中に縦の切り取り線(細い実線)。切ると A5 縦。紙の端から 8mm 内側 |

- `@page` の余白は 0 にし、紙の中で内側へ寄せます(印刷ダイアログの余白「なし」でも端まで出ない。`SAFE_MARGIN_MM` = 5mm 以上)。
- 印刷用の画面の上の **「印刷する」** は画面だけに出て、紙には出ません。
- 発注票の体裁は原紙 `注文票.xlsx` に合わせています(上に「発注票」、右に提出日付 `9/25` の形 / 依頼者の囲み、1 行目が `ﾘﾌﾟﾗ` と角サイズ、見出しの行なし、LotNo と数量のあいだに縦線なし)。
- LotNo が欄に入らないときは字を小さくし、6pt まで来たら折り返します(欠けない)。依頼者の名前が長いときも字を小さくします。
- 定尺が原紙の 12 行より多いときは、行の高さと字を縮めて 1 枚に収めます。

`app/routes/settings.py`、`coil_tool/config.py`、`coil_tool/user_settings.py`、`coil_tool/distribution.py`。
設定は面(タブ)に分かれています: **取り込み / マスタ管理 / ラインと担当者 / 配布設定 / 保存先(このPC／共有) / このアプリ**。

| 項目 | 鍵(`user_config.json`) | 変えるのに合言葉 | 配布設定に入るか |
|---|---|---|---|
| 梱包資材マスタのフォルダ | `master_db_dir` | 要る | 入る |
| 第1パス: 仕掛台帳のフォルダ | `lot_db_dir` | 要る | 入る |
| 第1パス: 梱包課共有の仕掛のフォルダ・LS4LOT の名前 | `konpo_db_dir`・`konpo_db_file` | 要る | 入る |
| 第2パス: 仕掛ファイルのフォルダ | `lot_db_dir_2` | 要る | 入る |
| 第2パスの名前(SIKAHIKI / SIKAODR / LS4LOT の代わり) | `lot_db2_file_hiki` / `lot_db2_file_odr` / `lot_db2_file_ls4` | 要る | 入る |
| 起動時の自動取り込み | `auto_import_on_start`(既定 ON) | 要らない | 入る |
| ライン | `line`(LS4 / NS1、既定 LS4) | 要らない | 既定では入れない |
| 担当者 | `worker`(既定は未選択) | 要らない | 入れられない |
| 発注票の定尺 | `stock_lengths`(画面に欄は無い) | ― | 入る |
| 合言葉 | `admin_password`(撹拌した値) | 今の合言葉が要る | 入る(撹拌した値) |

- 置き場所は**枠ごと**に直します(統合 1.2.30。梱包明細の「置き場所・取り込み」と同じ形。`settings.py` の `GROUPS`)。
  枠は 梱包資材マスタ / 第1パス 仕掛台帳 / 第1パス 梱包課共有の仕掛(LS4LOT) / 第2パス の4つで、フォルダとそのファイル名を同じ枠に入れます。
  - **確かめる** … 枠の中で打った値(保存前)で、届くか・目当てのファイルがあるか・要る列がそろっているかを見ます。ファイル名の確かめは、同じ枠で打ってあるフォルダを見ます。
  - **保存して取り込み**(`POST /api/settings/group`)… 枠の欄をまとめて保存し、**その枠の表だけ**取り込みます(マスタ → 包装仕様・パレット・リプラサイズ・班員名簿、仕掛台帳・第2パス → 仕掛引当・仕掛受注、梱包課共有・仕掛台帳・第2パス → コイル実績)。名前が使えない・書き方が読めない欄が1つでもあれば、枠ごと保存しません(422)。

- 配布設定は起動時に読み込みますが、**その端末にすでにある値は上書きしません**。「読み込み直す」は上書きします。書き出す・読み込み直す・消すには合言葉が要ります。

## 9. 作業状態は 1 組・要求は 1 つずつ

- 計算の入力と結果(`CalcState`)は**プロセスに 1 組**です(`app/session.py`)。VBA のフォームが 1 枚だったのと同じ持ち方です。保存はしません(止めると消える)。チェックリストだけは DB に残します。
- **使ってよい画面は 1 枚だけ**です(`app/screen.py`)。2 枚目は開いた時点で断り(`screen_taken`、409)、「この画面で使う」で取り上げられます。心拍が 3 回(心拍の間隔 × 3)途切れたら空きとみなしますが、裏に回っている画面は空きにしません。
- 作業状態を書く経路 **`/api/calc`・`/api/checklist`・`/api/order`**(`WORK_PREFIXES`)は、サーバ側で**1 つずつ**通します(`app/__init__.py` の `_WORK_LOCK`)。取り込み・設定・マスタ管理・心拍は待たせません。
- 画面側も同じ経路の要求を**押した順に 1 つずつ**送ります(`app/static/js/core.js` の `call`)。検入数は欄を離れたときに送るので、入れてすぐ「計算Start」を押しても、検入数の送信が先に済んでから計算されます(0.2.22 で直した)。

## 10. 主な API

経路はすべて `/material` の下です。`/api/*` と `/report/*` は起動トークンと同じオリジンを確かめます(`/api/health`・`/api/alive`・`/api/screen*` は除く)。

| 経路 | 中身 |
|---|---|
| `GET /`・`GET /api/health`・`POST /api/alive`・`POST /api/shutdown` | 待機画面 / 起動確認 / 心拍 / 停止 |
| `POST /api/screen/claim`・`GET /api/screen`・`POST /api/screen/release` | 使ってよい画面の受付 |
| `GET /api/calc`・`POST /api/calc/clear` | いまの計算画面 / はじめから |
| `POST /api/calc/lot` | LotNo → 受注番号の候補(候補が無くても 200。文言を添える)。候補は作業状態(`CalcState.候補`)にも持ち、画面の中身(`view.candidates`)で返す |
| `POST /api/calc/order` | 受注番号 → 受注情報の展開 |
| `POST /api/calc/input` | 検入数・外径・積数を受ける |
| `POST /api/calc/run` | 計算Start |
| `POST /api/calc/restack` | 積数の手直しから出し直す |
| `POST /api/calc/weight` | 単重再計算 |
| `POST /api/calc/burr`・`POST /api/calc/burr/transfer` | バリ揃え梱包の計算 / 結果転送 |

## 11. 断り方

断りは HTTP の状態番号で種類を分け、**`reason` 定数**で中身を運びます。画面は文言から推し量りません。

| 番号 | 意味 | 主な reason |
|---|---|---|
| 400 | 入力の形が違う(サーバの状態は動いていない) | `no_order_no`・`bad_row_no`・`no_field`・`nothing_to_save`・`unknown_key`・`no_password`・`no_screen`・`bad_value`(マスタ) |
| 403 | その操作をする資格が無い | `bad_token`・`cross_origin`・`needs_password`・`wrong_password`・`not_allowed`(マスタ) |
| 404 | 発注票がまだ無いのに紙面を開いた | ― |
| 409 | 先を越された・いまこの画面に資格が無い | `screen_taken`・`already_committed`・`no_row`(マスタ) |
| 422 | 形は正しいが業務として断る | `no_inspection_count`・`bad_inspection_count`・`not_positive`(検入数の入力が 1 未満)・`no_single_one_coil`・`spec_not_found`・`no_spec_no`・`no_allocation_data`・`no_pallet_fits`・`zero_stack`・`zero_stack_by_height`・`no_stack`・`not_integer`・`order_not_found`・`missing_values`・`no_unit_weight`・`not_calculated`・`no_worker`・`checklist_full`・`row_out_of_range`・`nothing_to_order`・`too_many_extra_lengths`・`nothing_pending`・`bad_line`・`bad_worker`・`bad_name` |
| 500 | 書けなかった | `write_failed`(設定ファイル)・`failed`(配布設定)・`no_hook`(停止) |
| 503 | 起動の準備中 | `starting` |
