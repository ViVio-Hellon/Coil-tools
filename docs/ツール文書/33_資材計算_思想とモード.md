# 資材計算 思想とモード

対象の版: 資材計算 0.2.30(コイル梱包ツール 1.2.49)

この文書は、資材計算が**なぜこの作りなのか**と、ツールの中にある**モード・状態**をまとめたものです。
根拠は、コードのコメントと `modules/packing_material_calculation/docs/` の文書です。
コードの場所は `modules/packing_material_calculation/` から見た道で書きます。

---

## 1. 設計の考え方

### 1.1 元の VBA の答えを「正しい答え」として移す

元は Excel の VBA(主画面 `UF_Material`、バリ揃え用の `UFalmo`)でした。移すときの約束は
「**移したアルゴリズムは 1 行も変えない**」です(`docs/移植計画.md` §1)。

- コードの字面と業務の意図が食い違って見えるところも、**勝手に直さず VBA どおり**に移し、試験で「現行の挙動」として固定しています。
  食い違いは `docs/不明点.md` に分けて、判断を待っています(例: 1C1103 の外径の境目の重なり Q1、外径指定の隙間 Q2、バリ揃えだけ切り上げ Q5)。
- 直したのは、**現場から答えをもらったもの**だけです。
  - ﾎｲｰﾙで収まるパレットが無いとき、VBA は負の台数を出す → 移植は断る(Q24)
  - 協豊製作所向け(ｺｲﾙ間は間紙入〇)で VBA は「型が一致しません」で止まる → 移植は続けて計算する(Q23)
  - 発注票の長さの行を、原紙の決め打ちから梱包資材マスタの表「リプラサイズ」へ(Q8)
- VBA で放っておかれていた発注票の不具合(チェックリストの 1 行目が空だと出せない・チェックリストを発行せずに発注票を出すとエラー)は、移植では起きません(`docs/VBA解析.md` §6.2)。
- 2026-09-23 に現行 VBA の画面を書き出してもらい、7 件・99 欄と色(赤い欄・FM の枠)がすべて一致しました(`docs/移植計画.md` §5、`docs/検証/照合のやり方.md`)。

**数の丸めと型が、ずれのいちばんの原因**なので、VBA の数の扱いは `coil_tool/vba.py` 1 か所に集めました
(銀行丸めの `Round`、Excel の `RoundUp`/`RoundDown`、`Format`、`Val`、`IsNumeric`、単精度どうしの比較)。
判定側は `vba.round_up(...)` のように呼ぶだけです。

**包装仕様 No 別の規則**は、VBA ではあちこちの関数に `If PackagingNO = "1C1188" Then …` の形で散っていました。
「どこに何があるか分からない」のが元のいちばんの保守の重荷だったので、`coil_tool/special_rules.py` 1 か所に集めました(判定の順番と中身は変えていない)。

### 1.2 フォームを模した入れ物と「順番がすべて」

VBA はフォームそのものを作業場所にしていて、関数どうしがフォーム経由で値を渡し合っていました
(`PalletType` が書いた指定パレットフラグを `PalletSize` が読む、`台数計算` が書いた積数を `リプラ計算` が読む)。

移植では、引数と戻り値に分けずに**同じ受け渡しの形**を残しました(`coil_tool/models.py` の `CalcState`)。
分けると「この時点でこの欄はもう埋まっているか」という前提がコードから消え、結果を合わせにくくなるためです。
そのかわり、呼ぶ順番(パレット種類 → パレットサイズ → 積数・台数 → リプラ)は `coil_tool/calc_service.py` に書いて、変えないことにしています。

### 1.3 「データなし」を値として残す

VBA は受注の値が 0 のとき、文字列「データなし」をフォームに入れ、以後は「数として読めない = 指定なし」と読んでいました。
**この表現が判定の入口そのもの**なので、移植でも数量を文字列で持ち、「データなし」をそのまま残しています(`coil_tool/lot_service.py`、`models.OrderInfo`)。
数に寄せると空欄と 0 の区別が消え、積数の優先順位が変わってしまいます。

### 1.4 業務の判断は Python 側、画面は写すだけ

守っている約束(`app/__init__.py`、`docs/移植計画.md` §1):

1. 業務判断はすべて Python。JavaScript は返ってきたもの(ビューモデル)を画面に写すだけ
2. API は**更新後の中身一式**を返す(差分ではない)。どこかが古いまま残る、を起こさない
3. 断りの種類は HTTP の状態番号と `reason` 定数で運ぶ
4. 同じ事実を 2 か所に持たない

たとえば検入数の整数チェックや外径の小数 2 桁への整形も、画面ではなくサーバでしています(`app/routes/calc.py` の `set_input`)。

### 1.5 「どの規則で決まったか」を見せる

VBA の画面の色は飾りではなく**業務の情報**でした。赤い見出しは「重量 / 枚数 / 高さ / 包装仕様 のどれで積数が決まったか」、水色の枠は「1 本積み不可」です。
現場はこれを見て、出た数を信じてよいか判断しています(`docs/VBA解析.md` §4.1)。

そこで計算は**フラグも戻り値に含めて**返し(`flags`)、画面はそれを写します(`app/routes/calc.py` の `view_of`)。
色だけで意味を運ばないよう、見出しには ● も付けます(`app/static/css/coil.css`)。
リプラを「最下部」「コイル間」の 2 つの枠に分け、最下部を長 / 短の列にしたのも、**本数の取り違え**を防ぐためです(`app/templates/calc.html`)。

### 1.6 断るときは理由の定数で運ぶ

「文言ではなく定数で運ぶ(文言を直した日に区別が壊れないように)」(`coil_tool/pallet_service.py`)。
画面は `reason` を見て動き、文言から推し量りません。状態番号の分け方:

| 番号 | 意味 |
|---|---|
| 400 | 入力の形が違う。サーバの状態は動いていない |
| 403 | 入力は正しいが、いまこの操作をする資格が無い(合言葉・トークン) |
| 409 | 先を越された・いまこの画面に資格が無い |
| 422 | 形は正しいが業務として断る(引当データなし・積数 0 など) |
| 503 | まだ起動の準備中 |

VBA ではゼロ除算で止まっていた所(積数 0)も、止めずに理由つきで断ります(`coil_tool/stack_service.py`、Q6)。

### 1.7 画面は 1 枚

作業状態はプロセスに 1 組です(`app/session.py`)。VBA のフォームが 1 枚しか開かなかったのと同じ持ち方です。
まずいのは**ブラウザのタブは何枚でも開ける**ことで、2 枚開くと同じ 1 組を奪い合い、しかも打った値が相手の画面に出ないので**上書きに本人が気づけません**。

    タブA: LotNo 1234567 を打つ → タブB: LotNo 7654321 を打つ → タブA: 計算Start → 7654321 で計算される

**状態を分けるのではなく、画面を絞るほうで解きました**(`app/screen.py`)。分けると VBA と挙動が変わる(画面をまたいで値が続かない)ためです。
2 枚目は開いた時点で断ります ── 使えてしまってから「さっきの入力は消えました」と言うのがいちばん悪いからです。
ブラウザが固まったときに誰も使えなくならないよう、人が押す「この画面で使う」で取り上げられるようにしてあります(2 枚とも使える、にはしない)。

### 1.8 作業状態の要求は押した順に 1 つずつ

計算は「いったん結果を消してから出し直す」作りです(`CalcState.soft_clear`)。そこへ 2 つの要求が重なると、
片方が消した直後の空の結果を返したり、前の検入数で計算したりします(0.2.22 で直した。検入数 400 を入れてすぐ計算 → 台数 2、正しくは 80)。

- 画面: 作業状態を書く要求を**押した順に 1 つずつ**送る(`app/static/js/core.js` の `call`)
- サーバ: `/api/calc`・`/api/checklist`・`/api/order`(`WORK_PREFIXES`)を 1 つずつ通す(`app/__init__.py`)

待たせても誰も困らない(どれも一瞬で終わる)ので待たせます。取り込み・設定・マスタ管理・心拍は待たせません。

### 1.9 古いデータを黙って読み直さない

マスタは取り込んだ時点の写しです。**日付が変わっても、元が更新されても、黙って読み直しません** ── 計算の途中で足元の値が変わるほうが困るからです(`coil_tool/data_sync.py`)。
かわりに帯に取り込み日時を出し、取り込んだ日と今日が違えば「古い」と、その理由を出します。
以前は「24 時間たったら古い」でしたが、23:50 に取り込んで翌 0:10 に使うと前日の写しのまま計算できてしまうので、日付で見るように変えました(`docs/不明点.md` Q20)。

### 1.10 同じ事実を 2 か所に持たない

| 事実 | ただ 1 つの出どころ |
|---|---|
| 梱包資材マスタの中身 | 共有フォルダの元のファイル。マスタ管理はそこへ書き、書いた表だけ取り込み直す(手元を直しても次の取り込みで消えるため) |
| 担当者の名簿 | 梱包資材マスタの「班員名簿」(日報ツールが書く)。ここでは読むだけ |
| 発注票の定尺 | 表「リプラサイズ」(リプラの長さの選び方と同じ表) |
| 版 | `config/app.json` の `version` |
| マスタを直せるか | `master_admin.can_edit()` |
| 古いかどうか | `data_sync.stale_reason()` |

### 1.11 関門は書くほうにだけ

- **見るのは誰でもできます。** 中身を確かめられることと、書き換えられることは別の話です。
- **直すには合言葉が要ります。** 共有のマスタ・置き場所・配布設定を変える操作だけです。置き場所を間違えると**その端末が計算できなくなる**ので、担当者の選び直し(間違えても選び直せばよい)とは分けました。
- 合言葉は**誰かを見分けるものではなく**、うっかり書き換えを防ぐためのものです(`coil_tool/config.py`、`coil_tool/master_admin.py`)。
- 30 分さわらなければ閉じます。数えるのは「直せるかを実際に確かめたとき」だけで、画面を開いているだけでは延びません(開きっぱなしのタブが永久に閉じなくなるため。`coil_tool/admin_session.py`)。
- 合言葉そのものは設定ファイルに素のまま残しません(撹拌した値)。

### 1.12 誰が出したかを残し、仕事は止めない

- 担当者を選んでいないと、チェックリストへ積めず、発注票も作れません。依頼者欄が空のまま倉庫へ回ると、問い合わせ先が分からないためです(`app/routes/checklist.py`)。
- その一方で、**名簿が読めないだけで仕事を止めない**ようにしています。名簿を取り込めていなければ内蔵の 7 名、機側の人が 1 人もいなければ全員を出し、そうしていることを画面で言います(`coil_tool/staff.py`)。

### 1.13 発注は人が決める

- 2 週間以内の同じロットは**止めずに知らせる**だけです。中身を先に見せ、続けるかは人が決めます(VBA も「このまま重複して発注しますか？」と聞いていた。`app/routes/order.py`)。
- 履歴に残すのは「発注済みとして記録」を押したときだけ。同じ票を 2 度は記録しません。
- 止めると消えるもの(積んでいない計算・記録していない発注票・押していないバリ揃えの本数など)は、閉じる前に知らせます(`core.js` の `cptUnsaved`)。

## 2. モードと状態

### 2.1 モード(役割)

| 場所 | 中身 |
|---|---|
| `coil_tool/modes.py` | モードは **`main`(資材計算)1 つだけ**。元の VBA も 1 つのフォームで最初から最後まで操作する作りで、画面ごとに資格が分かれていないため。起動基盤がモードを引数に取る作りなので、形だけ残してある |
| `common/modes.py` | 統合アプリのモードも **1 つ**。3 つの機能はモードではなく**タブ**で分ける |
| `config/app.json` | 役割 `main` のポート 8733。統合版ではポートは統合アプリが決める(8740)ので使われない |

- `create_app`(この機能だけで立てるとき)は、知らないモード名を渡されると断ります(`app/__init__.py`)。`coil_tool/modes.normalize` は知らない名前をそのまま返し、呼び手に判断させます(既定へ倒すと、打ち間違いが「既定で起動した」としか見えないため)。
- 統合アプリ側の `common/modes.normalize` は、逆に知らない名前を既定のモードにします(モードが 1 つしかないので行き先は決まる)。

### 2.2 起動中 / 準備完了

| 状態 | 見え方 | 決まり |
|---|---|---|
| 起動中(`READY` が偽) | 待機画面。業務の API は 503 `starting`「起動しています」 | `app/routes/health.py`、`app/__init__.py` |
| 取り込み中 | 待機画面に進み具合 | 起動時の自動取り込み。最長 120 秒待ち、過ぎたら画面を先に開いて裏で続ける(`__init__.py`) |
| 準備完了 | `/material/calc` を開く | ― |

初期化の順番は「古い置き場所からの移し替え → 配布設定を読む → DB を用意(壊れていれば退けて作り直す) → 自動取り込み」です。
配布設定を取り込みより先に読むのは、置き場所が入っているからです。初期化に失敗してもサーバは落とさず、画面に理由を出します。

### 2.3 マスタの写しの状態

| 状態 | 理由の定数 | 帯 |
|---|---|---|
| 新しい | ― | 取り込み日時だけ |
| まだ取り込んでいない | `not_imported` | 「古い」 |
| 取り込んだ日から日付が変わった | `date_changed` | 「古い」(カーソルで理由) |

自動取り込みは、元ファイルの更新時刻が前回より新しい表だけを取り込みます。「いま取り込む」は全部です。

### 2.4 マスタの読み元と、管理の認証

| 場面 | 読む先 |
|---|---|
| 計算・担当者の一覧 | 手元の作業用DB(取り込んだ写し) |
| マスタ管理で見る・直す | 共有フォルダの元の梱包資材マスタ(開いてから読む。画面を開くだけでは共有に触らない) |

マスタ管理の状態:

| 状態 | できること |
|---|---|
| 見るだけ | 表を開く・絞り込む・並べ替える |
| 直せます(認証済み) | 包装仕様・パレット・リプラサイズの行を足す・直す・消す。置き場所・配布設定も変えられる |
| 見るだけの表 | 班員名簿(日報ツール)・板側の表など。理由を出して、直させない |

認証は**プロセスに 1 つ**で、複数のタブで共有します。30 分さわらないと「見るだけ」へ戻ります。

### 2.5 計算画面の状態

| 状態 | 中身 |
|---|---|
| 入力中 | LotNo・受注番号・検入数・外径。LotNo を打ち直すと全部消える(VBA の `フォームクリア`)。計算のあとで検入数・外径を入れ直すと計算結果だけ消える(統合 1.2.26) |
| 計算済み | 計算Start で結果が出た。計算Start は計算結果だけ消してから出し直す(`ソフトクリア` = `CalcState.clear_results`。断る前に消す) |
| 断られた | 結果の欄はそこまで出た分だけ。理由が画面の注意欄とトーストに出る |

**サイズ確定の有無**: 「ｻｲｽﾞ確定品」のチェックは、チェックリストの確定欄に `〆` を付けるだけです。計算・発注票・履歴には効きません。

**積数を手で直したとき**: 積数の欄を直すと、台数 = 切り上げ(検入数 ÷ 積数)で出し直し、リプラを計算し直します。
積数の規則(5 段・包装仕様 No 別・高さ)は**通しません** ── 手で入れた積数を規則で上書きしないためです(VBA `積数_AfterUpdate`)。
ただし **1 本積み不可は守ります**(統合 1.2.27・現場の指示)。最後の台が 1 本になるなら、計算Start と同じく 1 台戻して別枠 2 台に分けます(13 本・積数 4 → 4・4・3・2 の 4 台)。積数は手で入れた値、守るのは「1 本の台を作らない」ことだけです。
もう一度計算Start を押すと規則どおりに戻ります。
**手で入れた積数のほかの前の結果(別枠 Re_・印)は消してから**出し直します(`clear_results(keep_stack=True)`)。
VBA はこれを消さず、1 本積み不可で分けたあとに積数を直すと台数を二重に数えていました。VBA のバグとして直しました(統合 1.2.26・現場で確認)。
「手で入れた積数が最後の答え」なので、高さで直すことはしません(1 本積み不可の振り分けだけはする)。

**バリ揃え**: 「計算Start(窓の中)」は上下の台数を出すだけで本体を変えません。「結果転送」を押したときだけ積数・台数を本体へ書き、積数の手直しと同じ道(`recalculate_from_stack(units=台数)`)でパレット・リプラを出し直します。
計算しただけで画面が変わらないようにするためです(`coil_tool/burr_split.py`)。

**1 本積み不可**: 最後の 1 台が 1 本だけになるときに台数を分けます。2 台ぶんしかなければ 2 台へ均等に、それより多ければ 1 台戻して別枠(Re_)で 2 台に分けます。
検入数が 1 本なら分けようがないので断り、積数を手で入れてもらいます(`no_single_one_coil`)。

**2 行になる品**: 1C1282(ｱｲｴﾑｱｲｶﾊﾞｰ)と 1C1297(ｺﾄﾌﾞｷｾｲﾐﾂ)は、計算の途中で特殊フラグが立ち、チェックリストの同じ行番号に 2 行(枝番 0 / 1)入ります。

### 2.6 チェックリストと発注票の状態

| もの | 状態 | 残り方 |
|---|---|---|
| チェックリスト | 0〜15 行 | 作業用DB に残る(閉じても消えない。VBA の「ブックに残る」に合わせた) |
| 発注票 | 未作成 → 作成済み(重複の確かめ待ちのこともある) → 記録済み | サーバのメモリだけ。閉じると消える |
| 発注履歴 | 追記だけ | 作業用DB(このPC) |

### 2.7 画面の持ち主

| 状態 | 見え方 |
|---|---|
| 使ってよい画面 | ふつうに使える。心拍のたびに「まだ自分のものか」を確かめる |
| 断られた画面 | 「すでに別の画面で開いています」。相手がどれくらい前から開いているかも出す。「この画面で使う」で取り上げられる |
| 取り上げられた画面 | 次の心拍で「この画面は使われなくなりました」。書く要求はサーバでも 409 で断る |
| 裏に回った画面 | 心拍が途切れても空きにしない(最小化やスリープ明けで締め出さない) |

誰も画面を持っていないときは通します(画面なしで立てる使い方や試験を巻き添えにしないため)。

### 2.8 担当者一覧の出どころ

| 状態 | 出る人 |
|---|---|
| 名簿から(ふつう) | 班員名簿のうち、担当ラインに「機側」を含む人(班ごと) |
| 名簿に機側の人がいない | 名簿の全員(そう書いて出す) |
| 名簿を取り込めていない | 内蔵の 7 名(名簿の書き方に直した名前) |

いま選ばれている人が名簿から消えた・機側でなくなったときは、名前を残したまま「名簿にありません」「担当ラインが機側ではありません」と分けて言います。

### 2.9 配布設定

| 場面 | 決まり |
|---|---|
| 起動したとき | 置いてあれば読む。**その端末にすでにある値は上書きしない** |
| 読み込み直す | 上書きして揃え直す(合言葉が要る) |

### 2.10 仕掛台帳の第1パス / 第2パス

第1パスは決まった名前(SIKAHIKI / SIKAODR)。第2パスは空でよく、ファイル名も変えられます。第1パスに無いファイルは第2パスから読み、
第1パスに無いロット・受注は第2パスから足します(両方にあれば第1パス)。要る列が足りない第2パスからは足しません。コイル実績(外径・検入数)だけは、第1パスの行で空の項目を第2パスの同じロットで埋めます(0.2.30・現場の指摘: 第1パスが読めても検入数が埋まらないことがあった。値のある項目は第1パスのまま)。
どちらのパスも、この PC へ写してから読みます(統合 1.2.28。共有のファイルを開いたままにしない)。
VBA が 2 つの置き場所を交互に試していた(片方が更新中で読めないことがあった)考え方を残したものです(`coil_tool/config.py`)。

### 2.11 ブラウザ版 / デスクトップ版

計算・印刷・DB は同じです。デスクトップ版では、設定の「ポート」が「なし（デスクトップ版）」と出て、
チェックリスト・発注票の印刷用の画面は別の窓で開き、包装仕様書の閲覧システムは既定のブラウザで開きます(`docs/変更履歴.md` 0.2.12)。
