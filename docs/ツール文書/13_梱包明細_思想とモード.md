# 梱包明細 思想とモード

対象の版: 梱包明細 VER 0.13.34(コイル梱包ツール 1.2.56)

梱包明細を「なぜこの作りにしたか」と、「ツールの中にどんな状態・モードがあるか」をまとめます。
根拠は、コードのコメント(`modules/packing_details/` の各ファイルの冒頭)・`modules/packing_details/README.md`・`modules/packing_details/docs/変更履歴.md` です。
何ができるかは [11_梱包明細_仕様.md](11_梱包明細_仕様.md)、使い方は [12_梱包明細_操作説明.md](12_梱包明細_操作説明.md) を見てください。

## 1. 設計の考え方

### 1.1 VBA から移すときに守ったこと

もとは Excel VBA のフォーム(`frmCoilPacking`)です。README は「**業務上の結果・判定・計算・出力内容は同じです。変えたのは実現方法だけ**」と書いています。

- **VBA のボタン・イベントと 1 対 1 にする。** `app/routes/meisai.py` の冒頭に、VBA のイベント(`txtLotNo_Change` `cmdShowJouTai_Click` `cmdKettei_Click` など)と API の対応表があります。`strand_service.py` `history_repo.py` `meisai_service.py` も、VBA の手続き名と関数の対応を冒頭に書いています
- **確かめる順番も VBA のまま。** 条番号表示の 4 つの確認、出力の 8 つの手順、ロット切替の片付け(出力を消す → 副番履歴 → 連番 → 途中経過)を同じ順で行います
- **結果が変わってはいけない所に名前を付ける。** RULE-01〜10(前工程実績数 = 縦割数 × 横割数、余りは丈番号の大きいほうから、条番号は降順、最小の空きスロットへ、など)。条数の配分は「VBA の手順をそのまま書き下した参照実装」と 0〜299 本 × 1〜20 丈の全組合せで突き合わせています(手で期待値を並べると、写し間違いがそのまま正解になるため)
- **VBA が黙って無視する操作は、黙って無視する。** 使用済み・廃棄済みのコイルを押す、空のスロットを押す、などは警告を出さずに状態だけ返します
- **VBA の数もそのまま。** 途中経過は直近 5 ロット(VBA はシートの G〜K 列という物理的な制約から 5 件だった)、丈数 1〜20、積み条数 1〜15、紙は 15 行
- **紙面も同じ。** A4 横の左半分に 1 枚、右半分は空ける(VBA の `FitToPages` は縮めるだけで引き伸ばさないので、等倍のまま左半分に出ていた)

一方で、VBA のままだと現場で困る所は、理由を書いたうえで変えています。

| 変えた所 | 理由 |
|---|---|
| 紙の端から 5mm 内に置く | 余白 0 のままだと、刷ると左と上が欠けた(プリンタは縁から約 4mm を刷れない) |
| 16 行目以降を黙って捨てず、断る | 紙と現物が食い違わないように |
| 重量の小数・0 は断る | VBA の入力欄は数字以外を弾くので小数は入らないが、Web では日本語入力から入りえた。違う数を書くより断る(VER 0.13.16・0.13.19) |
| 右上の文字を設定で変えられる(全ラインで共有) | 現場の要望。変えていなければ VBA と同じ紙面 |
| 紙面の上でサイズ・LOTNO を書き足す | VBA は Excel のセルに打ててから刷れた。紙が HTML になったので代わりを用意した |
| 「はい/いいえ」は 2 往復にする | Web は 1 往復で尋ねられないので、まず確認事項を返し、了解されたら `confirm` 付きで呼び直す。**何を尋ねるかの判断は VBA と同じ** |
| 「出力済み修正」を足し、「No指定」「副番履歴クリア」を外す | VBA には出し直し専用のボタンが無く、「No指定」(重複を確かめずに同じ番号へ上書き)で出し直していた。出したコイルは使用済みでほどけないので、積み直すには「副番履歴クリア」か「条番号表示」で使用済みをほどくしかなく、**ほかの No のコイルまでほどけて二重に積めた**。出し直しを 1 つの操作にまとめ、ほかの No のコイルは積めないようにした(VER 0.13.23・現場の判断) |
| 「全クリア」を足す | やり直すときは途中から直すより初めからのほうがよいことが多い(現場)。出力済み・副番履歴・連番・途中経過をまとめて消す。紙の履歴は消さずに「取り消し」と残す(VER 0.13.23) |
| 積み上げを始めたら丈数・前工程実績数を変えられない | どちらも条番号の配り直しにつながり、積んだ副番・出した紙と食い違う。変えるときは全クリアしてから(VER 0.13.24・0.13.25・現場の求め) |
| 「この操作はいまできるか」を1か所に置き、画面へ渡す | 断る操作の一覧を画面とサーバに別々に書いていて、条番号表示がサーバの一覧から漏れ、前工程実績数のロックに抜け道ができた(構造点検で見つかった)。表をサーバの1か所(`_locks`)に置き、画面は渡された表(`state.locks`)でボタンを止める(VER 0.13.26) |
| 条番号を再表示しても、出力済みのコイルは使用済みのまま | VBA は再表示で使用済みが全部ほどけ、副番履歴クリアと同じく出したコイルを次の No へまた積めた(VER 0.13.23) |

取り込みでは、取り込み元が全列文字(`オーダー板丈` は `'0'` ではなく `'0.0'`)なので、VBA の条件をそのまま当てると 1 件も一致しません。取り込むときに数へ直すことを README は「**この変換が移植の要点です**」と書いています。

### 1.2 業務の判断はサーバ、画面は描くだけ

- `app/static/js/api.js` の冒頭: 「JS が持つのは『呼ぶ』『受け取ったものを描く』だけ。**業務の判断はサーバが行う**(押せるか・何と出すか・断るか)」
- `app/routes/meisai.py`: **画面の状態は毎回まるごと返す。** 差分を返して画面側で組み立て直すと、サーバと画面で状態が二重になり、どちらが正しいかの規則が要って、ずれたときに直す先が分からなくなるため
- 画面が自分で持つのは、送るまでの入力途中の値(重量の欄・廃棄選択の入/切・前工程実績数の修正中)だけです(`meisai.js` の冒頭)
- 断りの文言もサーバが持ちます(`error_body`)。画面はそのまま出します

### 1.3 画面は同時に 1 枚

`meisai/screen.py` の冒頭に理由があります。

- 作業の状態(開いているロット・条番号・積み上げ)は **プロセスに 1 つ** です(`meisai/session.py`)。VBA のフォームが 1 枚しか開かなかったのと同じ持ち方で、1 台の PC を 1 人が使う前提です
- Web ではタブを何枚でも開けるので、2 枚開くと同じ盤面を奪い合い、**先に開いた画面のロットが、触った瞬間に別のロットへ化ける**(実際に確かめた)。現物と紙が食い違う事故になるので、2 枚目は開かせません
- 再読込(F5)と 2 枚目は、サーバからは見分けられません(ブラウザは古いページを畳む前に次の要求を送る)。見分けはブラウザ側(`sessionStorage` と `BroadcastChannel`。`app/static/js/screen.js`)で行い、サーバは名乗りを断ります
- **本当の歯止めは API 側** です。持ち主でない画面からの操作は 409 で断ります(`app/__init__.py`)
- 断るだけだとタブが落ちたときに誰も入れなくなるので、「この画面で使う」で **移せる** ようにしてあります(2 枚にはしない)
- 裏に回った画面は、心拍が止まっても居るものとして扱います。ブラウザが裏のタブのタイマーを間引くため、以前は戻った持ち主が自分の画面から締め出されていました

### 1.4 書き込みは 1 つずつ、押した順に送る

- **サーバ側**(`app/__init__.py` の `_WRITE_LOCK`): 書く要求(GET 以外)は 1 つずつ通します。重なると、連番を 2 枚に同じ番号で付ける・後から書いたほうが黙って勝つ・`database is locked` が起きるためです。1 人で使う道具なので、待たせても誰も困りません。この順番待ちは梱包明細の中だけで、心拍・履歴・マスタ管理(共有を待つことがある)は入れません
- **画面側**(`meisai.js` の `queued`。VER 0.13.21): 作業の操作を **押した順に 1 つずつ** 送ります。重量は欄を離れたときに送るので、入れてすぐ「条番号表示」を押すと 2 つの要求が同時に出て、どちらが先に処理されるかが決まりませんでした。前の返事を待ってから次を送れば、押した順に処理され、押した順に描かれます
- **1 操作 = 1 まとまり。** 出力・ロットの片付けなどは、全部書けるか 1 行も書かないかのどちらかにします。書けなければ 503 と理由を返し、画面は「できた」と思いません(以前は書けていないのに「出力しました」と出ていた。README「書き込みの決まり」)

### 1.5 印刷済みを先に記録する

`app/routes/meisai.py` の `mark_printed` と `meisai.js` の `doPrint` のコメントにあります。

- ブラウザの印刷は、押されたかどうかを確実には拾えません
- 帳票を開いただけで印刷済みとみなすのでもなく、画面の「印刷」ボタンが **先に** `/api/printed` を叩いてから帳票を開きます(VBA の `cmdPrint_Click` の `SetPrinted True` にあたる)
- この記録が、別のロットへ切り替えるときの「まだ印刷されていません」の確認に使われます

### 1.6 途中経過は都度 DB へ

`meisai/session.py` と `meisai/history_repo.py` の冒頭: タブを閉じるとプロセスが終わる(自動終了)ので、メモリに置いた状態は消えます。VBA が `SaveCurrentSnapshot` を呼んでいた 3 つの時点(条番号表示・廃棄の増減・出力)で必ず DB へ書き、開き直したらそこから組み立て直します。メモリは「いま触っているものを速く返すための置き場」で、記録ではありません。

### 1.7 手元に先に書いて、共有へ送る

`meisai/slip_history.py` の冒頭: 複数の PC が同じ SQLite に同時に書くと、ネットワーク越しではロックが正しく効かず壊れることがあります。手元に先に書けばネットワークが切れても失いません。送るときは鍵を置いて 1 台ずつ、送信ID で二重にしません。同じ理由で、手元の DB そのものは共有フォルダに置かせません(`meisai/config.py`)。

### 1.8 そのほかの考え方

| 考え方 | 根拠 |
|---|---|
| マスタ管理は **見るだけ**。直すところは移さない | 誰が直せるかの決まりが梱包資材総合ツールにあり、ここから書けるとその決まりを通らずにマスタが変わる(README) |
| 管理者パスワードで守るものを増やさない | 守る対象を増やすほど、現場はパスワードを紙に貼る(`app/routes/settings.py`)。置き場所の間違いはその PC の取り込みが「見つからない」と言うだけで紙には出ないので守らない |
| 取り込んでも、開いているロットを黙って読み直さない | 読み直すと「修正する」で手入力した前工程実績数が消える。どちらを選ぶかは使う人にしか決められないので、事実だけ伝える(`run_import`) |
| CSV はダウンロードせず、こちらから開かない | 現場の指定。書き出して場所を出すだけ |
| 黙って待たせない・開いてすぐ出す | 現場の指摘「押しても反応が鈍い」。窓は先に開き、共有の様子は後から埋め、経過秒を出す(`app/static/js/ui.js`) |
| 操作のあとは読み直さずに状態を出す | 現場の指摘(VER 0.13.18) |
| 追加ライブラリを入れない | ラインの PC に入れられないため。取り込み元の読み書きは標準ライブラリの `sqlite3` だけ、画面もビルド工程なし(README) |
| 起動時の失敗でサーバを落とさない | 落とすとブラウザには「接続できません」としか出ず理由が伝わらない(`modules/packing_details/__init__.py`) |

## 2. モードと状態

### 2.1 アプリのモードは 1 つだけ

`meisai/modes.py` の冒頭に「**モードは1つしかありません**」とあります。移植元の起動の仕組みが「どのモードを起動・停止するか」をモード名で受け渡すので、名前を 1 つ(`meisai`)だけ置いています。現場用・資材用のような切り替えはありません。増やしたくなったら、それは別のアプリである可能性を先に疑う、と書かれています。

以下は、モードではなく **画面や作業の状態** です。

### 2.2 廃棄選択モード(画面だけが持つ)

| 状態 | ボタンの文字 | コイルを押すと |
|---|---|---|
| 切(ふつう) | 廃棄選択 | 積み上げへ(`/api/stack`)。使用済みのコイルは押せない |
| 入 | 廃棄選択中 | 廃棄の付け外し(`/api/discard`)。使用済みのコイルは何も起きない |

- VBA の `mHaikiMode` にあたります。画面の変数だけで持ち、サーバには送りません。再読込すると「切」に戻ります
- 廃棄の付け外しそのものは、そのつど途中経過に保存されます

### 2.3 コイルの 3 つの状態

`strand_service.Board.state_of` が決め、画面は色で描きます。

| 状態 | 意味 |
|---|---|
| 未使用(available) | 積める |
| 使用済み(used) | 積み上げに入っている、または出力・復元で使用済みになった。押しても反応しない |
| 廃棄(discarded) | × の印。積めない。廃棄選択中なら解除できる |

出力したコイルは、積み上げからは外れますが使用済みのまま残ります(同じコイルを次の梱包へ二重に積ませない)。**条番号を再表示しても、出力済みのコイルは使用済みのまま**です(VER 0.13.23。ほどけるのは出力していない使用済みだけ)。出したコイルが空くのは、出力済み修正でその紙から外したとき・全クリア・ロット切替のときだけです。

### 2.4 前工程実績数の修正中

「修正する」を押すと欄が打てるようになり、ボタンが「確定する」に変わります(VBA のギミックA)。「確定する」でサーバへ送り、半角の数字でなければ断ります。修正中かどうかは画面だけが持ちます。

### 2.5 出力済みの修正中(VER 0.13.23)

`Board.edit_no` が 0 でなければ修正中です(サーバが持ち、画面の状態 `edit` に出る)。No指定(VBA の `chkSpecifyNo`)は外しました。

| 状態 | 見え方・できること |
|---|---|
| ふつう | 「出力」は連番を 1 進めた No で出す。「出力済み修正」は出力済みのチェックが 1 つのときだけ押せる |
| 修正中 | 積み上げの上に「No…を修正中」と修正前の並び・「修正をやめる」。その No のコイルが積み上げに戻り、**ほかの No のコイルは使用済みのまま**。「出力」は「修正して出力」になり、同じ No で出し直す。条番号表示・丈数の変更はできない(サーバも断る) |

- 修正中でも、紙(明細出力)はまだ前のままです。途中経過には修正前のコイルも使用済みとして書くので、修正中にタブが落ちて開き直しても、前の紙のコイルが空いて見えることはありません(開き直すと修正はやめた扱い)
- 重量は、その No を出したときの値で出し直します。修正を終えるかやめると、入る前の値に戻ります
- 統合画面の「終了」などの前に聞く「送っていない入力」に、修正中であることを出します

### 2.6 出力の前と後(確定前/確定後)

| 状態 | 見え方 |
|---|---|
| 積み上げ途中 | 枠が全部埋まるまで「出力」は押せない(`is_complete`) |
| 確認待ち | 出力・ロット切替・条番号表示で確認の窓が出ている。了解前はサーバは何も書いていない |
| 出力後・未印刷 | 印刷済が 0。別のロットへ移ろうとすると確認が出る |
| 印刷済 | 「印刷」を押した後。ロット切替・全クリアでも 1 に戻る(出力・出力済み修正で 0 になる) |

### 2.7 復元直後

同じロットの途中経過を戻した直後(VBA の `mRestoredSnapshot`)。この間に「条番号表示」を押すと、出力していない使用済みが消える確認が出ます(出力済みのコイルは使用済みのまま)。条番号表示か丈数の変更で、この状態は終わります。積み上げのスロットは戻さないので、積み条数は入れ直します。

### 2.8 取り込み前・取り込み中

| 状態 | 見え方 |
|---|---|
| まだ取り込んでいない | 「仕掛台帳がまだ取り込まれていません。左の「取り込み」を押してください。」の帯 |
| 取り込み中 | 進み具合の窓(いま読んでいる台帳・n/m・経過秒)。Esc で閉じない。取り込みは 1 本ずつ |
| 取り込み後に開いていたロット | 取り込み前の内容のまま。そう知らせる |
| 起動時 | 自動取り込みが「する」なら、前回から変わったファイルだけ読む。終わるまで(待つのは上限まで)起動待機画面に「梱包明細: 取り込み中」と出る |
| 第2パス(仕掛4ファイル) | 設定していれば、第1パスで見つからない分を第2パスから読む(LS4LOT も。統合 1.2.28)。設定していなければ使わない。どのパスのファイルも、この PC へ写してから読む |

### 2.9 画面の持ち主と 2 枚目

| 状態 | 見え方 | 抜け方 |
|---|---|---|
| 持ち主 | ふつうの画面 | ─ |
| 裏に回った持ち主 | ふつうの画面(心拍が止まっても空きにしない) | 前に戻ると心拍を送り直す |
| 2 枚目 | 「この画面はすでに開いています」の覆い。前の画面からの応答の秒数を数え直して出す | 前の画面を使う/「この画面で使う」/前が閉じたら「もう一度ためす」 |
| 引き継がれた | 「この画面は引き継がれました」の覆い。下の画面は押せない(消さずに止める) | 「この画面で使う」 |
| アプリが開き直された | 「アプリが開き直されています」の覆い(トークンが通らない古い画面) | 「読み込み直す」 |
| 接続が切れた | 赤い帯「バックエンドと通信できません」(2 回続けて失敗したとき) | 開き直す |

心拍が 50 秒途切れた持ち主は、居ないものとして扱います(1 回の取りこぼしでは奪わない。`screen.GRACE_SEC`)。

### 2.10 この PC に保存するものと共有するもの

| 状態 | ふるまい |
|---|---|
| 共有に届く | 右上の文字はマスタの表(なければ控えの JSON)から。履歴は全ラインから探す |
| 共有に届かない | 右上の文字はこの PC が最後に読んだ値で刷り、紙面の画面にそう出す。**変えるのは断る**(この PC だけ違う文字になるのを防ぐ)。履歴の「探す」「作り直す」はこの PC の分だけ。CSV の書き出しは断る |
| 送り残しがある | 履歴の窓・マスタ管理に枚数を出す。5 分ごと、または「いま送る」で送る |
| 置き場所の設定 | どのフォルダを見るかはこの PC の設定。中身は全ラインで共有 |
| 配布設定 | 起動時に、その PC にまだ無い項目だけ読む/「読み込み直す」は上書き |

### 2.11 帳票の 2 つの開き方

| 紙面 | できること |
|---|---|
| 出力済みから開いた紙面 | サイズ・LOTNO を書き足せる。右上の文字はいまの文字(開いたままでも、前に戻ったときに聞き直す) |
| 履歴から作り直した紙面 | 読むだけ。書き足せない。右上の文字は、そのとき刷った記録の文字 |

### 2.12 起動の待機

準備が終わるまでは `/details/` で起動待機画面を出し、終わったら `/details/meisai` へ送ります(`app/routes/health.py`)。起動の途中の段階(準備中・取り込み中)はその画面に出ます。
