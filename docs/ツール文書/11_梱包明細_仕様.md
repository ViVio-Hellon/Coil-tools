# 梱包明細 仕様

対象の版: 梱包明細 VER 0.13.40(コイル梱包ツール 1.2.63)

この文書は、機能「梱包明細(コイル梱包明細打ち出しシステム)」が何をするか・どこのデータを使うか・どんな決まりで判定するかをまとめたものです。
コードは `modules/packing_details/` にあります。現場向けの使い方は [12_梱包明細_操作説明.md](12_梱包明細_操作説明.md)、作りの考え方は [13_梱包明細_思想とモード.md](13_梱包明細_思想とモード.md) を見てください。

## 1. 目的と範囲

アルミコイルを梱包するときに貼る **梱包明細表** を作ります。もとは Excel VBA のフォーム(`frmCoilPacking`)で、それを Python + Flask の Web 画面へ移したものです(移植元 VER 0.13.1。`modules/packing_details/__init__.py` の `PORTED_FROM`)。

- 1 本の母材ロットは、丈(じょう。たて方向の切り分け)と条(じょう。よこ方向の切り分け)に割られ、1 ロットから `縦割数 × 横割数` 本のコイルができます
- 各コイルは `丈番号-条番号`(例 `2-15`)で呼びます。ロット番号を前に付けたものが **副番**(例 `L5160Z0-2-15`)です
- 作業する人は、現物を積む順にコイルを押します。**その並びをそのまま紙に出します**

範囲に入るもの: ロットを引く・重量を入れる・条番号を並べる・積む・出力・帳票(書き足し・印刷)・明細の履歴(全ライン・3 年)・取り込み・マスタ管理(見るだけ)・設定・説明書。
範囲に入らないもの: 梱包資材マスタを直すこと(梱包資材総合ツールの役目)、仕掛台帳を書き換えること(読むだけ)。

### 統合ツールでの載り方

コイル梱包ツールの **梱包明細** タブとして動きます。入口は `/details` で、その下に移植元の経路がそのまま並びます(`docs/統合設計.md`)。

| 経路 | 中身 |
|---|---|
| `/details/` | 準備中は起動待機画面、準備ができたら `/details/meisai` へ送る(`app/routes/health.py`) |
| `/details/meisai` | 梱包明細の画面(統合画面の iframe で開く) |
| `/details/api/…` | 画面から呼ぶ API |
| `/details/report/…` | 帳票(別のタブで開く) |
| `/details/docs` `/details/docs/変更履歴` | 文字だけの詳しい説明書・変更履歴 |

左に「引く → 決める」、右に「積む → 出す」を並べます。

| 欄 | 中身 |
|---|---|

| 丈数と重量 | 丈数(−/＋)・「条番号表示」「反転」「廃棄選択」・丈ごとの重量(±1・±10) |

| 積み上げ | 積み条数(−/＋・最大 15)・スロット(下がスロット 1)・「出力」(修正中は「修正して出力」)「印刷」・現在の連番・「全クリア」。修正中は上に「No…を修正中」の帯と「修正をやめる」 |
| 出力済み | このロットで出した明細の一覧(`ロット番号-NoN`)。チェックでまとめて刷る。「出力済み修正」(チェック 1 つのときだけ押せる) |

このほか、2 枚目を開いたときの覆い・引き継がれたときの覆い・アプリが開き直されたときの覆い・確認の窓・バージョン情報の窓があります。

## 3. 入力と出力(データの置き場所と役割)

### 3.1 取り込み元(読むだけ)

共有フォルダの sqlite3 ファイルを、**手元の DB へ取り込んでから**使います。画面と業務の処理は手元の表しか見ません(`meisai/data_sync.py`)。

| 取り込み元 | 既定の置き場所 | 手元の表 | 使いみち |
|---|---|---|---|
| `SIKALOT.sqlite3` | `\\nlmsrvngy03\Read\【New】仕掛\台帳`(第1パス: 仕掛台帳のフォルダ) | 仕掛ロット | ロットの情報 |
| `SIKAHIKI.sqlite3` | 同上 | 仕掛引当 | 受注番号 |
| `SIKAODR.sqlite3` | 同上 | 仕掛受注 | 包装仕様NO・取引先・納入先 |
| `LS4LOT.sqlite3`(名前は変えられる) | `\\nlmfangyshrd\各課共有\0130_日軽稲沢\梱包課\梱包課共有\仕掛`(第1パス: 梱包課共有の仕掛フォルダ) | 仕掛当工程 | **縦割数・横割数** |

- 拡張子違い(`.db`)も拾います
- **第1パス**: 仕掛台帳のフォルダ(SIKALOT・SIKAHIKI・SIKAODR。名前は固定)と、梱包課共有の仕掛フォルダ(LS4LOT。**名前も変えられる**。`konpo_db_file`、空なら `LS4LOT.sqlite3`。統合 1.2.28)の 2 つ
- **第2パス**: 第1パスで見つからないときに見る、**4 ファイル共通の 1 つのフォルダ**(統合 1.2.28 から LS4LOT も)。4 つともファイル名を変えられます(空なら第1パスと同じ名前)。第1パスに無いファイルは第2パスから読み、第1パスに無いロット・受注は第2パスから足します(両方にあれば第1パス)。第1パスと同じファイル(同じフォルダ・同じ名前)は 2 度読みません。既定は無し
- **LS4LOT は名前で形式が変わります**(統合 1.2.29・現場の指示。`common/ls4_source.py`)。名前が LS4LOT なら いままでの形式(`当工程設計_縦割数` / `_横割数`)。それ以外の名前(例: 実績_LS4.sqlite3)なら実績の形式で、`BOX設計_縦割数` / `_横割数` を当工程設計の割数として使い、`BOX実績_作業開始_日付` が**いまの年月の行だけ**を取り込みます(同じロットは作業開始がいちばん新しい行。今月の行が無ければ空)。LS4LOT の作られる時刻が作業と合わないときの受け皿です。仕様と列の関係は [`docs/仕掛ファイルの仕様.md`](../仕掛ファイルの仕様.md)
- **どの置き場所のファイルも、この PC(一時フォルダ)へ写してから読みます**(統合 1.2.28・現場の指示。`common/source_copy.py`)。共有の上のファイルは直接開きません。本体と `-wal` / `-journal` を一緒に写し、写している間に書き換わったら写し直します。中身が前と同じなら写し直しません
- 縦割数・横割数は `LS4LOT` からだけ採ります。仕掛ロットの `BOX設計_縦割数/横割数` は実データで 532 件中 340 件が食い違うため使いません(`meisai/config.py` のコメント)
- 取り込み元は全列が文字なので、取り込むときに数へ直します(`meisai/import_specs.py`)。板厚・板幅は VBA の `Val` と同じ読み方、縦割数・横割数は整数でなければ 0 にします(VER 0.13.19)

## 4. 業務の決まり(コードの判定の要約)

VBA と結果が変わってはいけない決まりです(`modules/packing_details/README.md` の RULE-01〜10)。

### 4.1 ロットを開く(`/api/lot` → `session.open_lot`)

- ロット番号は 7 桁。英数字だけ・大文字に直して送ります(画面)。7 桁でなければ断ります
- 仕掛ロットから `ロット番号 = ? AND オーダー板丈 = 0` の **先頭 1 行** を引きます(RULE-10)。無ければ「該当するﾛｯﾄ情報が見つかりません。」(404)
- **前工程実績数 = 縦割数 × 横割数**(RULE-01)。LS4LOT に無いロットは 0 になります
- 丈数には縦割数が入ります(1〜20 のとき。RULE-02)。21 以上なら入れずに「丈数は手で入力してください」、0 なら「「修正する」で入力してください」と出します
- 受注番号は仕掛引当から初出順に重複なく並べ、包装仕様NO は仕掛受注から引きます。無ければ「(未登録)」
- **前のロットと違うロットを開くとき**:
  - 直近の出力が印刷されていなければ、確認を返します(`confirm: "unprinted"`)
  - 了解されたら前のロットを片付けます(1 まとまりで): 出力を消す → 副番履歴を全部消す → 連番を 0 に戻す → 前のロットの途中経過を消す(`session.close_lot`)
- そのロットの途中経過があれば戻します(§4.6)

### 4.2 重量(`/api/weights` → `meisai_service.read_weights`)

- 丈ごとに 1 つ。全角の数字は半角に直して読みます
- 数字だけの整数のみ受けます。`250.0` のように小数点以下が 0 だけなら通します。`2502.7` や `2.5e3` は断ります(**黙って切り捨てない**。VER 0.13.16)
- 空は「丈Nの重量が未入力です。」、0 は「丈Nの重量が0です。」で断ります(紙に `0.0Kg` と出さないため)
- 重量は **丈単位**。同じ丈のコイルはみな同じ重量です(RULE-06)
- **「出力」「条番号表示」を押したときも、画面の重量欄を読み直します**(0.13.29。VBA `cmdKettei_Click` の `ReadWeights` と同じ)。画面は押したときの欄の値を `weights` として添えて送り、空・読めない値なら同じ理由文で止めます(紙は出さない)。以前は欄を離れたときに送った値だけを使い、欄を空にしても前の重量のまま紙に出ていました
- 画面は欄を離れたとき(全部の丈が入っていれば)送ります。返事で欄を描き直すときは、丈の数が同じなら欄を作り直さず値だけ合わせ、**打っている最中の欄には触りません**(VER 0.13.26。作り直すと、丈1の返事が丈2に打った数字を消していた。資材計算の入力欄と同じ決まり)

### 4.3 条番号(`/api/strands` → `strand_service`)

VBA と同じ順で確かめます。

1. 途中経過を戻した直後なら、上書きしてよいか尋ねる(`confirm: "overwrite_restored"`。使用済みが消え、廃棄は残る)
2. 丈数が入っているか
3. 前工程実績数が 0 より大きいか
4. 重量がすべて入っているか

通ったら配ります。

- **条数の配分**: `前工程実績数 ÷ 丈数` の商を各丈へ、**余りは丈番号の大きいほうから** 1 本ずつ(RULE-03)。例 31 本 / 2 丈 → `[15, 16]`、5 本 / 3 丈 → `[1, 2, 2]`
- **条番号の並び**: 丈ごとに降順。左端がその丈でいちばん大きい番号(RULE-04)
- 配り直すとスロットは空になり、**出力していない使用済みは消えます**。**出力済みのコイルは使用済みのまま**です(VER 0.13.23。以前はすべて消え、出したコイルを次の No へまた積めた)。廃棄は、まだある条番号のぶんだけ残ります
- 出力済みの修正中は断ります(409 `editing`)
- 丈数を変えると、重量・条番号・積み上げ・廃棄をすべて作り直します(`/api/jou-su`。出力済みの修正中は断る)
- **積み上げを始めたロットは丈数を変えられません**(VER 0.13.24)。出力済みがある・積み上げにコイルがある・使用済みのコイルがある(途中経過から戻したものを含む)ときは 409 `jou_su_locked`。画面の状態 `jou_su_locked` で欄と −/＋ を止めて案内を出す。変えるときは全クリア
- **前工程実績数も同じ**(VER 0.13.25): 積み上げを始めたら `/api/zen-kotei` は 409 `zen_kotei_locked`、出力済みの修正中は 409 `editing`。画面は `zen_kotei_locked` で「修正する」を止めて案内を出す
- 積む前に前工程実績数を変えて配分が変わるなら、丈数と同じく条番号を消します(条番号表示し直す。VER 0.13.26。古い条番号のまま無いコイルを積ませない)
- 積み上げを始めたら、**条番号表示は断ります**(409 `strands_locked`。VER 0.13.26 は配分が変わるときだけ、VER 0.13.35 からはいつも。現場の指摘「+- が押せないだけで条番号表示が押せてしまう」)。画面のボタンも止めます
- **重量も同じ**(VER 0.13.35): 積み上げを始めたら重量の欄・±ボタンを止め、サーバも、いまと違う重量が来たら 409 `weights_locked` で断ります(同じ値なら通す)。重量の保存・条番号表示・出力のどれでも見ます(`_take_screen_weights`)。出力済みの修正中も同じ(変えるときは全クリア)
- **断る操作の表は1か所**(`app/routes/meisai.py` の `_locks`)。修正中に断るもの(ロットの開き直し・ロットを閉じる・前工程実績数・丈数・条番号表示・もう1枚の修正)と、積み上げを始めたら断るもの(前工程実績数・丈数・条番号表示・重量。VER 0.13.35)を持ち、各ルートは `_guard` で断ります。画面には同じ表を `state.locks`(操作 → code・message)で渡し、画面はそれでボタンを止めます(VER 0.13.26)
- **反転**(`/api/reverse`)は表示の左右を入れ替えるだけで、番号も状態も変わりません

### 4.4 積み上げ(`/api/stack-max` `/api/stack` `/api/unstack`)

- 積み条数は 1〜15(RULE-09)。**積み始めてからでも変えられ、積んだコイルは残ります**(VER 0.13.33・現場の求め。VBA は変えると全部外れて積み直しだった)。増やすと上に空きのスロットを足し、減らすと上の空きを取ります。取るスロットにコイルが入っていれば断ります(409 `stack_shrink`。どのスロットのどのコイルかを出す。何も変えない)
- コイルを押すと **いちばん若い空きスロット** に入ります(RULE-05)。スロット 1 が最下段 = 最初に積むもの
- スロットを押すとそのスロットだけ空きます。**詰め直しません**(次に積むとそこへ入る)
- 使用済み・廃棄済みのコイルを押しても、VBA と同じく黙って何もしません(返事は `ignored`)
- **全部のスロットが埋まるまで「出力」は押せません**(`Board.is_complete`)

### 4.5 廃棄(`/api/discard`)

- 「廃棄選択」を押している間、コイルを押すと廃棄の付け外しになります
- 廃棄済み → 解除、未使用 → 廃棄、使用済み → 何もしない(使用済みは廃棄にできない)
- 廃棄したコイルは積めません

### 4.6 途中経過(スナップショット)

- **保存する時点は 3 つだけ**: 条番号表示・廃棄の付け外し・出力(VBA の `SaveCurrentSnapshot` と同じ。`session.save`)
- 中身: 前工程実績数・丈数・重量・条数・使用済み・廃棄。直近 5 ロットだけ残します
- 出力済みの修正中に書くときは、修正しているNoの修正前のコイルも使用済みに数え、重量は修正に入る前の値を書きます(紙はまだ前のままなので。`Board.committed_used`)
- 開き直したとき、紙に載っているコイル(明細出力)は、途中経過が古くても使用済みに戻します。使用済みと廃棄の両方に入っていたコイルは廃棄から外します(VER 0.13.26)
- 戻すとき(`session._restore`): 条数の数と丈数が合わない・丈数が 1〜20 でないときは戻しません。前工程実績数は保存した値で上書きします(台帳が変わっても作業中の数を勝手に変えない)
- 積み上げのスロットは戻しません(積み条数は入れ直す)。使用済みだったコイルは「使用済み」のまま押せません
- 開いたら「前回の条番号情報を復元しました。(丈数:N 合計:N条)」と出します

### 4.7 出力(`/api/output` → `meisai_service.output`)

1. 積み上げが埋まっていなければ断る(「積み上げが埋まっていません。」)
2. 1 枚に載るのは 15 行まで(RULE-09。積み条数の上限も 15 なので、ふつうは起きない)
3. 積んだ副番のうち出力済みのものを集めて確認を返す(`duplicate`)
4. 確認があって了解前なら、**何も書かずに** 確認だけ返す
5. 書くときは 1 まとまりで(全部書けるか、1 行も書かないか):
   - No: 連番を 1 進めた値
   - 明細の履歴(手元)に書く → 明細出力に 1 行足す
   - 副番を副番履歴に足す(すでにあるものは足さない)
   - 印刷済を 0(未印刷)にする
6. 書けたら**積み上げだけ空にし**、途中経過を保存します(保存に失敗しても、紙は書けているので失敗とは返さず、知らせを添える。VER 0.13.26)。出したコイルは「使用済み」のまま残ります(同じコイルを次の梱包へ二重に積ませないため)。履歴を共有へ送る処理を起こします
7. 「出力しました。No…を確認してください。」と出します

**No指定は外しました(VER 0.13.23)。** VBA にあった「No指定」(番号を手で決める。重複を確かめずに上書き・連番を引き上げる)は、出力済みの出し直しに使われていました。出し直しは §4.8 の出力済み修正で行います。古い画面が `specify_no` を送ってきても読みません(次の連番で出す)。

### 4.8 出力済みの修正(`/api/edit-output` → `/api/output` / `/api/edit-cancel`)

出力済みの 1 枚を、**同じ No のまま** 積み直して出し直します(`meisai_service.begin_edit` / `output_edit`)。画面では「出力済み」で 1 つだけチェックを入れて「出力済み修正」を押します(2 つ以上・積み上げ中のコイルがある・条番号を表示していないときは押せない)。

1. 修正に入る(`/api/edit-output {no}`):
   - その No が無ければ断る(`no_output`)・条番号を表示していなければ断る・積み上げ中のコイルがあれば断る(`stacking`)・すでに修正中なら断る(409 `editing`)・その No のコイルがいまの条番号に無ければ断る(`unknown_output`)
   - その No のコイルを使用済みから外して積み上げに戻す(積み条数 = その No の本数)
   - **ほかの No のコイルは使用済みのまま**(積めない。No1〜No3 があって No1 を直すとき、No2・No3 のコイルは使えない)
   - 重量はその No を出したときの値にする(修正を終えると、入る前の値に戻す)
2. 修正中は「出力」が「修正して出力」になります。ロットの開き直し(画面で了解すれば修正をやめて開く)・ロットを閉じる・前工程実績数・丈数・条番号表示・もう1枚の修正は断ります(409 `editing`)。積み条数・紙に載っていないコイルの廃棄は変えられます(重量は VER 0.13.35 から変えられません。積み上げを始めているため)。紙に載っている(修正中の No の)コイルは廃棄にできません。修正を終えるかやめると、積み条数と重量は入る前の値に戻ります(重量を打ち直していたときは、戻したことを知らせる。VER 0.13.26)
3. 「修正して出力」(`/api/output`。修正中ならこちらの処理になる):
   - 埋まっていなければ断る・15 行を超えれば断る・**ほかの No のコイルが入っていれば断る**(`used_elsewhere`。積むときにも断っているので、念のための最後の砦)
   - **いつも確かめる**(`edit`)。前・後の並び、外すコイル・加えるコイルを出す
   - 書くときは 1 まとまりで: 前の紙の履歴に「作り直し」の印(消さない)→ 新しい紙の履歴を書く(書き足したサイズ・LOTNO を引き継ぐ)→ 明細出力の行を作り直す(行の番号が変わる)→ 副番履歴から外れたコイルを外し(ほかの No に無ければ)、加わったコイルを足す → 印刷済を 0 に
   - **連番は進めません**
   - 書けたら修正を終え(積み上げを空に、外したコイルは空き・加えたコイルは使用済み)、途中経過を保存します。「No…を修正しました。刷り直してください(印刷)。」
4. やめる(`/api/edit-cancel`): 積み上げを空にし、その No のコイルを使用済みに戻す。紙は前のまま

### 4.9 印刷済みの記録(`/api/printed`)

- 画面の「印刷」は、**先に** 印刷済を 1 にしてから帳票を開きます。ブラウザの印刷は押されたかどうかを確実に拾えないためです
- 印刷済が 0 のまま別のロットへ切り替えようとすると、§4.1 の確認が出ます

### 4.10 全クリア(`/api/clear-all`)

開いているロットを初めからやり直します。`confirm` が無ければ、何枚消えるかを書いた確認(`clear_all`)を返すだけです。

- 消すもの(ロット切替の片付け `session.close_lot` と同じ 4 つ): そのロットの出力済み・副番履歴・連番(次は No1)・途中経過(条番号・廃棄)。印刷済は 1 に戻ります
- **明細の履歴は消しません。** そのロットの紙に「取り消し」の印を付けます(刷って現場へ出た紙を追えるように)。CSV の集計では枚数に数えず、「取り消した枚数」に出します
- 印を付けるのは **その時点で出力済みの一覧にある紙だけ** です。それより前に出力済み修正で作り直された紙は「作り直し」のまま、前の全クリアで取り消した紙・ロット切替で片付いた紙には触りません(VER 0.13.24 で試験に固めた)
- 消したあと、台帳から開き直します(丈数・前工程実績数は台帳の値に戻り、条番号表示からやり直す)。修正中でも全クリアできます

**副番履歴クリアは外しました(VER 0.13.23)。** 副番履歴だけ消すと、No1〜No3 で使ったコイルを No4 へまた積めてしまい、ミスがミスを呼ぶためです(現場の判断)。


## 5. 帳票

組み立ては `meisai/report.py`、印刷用 HTML の仕組みは `meisai/printing.py` です。

### 5.1 紙面

- **A4 横の左半分に 1 枚、右半分は空白**。明細 1 枚につき用紙 1 枚。A4 1 枚に 2 枚並べることはしません(右半分は現場で切り取る)
- 文字・罫線は紙の端から 5mm 内に置きます(切り目の側も)。プリンタは縁から約 4mm を刷れないため。VBA より幅で約 7%・高さで約 5% 小さくなります
- 行・列の寸法は VBA の実ブック(A1:F20)の比率のまま、百分率で持ちます

| 位置 | 中身 |
|---|---|
| 1 行目 左 | `<ロット番号>-No<N>  梱包明細表` |
| 1 行目 右 | 右上の文字(既定 `NLM.NAGOYA.QA`、赤)。長いときは字を小さくして欄に収める(5pt まで) |
| 2〜4 行目 | 左に「種類質別 / 寸法 / 検番」。B〜C 列に書き足し欄、D 列に「小ラベル添付」(橙)。D〜F 列は現物のラベルを貼る場所 |
| 5 行目 | 「コイル副番」「重量(Kg)」 |
| 6〜20 行目 | 積んだ順の副番と重量(15 行。スロット 1 が一番上) |

### 5.2 開き方

| 経路 | 中身 |
|---|---|
| `/report/<ロット>/<No>` | 1 枚 |
| `/report/<ロット>?nos=1,2,3` | まとめて。**No の順に並べ直す**(押した順ではない)。1 枚ずつ別の用紙 |
| `/report/history?ids=…` | 履歴から作り直す(§5.4) |

- 帳票は別のタブで開きます(デスクトップ版では別の窓。変更履歴 VER 0.13.12 の記載による。デスクトップ版の側のコードは(未確認))。トークンは要りますが、画面の持ち主でなくても開けます
- 開くたびに、明細の履歴へ「開いた回数・そのとき刷る右上の文字」を記録します
- 紙面の上の案内とボタン(「印刷する」)は画面のときだけで、紙には出ません
- 開いたままの紙面は、前に戻ったときに右上の文字を聞き直します(`/report/qa-mark`)。同じ PC で変えたときは画面から知らせて差し替えます

### 5.3 書き足せる欄(サイズ・LOTNO)

- 紙面の「寸法」「検番」の行に点線の欄があり、**サイズ** と **LOTNO** を書けます
- 欄を離れたとき・Enter で `/report/<ロット>/edits` へ送り、「保存しました」と出ます
- 1 欄 20 文字まで(超えると理由を出して受けない)
- 1 枚ぶんは丸ごと入れ替えます。まとめて開いた紙面で 1 枚でも書けなければ、1 枚も書きません
- 出力済み修正で作り直された明細(行の番号が変わったもの)への書き足しは断ります(409「この明細は作り直されたか、もうありません。紙面を開き直してください。」)
- 書き足しは明細と一緒に残り、刷り直しても出ます。ロットを切り替えると明細ごと消えます(明細の履歴には残ります)
- 空なら何も印字しません

### 5.4 履歴から作り直す紙面

- 明細の履歴に残した中身のとおりに組みます(積んだ順・重量・書き足し・そのとき刷った右上の文字)
- 右上の文字の記録が無い紙(一度も開いていない)は、いまの文字で刷り、そう出します
- 作り直された紙は「このあと作り直されています(新しい紙があります)」、全クリアで取り消された紙は「このあと全クリアで取り消されています(この紙は使いません)」と出します
- **読むだけ** です。書き足しはできず、履歴も書き換えません
- 一度に 20 枚まで。見つからない紙が 1 枚でもあれば作りません

### 5.5 古い紙・古い台帳で刷らない(0.13.32)

- 紙面は作ったときの身元(明細出力の管理番号・履歴ID)を持ちます。タブに戻ったときと刷る直前(「印刷する」・Ctrl+P)に、まだ有効か(出力済み修正で作り直された・全クリアで取り消されていないか)を確かめ、無効なら紙面を隠して「この紙は作り直されました(取り消されました)。開き直してください」と出します(紙にも断りだけが出る)。履歴から作り直した過去の紙面は止めません。
- 動いている間に取り込み元の台帳が変わったら(大きさ・更新時刻を見るだけ)、上の帯に「新しい台帳があります [取り込む]」を出します。起動時の自動取り込みは、本体・`-wal`・`-journal` の大きさ・更新時刻(ns)の目印が前と**一致するか**で決めます(読む前に取る)。
- ロットを入れ直したとき、途中経過の丈数・前工程実績数が台帳と違えば知らせます(途中経過を優先するのは VBA どおり)。

- 中身はこの文書には書きません

### 6.4 配布設定

- 配った先では、起動時(取り込みより先)に **その PC にまだ無い項目だけ** 読みます。空の値は「無い」と同じに扱います

## 7. 明細の履歴(全ライン・3 年)

`meisai/slip_history.py`。明細出力はロットを切り替えると消えるので、あとから追う・数えるために消えない履歴にも書きます。

- 出力と **同じまとまり** で手元に先に書き、裏で共有の `梱包明細履歴.sqlite3` へ送ります。**共有へ直接は書きません**
- 送るのは、出力・書き足し・紙面を開いたときはすぐ、届かなければ 5 分ごと。1 回に 500 枚まで
- 1 枚ごとに一意の `送信ID`。送り直しても二重になりません。あとから変わる値(書き足し・開いた回数・作り直し・取り消し)は送り直すと共有も書き換わります
- 状態: `有効` / `作り直し`(出力済み修正で出し直された前の紙) / `取り消し`(全クリア。VER 0.13.23)。作り直し・取り消しの日時は「作り直し日時」の列に入れます(表の形は変えない)
- 3 年より前は共有も手元も 1 日 1 回整理します(`VACUUM` はしない)
- **共有の整理は、この PC の時計を確かめてから**(VER 0.13.40・現場の指示)。整理する日は出力日時で決めるので、時計が大きく進んだ PC が
  1 台あると全ラインの履歴を消してしまう。共有フォルダに小さなファイルを作って付いた日時(ファイルサーバーの時計)と比べ、1 日より大きく
  ずれていれば(確かめられないときも)見送る。消す枚数が全体の 1 割かつ 50 枚を超えるときも見送る。見送ったわけはログと履歴の画面に出し、
  整理した日は残さない(次の日にまた確かめる)。手元は送り終えた行だけ整理する(送れていない行は消さない)
- 探す: 出力日の範囲・ロット番号(前方一致)・副番。新しい順に 200 枚まで並べ、超えたぶんは数で言います。共有に届かなければこの PC の分から探し、そう出します
- CSV: 明細(1 行 = コイル 1 本)と集計(出力日 × PC。作り直し・取り消しの紙は数えず、「作り直した枚数」「取り消した枚数」に出す)の 2 つを CSV の出力先に書きます。UTF-8(BOM 付き)・CRLF。副番 `1-10` のように Excel が読み替える値は `="1-10"` で書きます。書き出す前にこの PC の送り残しを送ります
- **ブラウザのダウンロードはせず、Excel やフォルダをこちらから開くこともしません**(現場の指定)
- 「いま送る」は 15 秒まで待ち、その先は裏で続けます
- 共有のファイル・表が無ければ作ります。手で作った表で列が足りなければ足し、足せない列(送信ID など)が無い表には触らずに断ります

### 7.1 作業の記録・テストモード・編集履歴(0.13.30。ペナラベルと同じ仕組み)

- **作業の記録**(`meisai/work_record.py`): 出力・出力し直し・修正の開始/取り消し・全クリア・印刷画面(`/api/printed`)・紙面を開いた・履歴の紙面を開いた・設定(テストモード・記録の保存先) を、版(統合・梱包明細)・PC 名・ライン名・ログインID(テストモードなら印)つきで、月ごとのファイル `梱包明細記録_YYYY-MM.csv` に 1 行ずつ足す(形式は設定「記録ファイルの形式」(`record_format`。この PC。配布できる。パスワード無し。0.13.31)で **CSV(既定。Excel で開ける)**・JSONL・両方。CSV の列はペナラベルと同じ。Excel で開いていて書けない間は「追記待ち」に足し、次に書けたときに書き足す。`common/record_file.py`)。この PC の `records` にいつも、設定「記録の保存先フォルダー」(`record_dir`。管理者パスワード。配布できる)があれば `<record_dir>/<PC名>/` にも。書けなくても出力は止めない。画面は `/report/records`(新しい順に 300 件・控えの場所と書けない理由・資材マスタの編集履歴)
- **テストモード**(`test_mode`。管理者パスワード。配布しない): 記録・明細の履歴(列「モード」。手元・共有とも最後の列。古い表には足す)・編集履歴に「テストモード」と残し、上の帯と紙面の画面に赤い札(紙には出ない)
- **ライン名**(`line_name`。40 文字まで。配布しない)
- **編集履歴**(`meisai/edit_history.py`): 右上の文字の変更・既定に戻す と、管理者パスワードの変更・初期化 を、梱包資材マスタの表「資材マスタ編集履歴」(ペナラベルと同じ列)に残す。パスワードは前・後とも「(伏せる)」

## 8. マスタ管理(見るだけ)

`meisai/master_browse.py`・`app/routes/master.py`。梱包資材総合ツールのマスタ管理の「中身を見る」ところだけを移したものです。

- 見るファイル: 梱包資材マスタ・梱包明細履歴(無ければ作ってから開く)
- 200 行ずつ出し、出さなかった分は数で言います。絞り込みはどの列でも(一部一致。`%` `_` は文字どおり)
- 見出しで並べ替え。数字は数の大きさで、空はいちばん後ろ。並べ替えは実在する列だけ
- 行を押すとその 1 行の中身を出します
- CSV: いまの絞り込み・並べ替えのまま全行を書き出します
- 読み取り専用の接続でだけ開きます。共有を待つのは 15 秒まで。応えないまま残っている読み込みがあれば重ねずに断ります
- 梱包明細履歴は共有へ送った分だけが見えます。送り残しがあれば枚数を出し、裏で送ります

## 9. 主な API

経路は `/details` の下です。画面から呼ぶ `/api/*` と `/report/*` は、起動トークン(`X-Tool-Token`、帳票は `?t=`)と同じページからの要求であることが要ります。

画面は操作を**押した順に 1 つずつ**送り、そのとき**押した画面のロット**を `X-Screen-Lot` に付けます(`meisai.js` の `queued`)。
サーバはいま開いているロットと違えば使わずに断ります(409 `lot_changed`。`routes/meisai.py` の `_refuse_other_lot`。VER 0.13.26)。
ロットを開く `/api/lot` は開く前の画面から押すので見ません。ヘッダの無い要求(帳票の別タブ・設定)も見ません。
台帳の読み込みが遅いあいだに打った重量・押したコイルが、開いたロットに入るのを防ぐためです。

| 方法・経路 | 用途 |
|---|---|
| `GET /meisai` | 画面(いまの状態を埋め込んで返す) |
| `POST /api/screen/claim` `/take-over` `/release` ・ `GET /api/screen/state` | 画面の持ち主(名乗る・手放させる・閉じた・様子) |
| `POST /api/lot` | ロットを開く(`confirm` 付きで片付けを了解。出力済みの修正中は `cancel_edit` 付きのときだけ、修正をやめて開く) |
| `POST /api/clear-lot` | ロットを閉じる(画面からは呼んでいない。修正中は断る) |
| `POST /api/zen-kotei` | 前工程実績数を手で直す(半角の数字だけ) |
| `POST /api/jou-su` | 丈数(1〜20) |
| `POST /api/weights` | 丈ごとの重量 |
| `POST /api/strands` | 条番号表示 |
| `POST /api/reverse` | 反転 |
| `POST /api/stack-max` `/api/stack` `/api/unstack` | 積み条数・積む・外す |
| `POST /api/discard` | 廃棄の付け外し |
| `POST /api/output` | 出力(`confirm`)。出力済みの修正中なら修正して出力 |
| `POST /api/edit-output` `/api/edit-cancel` | 出力済み修正に入る(`no`)・やめる |
| `POST /api/printed` | 印刷済みを記録 |
| `POST /api/clear-all` | 全クリア(`confirm`) |
| `POST /api/import` ・ `GET /api/import/progress` | 取り込み(`force`・`only: lot/konpo`)と進み具合 |
| `GET /report/…` ・ `POST /report/<ロット>/edits` ・ `GET /report/qa-mark` | 帳票・書き足し・いまの右上の文字 |
| `GET /api/history/status` ・ `POST /api/history/send` `/search` `/export` | 明細の履歴 |
| `GET /api/master/browse` ・ `POST /api/master/export` | マスタ管理 |
| `GET/POST /api/settings` ほか `/share` `/qa-mark` `/admin-password` `/shared-dir` `/lot2` `/distribution/*` `/auto-import` | 設定 |
| `GET /api/health` ・ `POST /api/alive` ・ `POST /api/shutdown` | 起動確認・心拍・停止 |
| `GET /docs` `/docs/<名前>` | 説明書・変更履歴(トークン不要) |

ロットを扱う操作の返事には、毎回 **画面の状態まるごと**(`state`)が入ります。

## 10. 断り方

返事の形は `{"error": {"code": …, "message": …, "field": …}}` です(`app/__init__.py` の `error_body`)。文言はサーバが持ち、画面はそのまま出します。

| 番号 | code の例 | いつ |
|---|---|---|
| 400 | `bad_lot_no` `bad_number` `out_of_range` `no_weight` `bad_zen_kotei` `incomplete` `bad_no` `bad_edit` `no_output` `stacking` `unknown_output` `used_elsewhere` ほか | 入力の形・範囲が違う、順番が足りない、出力済み修正に入れない・ほかのNoのコイルが入っている |
| 401 | `bad_token` | トークンが違う(「この画面は無効になりました。アプリを開き直してください」) |
| 403 | `cross_origin` | 別のページからの要求 |
| 403 | `need_password` `wrong_password` | 管理者パスワードが違う |
| 404 | `not_found` | ロット・出力が見つからない |
| 409 | `screen_busy` | 名乗ったが、ほかの画面が持っている(2 枚目) |
| 409 | `screen_taken` | 持ち主でない画面からの操作(引き継がれた古いタブ) |
| 409 | `no_lot` `no_strands` | ロットを開いていない・条番号が出ていない |
| 409 | `bad_edit` | 作り直された明細への書き足し |
| 409 | `jou_su_locked` `zen_kotei_locked` `strands_locked` `weights_locked` | 積み上げを始めたロットで丈数・前工程実績数・重量を変えようとした・条番号表示をしようとした(全クリアしてから) |
| 409 | `editing` | 出力済みの修正中に、条番号表示・丈数の変更・もう 1 枚の修正をしようとした |
| 409 | `lot_changed` | 押した画面のロット(`X-Screen-Lot`)が、いま開いているロットと違う(開く前の画面で打った・押した。VER 0.13.26) |
| 503 | `write_failed` | 手元の DB に書けなかった(待つのはまとまりごとに最大 13.5 秒) |
| 503 | `shared_unreachable` | 共有に届かないので右上の文字・管理者パスワードを変えられない |

### 確認が要る返事

断りではなく、`200` で `{"ok": false, "confirm": …}` を返します。画面は「はい/いいえ」の窓を出し、「はい」なら同じ要求を `confirm: true` で送り直します。了解前は何も書きません。

| confirm | 文 |
|---|---|
| `unprinted` | 前回の出力(…)がまだ印刷されていません。シートを削除してよいですか？ |
| `overwrite_restored` | 前回の状態が復元されています。条番号を再表示すると、出力していない使用済みはリセットされます。(出力済みのコイルと廃棄は維持) 続行しますか？ |
| `output` | `confirms` に `duplicate`(§4.7)か、修正中なら `edit`(§4.8)を並べる。`overwrite` / `beyond_seq` は No指定と一緒に外した |
| `clear_all` | ロット … を初めからやり直します。出力済み(N枚)・副番履歴・連番・条番号と廃棄を消します。…(§4.10) |

### 黙って何もしない返事

使用済み・廃棄済みのコイルを積もうとした、空のスロットを押した、使用済みを廃棄にしようとした、のときは `200` で `ignored` を付けて状態だけ返します(VBA と同じく警告を出さない)。
