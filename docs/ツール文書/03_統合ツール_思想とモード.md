# 統合ツール 思想とモード

対象の版: コイル梱包ツール 1.2.57(梱包明細 VER 0.13.35 / ペナラベル 1.5.52 / 資材計算 0.2.35)

統合ツール(外枠)を「なぜこの作りにしたか」と、外枠の中にあるモード・状態の説明です。
根拠は、コードのコメントと `docs/統合設計.md`・`docs/デスクトップ版.md`・`docs/ランチャー連携.md`・`docs/変更履歴.md` です。

---

## 1. 設計の考え方

### 1.1 統合とは、機能を 1 つにまとめることではない

3 機能の計算・入力チェック・DB 処理・帳票は、移植元のまま別々に動かします。変えたのは「入れ物」(起動・停止・待ち受け・画面の外枠・ログ)だけです。
設定画面も設定値も機能ごとのままです。「設定画面を 1 つにすること」と「設定値を 1 つにすること」は別の話で、統合版はどちらもしていません(`docs/統合設計.md` §2)。
各機能の画面に要るもの(心拍・画面の色・エラーの報告・デスクトップ版の窓まわり)は、**各機能のコードを触らずに**統合アプリが HTML に差し込みます(`app.py`)。
移植元の試験がそのまま通ることを守るためです。

### 1.2 1 つのプロセスに同居させる

| 理由 | 根拠 |
|---|---|
| 移植元のうち 2 つが同じポート(8733)を使っていて、そのままでは同時に動かせない | `docs/統合設計.md` §1.2 |
| 起動・停止・多重起動の防止・自動終了を 3 組持つと、矛盾する(梱包明細と資材計算は心拍が途切れたら終わる、ペナラベルは終わらない) | 同上。見張りはプロセスに 1 つにし、生き死には画面ごとに持つ(`common/idle_exit.py`) |
| ログを 1 つのファイルにすると、「梱包明細で出力した直後に資材計算が固まった」のような、機能をまたぐ経緯を突き合わせられる | `common/logging_utils.py` |
| 守り(起動トークン)を 1 つにすれば、1 つだけ素通しの機能を作らない(ペナラベルにもトークンを要求した) | `common/security.py` |

同居させても、画面は **iframe で分けます**。3 つの画面は同じ名前の CSS・JS をそれぞれ持っているので、1 つの文書に流し込むと 3 画面の書き直しになるためです(`app.py` の冒頭)。
iframe は隠すだけで外さないので、タブを移っても入力の途中の値・心拍が続きます。

### 1.3 入口を増やさない

- 利用者がダブルクリックする通常の入口は **1 つ**(ブラウザ版は `Start.vbs`、デスクトップ版は exe)。原因を調べるための入口(`start.bat`)とは分けます(`Start.vbs`・`start.bat` の冒頭。社内の基盤仕様書 2.1)
- `run.py` は `start_app.py` を呼ぶだけの別名です。起動の流れを 2 本持ちません
- デスクトップ版も、待機画面 → 本体を組み立てる → 3 機能の初期化 の中身はブラウザ版と共有します(`start_app.start_bridge`。「2 本持つと片方だけ直すことになる」)
- ランチャーのための専用ファイルは置きません。1.2.4 で足した `launcher_stop.bat` などは 1.2.5 で取りやめ、起動ファイルの中身を変えずにプログラムの中だけで合わせました(`docs/ランチャー連携.md`)
- 待機画面も統合アプリの 1 つにまとめます。機能の入口を準備中に開いたら、統合アプリの待機画面へ回します(`app._install_boot_redirect`)

### 1.4 画面は 1 枚だけ(機能ごとに守る)

各機能は「同じ作業状態を 2 枚の画面から書き換えさせない」見張りを持っています。統合版でもこれは**機能ごとのまま**です。
守る相手(作業状態)が機能ごとに別で、画面との約束(ヘッダ名・本文・応答)も違うので、1 つにしても守れるものが増えないためです(`common/security.py`)。
そのため統合画面を 2 枚開くと、3 つのタブがそれぞれ「別の画面で開いています」になり、「この画面で使う」はタブごとに押します。
1 回で 3 つとも引き継ぐ仕組みは作っていません(`docs/統合設計.md` §7)。

### 1.5 判断はサーバが持ち、画面は写すだけ

- 準備ができたかは、時間ではなく**サーバの答え**(`/api/health` の `ready`)で決めます。待機画面は一定秒数で完了扱いにしません(`common/boot_screen.py`)
- 待機画面の段の文言はサーバが持ち、画面は写すだけです(同上)
- 止めてよいか(途中の処理があるか)は、サーバが `busy` で答えます。画面が「終了」を押しても、取り込み中なら 409 で断ります
- 起動してよいか・どの版が動いているかも、サーバ側(`launch_guard.py`)が `app_id` と版の組で決めます

### 1.6 止まったと確かめてから言う

- `stop.bat` は、待ち受けが閉じただけ・強制終了を頼んだだけでは「終了しました」と言いません。**プロセスが居なくなったのを確かめてから**言い、
  残っていれば「まだ動いています」と出してロックも残します(統合 1.2.19。業務ツール統合ツール all-tools で、止まったと言ったのに Python が残り、フォルダを消せなかった)
- 統合画面の「終了しました」も、サーバが `stopped: true` を返してから出します。止めた直後に `/api/health` が返っても「接続OK」で上書きしません(`static/js/shell.js`)
- 起動の確認も同じで、待ち受けを始めたあと `/api/health` に答えるまで確かめ、つながらないのか・つながるのに答えないのかを分けて理由を出します(`server.diagnose_listening`)

### 1.7 迷ったら、害の小さいほうへ倒す

| 場面 | 選んだほう | 根拠のコメント |
|---|---|---|
| 裏に回ったまま戻らない画面 | 終わらずに残る | 「裏で誤って終わるより、ずっと害が小さい」(`common/idle_exit.py`)。次の `Start.vbs` は残ったプロセスに合流する |
| PID が本当にこのアプリか確かめられない | 止めない | 「誤って別のアプリを落とすより、止まらないほうが害が小さい」(`process_manager.py`) |
| 動いているはずのアプリが答えない | 別物と決めつけず合流する・`--force` が無ければ落とさない | 重い処理の途中かもしれない。2 つ目を立てると同じ手元の DB を 2 つで開く(統合 1.2.26。`launch_guard.check_existing`・`process_manager._stop_by_pid`) |
| 起動の順番待ちを締められない | 通す | 「まれに 2 つ立ち上がるほうが、確実に開けないより害が小さい」(`launch_guard.startup_gate`) |
| 単体版が動いているか見分けられない | 起動は止めない | 1.2.0 で見分けの途中のエラーで起動できなかった(`launch_guard.find_legacy_instances`) |
| 取り込みの途中 | 止めない(古い版の入れ替えでも合流する) | 中途半端なデータを残すほうが害が大きい(`launch_guard._replace_stale`・`app._stop_now`) |
| 設定ファイル・版の書き方が壊れている | 既定値で起動を続け、理由を画面とログに出す | 起動そのものが失敗するより調べやすい(`common/app_config.py`) |
| 単体版が動いている | 自動では止めず、止め方を案内する | 保存前の作業を持っているかもしれない(`start_app.start`) |

### 1.8 待たせるために見せるものを待たせない

起動でいちばん時間がかかるのは Flask と本体の読み込みです。そこで標準ライブラリだけの小さなサーバ(`boot_server.py`)で先に待ち受けを始めて待機画面を出し、
本体ができたら**待ち受けを開き直さずに**差し替えます(開き直すと、その瞬間の問い合わせが落ちて「接続できません」に見える)。

### 1.9 このPCの、このアプリ以外からは触らせない

待ち受けは `127.0.0.1` だけ、Host の確認、別のページからの書き込みを断る、起動トークン、CORS ヘッダを返さない ── どれも業務の結果には触れず、
「このアプリの画面以外から操作させない」ためのものです(`common/security.py`)。心拍の口はトークンが要らないので、別のページから送って
「画面が開いている」と見せかけ、自動終了を止められないようにも断っています(統合 1.0.7)。

### 1.10 各言語が得意なことをする(デスクトップ版)

窓・プロセス・ファイルロック・静的ファイルは外枠(Rust)、取り込み・計算・SQLite・Access・画面の組み立ては Python のまま、Access は今までどおり cscript.exe 経由です。
重い処理は無く、VBA と同じ結果を守る試験(約 1,800 件)が Python の形で書かれているので、書き直す利点が無いためです(`docs/デスクトップ版.md`)。

## 2. モード

### 2.1 ブラウザ版とデスクトップ版

| | ブラウザ版 | デスクトップ版 |
|---|---|---|
| 入口 | `Start.vbs`(通常)/ `start.bat`(診断) | `コイル梱包ツール.exe` |
| 画面 | ふだんのブラウザのタブ | 専用の窓 |
| 通信 | `127.0.0.1` のポート(8740〜8743) | ポートを使わない(標準入出力) |
| 自動終了 | あり(心拍) | なし(窓を閉じたら終わる) |
| 外からの停止 | `stop.bat` / `POST /api/shutdown` | 窓の ×(`WM_CLOSE`) |
| 位置づけ | 予備 | ふだん使う |

同じ手元の DB・作業状態を使うので、**同時には動かしません**。統合アプリの中では、デスクトップ版のとき `BRIDGE` の印が立ち、
`PORT` は 0、`desktop.js` を差し込み、Host に `app.localhost` を足します。統合画面の JS は `window.__TAURI__` の有無で見分け、
デスクトップ版では「外からの閉じる頼み」をたずねに行きません(`static/js/shell.js`)。

### 2.2 `mode=main` ── モードは 1 つだけ

`common/modes.py` のとおり、**モードは `main` の 1 つしかありません**。3 機能はモードではなくタブで分けます。

| 項目 | 中身 |
|---|---|
| 名前 | `main`(画面・ログでの呼び名は「統合」) |
| 決め方 | `modes.normalize()` は、空・知らない名前・大文字も含め、何を渡されても `main` にする。断らない(打ち間違いが「起動失敗」に見えて、直す先が分からなくなるため) |
| 旧名の読み替え | 無い(`LEGACY_NAMES` は空) |
| 使われる場所 | ロック `runtime\main.lock`・順番待ち `runtime\main.start`・`/api/health` の `mode`・多重起動の照合(`app_id` と `mode` が合うか)・`config/app.json` の `server.roles.main` |
| モジュールを残す理由 | 起動基盤(`launch_guard` `process_manager` `server`)が移植元と同じ形でモード名を引数に取るため。基盤を書き換えずに済ませた |

移植元は現場モードと資材モードを別のポートで動かしていました。その名残の仕組み(旧名の読み替え・モードごとのポートの重なりの見張り)は
基盤に残っていますが、いまのモードは `main` だけです。`process_manager.py --mode` に渡せるのは `main` だけで(引数の選択肢が `main` のみ)、
`--all` は古い呼び出しを断らないための隠し引数で、`main` を止めるのと同じです。
(1.2.22 で、`process_manager.py`・`launch_guard.py`・`common/app_config.py` に残っていた「`--mode material` で資材モードを止める」
「現場と資材は同時に起動してよい」などの古い説明を、いまの作りに合わせて直しました)

### 2.3 通常起動と診断起動

| 起動 | 中身 | 使うとき |
|---|---|---|
| `Start.vbs` | コンソールを出さずに `pythonw start_app.py`(引数なし)。失敗はメッセージの窓・ブラウザの「起動できませんでした」 | ふだん |
| `start.bat` | 黒い窓を開いたまま。先に `--check` を流し、続けて `start_app.py %*`。窓を閉じるとアプリも終わる | 起動しないとき |
| `start.bat --check`(`start_app.py --check`) | 環境の確認(Python の版・部品・書き込み・3 機能の領域・設定)をして、アプリの ID・版・設定ファイル・ローカル領域・ポートの候補・プロキシの設定を出して終わる。起動はしない | 環境を見たいとき |
| `start.bat --diagnostic`(`start_app.py --diagnostic`) | 3 機能とも DEBUG まで残す。ふだんは梱包明細・資材計算・統合アプリが DEBUG、ペナラベルは INFO まで(移植元のまま) | 細かい経過を調べるとき |
| `start_app.py --no-browser` | ブラウザを開かない(起動した URL を表示) | 検証。1 度も画面がつながらなければ自動終了しない |

デスクトップ版には診断用の引数はありません(`bridge.py` は引数を読まない)。起動できないときは、窓に理由・Python の出力の終わり・ログの場所が出ます。

### 2.4 試験用の環境変数

ふだんの起動では使いません。置き場所を差し替えて、本番の領域を汚さずに試すためのものです。

| 名前 | 中身 |
|---|---|
| `COIL_PACKING_TOOLS_E2E_NO_AUTOPRINT=1` | ペナラベルの印刷ビューを開いたとき、自分で印刷の画面を出さない。Windows の窓では開いたときの印刷の画面が閉じるまで窓が止まり、自動操作(WebDriver)では押せないため、窓の通し試験だけが立てる(`modules/packing_pena_label/app/routes/pages.py`)。試験は「印刷する」ボタンから刷って確かめる |
| `COIL_PACKING_TOOLS_APP_CONFIG` `…_LOCAL_DIR` `…_LOG_DIR` `…_SETTINGS_PATH` `…_DISTRIBUTION_DIR` | 設定ファイル・手元の領域・ログ・このPCの設定・配布設定(共通)の場所を差し替える(通し試験・`scripts/desktop_smoke.py`) |
| `COIL_PACKING_TOOLS_ROOT` `COIL_PACKING_TOOLS_PYTHON` | exe が探すアプリのフォルダと Python |
| `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS` `WEBVIEW2_USER_DATA_FOLDER` | 窓の通し試験(msedgedriver)が付けるものを、exe が窓にそのまま渡す(Windows) |

`COIL_PACKING_TOOLS_LOG_DIR` が入っていると、上の帯の「ログ」の設定より勝ち、画面にもそう出ます。

### 2.5 待機画面の状態

段は 4 つ(実行環境・準備・取り込み・完了)。正確な割合を出すためではなく、反応が無いように見える時間をなくすためです(`common/boot_screen.py`)。
待機画面は `/api/health` を 300 ミリ秒ごと(`monitoring.job_poll_ms`)に問い合わせます。

| 状態 | `/api/health` の様子 | 画面 |
|---|---|---|
| 起動中 | `ready: false`、`stage` に段の文 | 段の文を写す。3 機能の取り込みが同時に進んでいれば「梱包明細: … / 資材計算: …」と並べる |
| 準備完了 | `ready: true` | 段を全部済みにし、統合画面(`/?t=…`)へ移る |
| 待たずに使い始める | (準備中のまま) | 「待たずに使い始める ▸」で `/?go=1`。準備中でも統合画面を出す(取り込みは裏で続く) |
| 取り込みが長い | 150 秒たっても終わらない | 先に準備完了にし、取り込みは裏で続ける(ログに残す) |
| 組み立て失敗 | `startup_error` に「アプリを組み立てられませんでした: …」 | 「起動できませんでした」・理由・ログの場所・「このまま終了する」。開いているあいだは 10 秒ごとに様子を聞く。ブラウザ版は 120 秒だれも見なければ Python が自分で終わる |
| 機能の初期化の失敗 | `startup_error` に「<機能>: 初期化に失敗しました: …」 | 組み立て失敗と同じ「起動できませんでした」の表示になる。ほかの機能の初期化は続く。このときは 120 秒の見張りは付かない(組み立て失敗のときだけ) |
| 別のアプリ | `app_id` が違う | 「別のアプリが同じポートを使っています」 |
| 応答が無い | 25 回続けて失敗 | 「バックエンドに接続できません」 |

デスクトップ版では、この待機画面の前に外枠の「起動しています…」が出ます。Python が見つからない・途中で落ちたときは、外枠の理由の画面になります(`src-tauri/src/pages.rs`)。

### 2.6 統合画面と見張りの状態

| もの | 状態 |
|---|---|
| 接続表示 | 接続確認中 → 接続OK / 接続なし(2 回続けて失敗。赤い帯)/ アプリが開き直されています(pid が変わった)/ 終了しました |
| 見張りから見た 1 枚の画面 | 前(心拍を待つ。90 秒で居ない)/ 裏(心拍の途切れでは居なくならない)/ 閉じた(8 秒の猶予のあと居ない) |
| 外からの閉じる頼み(ブラウザ版) | 頼みなし / 確かめ中(`working`)/ 閉じてよい(`ok`)/ 閉じない(`refused`)。頼みは 2 分で取り下げ |
