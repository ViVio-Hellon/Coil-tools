# ランチャー連携 — コイル梱包ツール側の取り決め

業務ツール統合ランチャー([python-business-tools-launcher](https://github.com/ViVio-Hellon/python-business-tools-launcher))
から、コイル梱包ツールを **1つのツールとして** 起動・終了するための、コイル梱包ツール側の取り決めです
(ランチャー連携 要件定義の「3. 各ツール側への依頼」)。

- 梱包明細・ペナラベル・資材計算は **コイル梱包ツールの中**(タブ)で動きます。ランチャーには
  コイル梱包ツールだけを登録します
- ランチャーはコイル梱包ツールの中身(exe → Python → 3機能)を知る必要がありません。下の起動ファイルを
  実行し、下の方法で起動を確かめ、下の方法で止めるだけです
- **作りは業務ツール統合ツール(all-tools 1.2.0)と同じです。** 起動ファイル(`Start.vbs`・`start.bat`・
  `stop.bat`)の中身は変えず、ランチャー専用のファイルも置かず、プログラムの中だけで合わせています(統合 1.2.5)。
  ランチャーへの登録の仕方・止め方・戻り値は all-tools と同じです
- 確かめたランチャーの版: **1.7.1(`0778df1`)**。1.6.4(`621a7fe`)でも同じに動きます

> 統合 1.2.4 で足した `launcher_stop.bat`・`launcher_status.bat`・`Start.vbs` の引数渡しは、1.2.5 で取りやめました
> (all-tools と登録の仕方がそろわないため)。1.2.4 を配った PC は、1.2.5 で入れ替えれば消えます。

## 1. 起動ファイル(要件 3.1・3.3)

| 起動ファイル | 中身 | 画面 | 使うとき |
|---|---|---|---|
| **`コイル梱包ツール.exe`** | デスクトップ版(Rust/Tauri の窓)。Python(`bridge.py`)を自分で起こす。**ポートを使わない** | コイル梱包ツール自身の窓 | 窓で使う PC |
| `Start.vbs` | ブラウザ版。`pythonw start_app.py` を起こして**すぐ戻る**(引数は渡さない) | ふだんのブラウザーにコイル梱包ツールが開く | ブラウザーで使う PC |
| `start.bat` | ブラウザ版の診断用の入口。`python start_app.py %*`(止まるまで戻らない) | `--no-browser` を渡せばランチャーが開く | 原因を調べるとき。ランチャーには登録しない(下の「start.bat を勧めない理由」) |

どれも、ダブルクリックでも、ランチャーから直接実行しても同じように起動します。exe・VBS から先
(Python の起動・3機能の準備・ブラウザを開く)はコイル梱包ツールが受け持ちます。

- ブラウザ版とデスクトップ版は**同時には動きません**(同じ手元のデータを使う)。片方が動いているときに
  もう片方を起動すると、理由を出して起動しません
- Access(.accdb)は今までどおり cscript.exe → VBScript → ADODB → ACE で読みます

## 2. 起動の確かめ方(要件 3.2・10)

| 起動ファイル | 起動したとみなす合図 |
|---|---|
| `コイル梱包ツール.exe` | **コイル梱包ツールの窓が出たこと**(待ち受けるポートは無い)。窓は「起動しています」→ 取り込みの進み具合 → 統合画面、と進みます |
| `Start.vbs` / `start.bat` | `GET http://127.0.0.1:<port>/api/health` が `app_id: "nlm.coil-packing-tools"` と `ready: true` を返すこと |

ブラウザ版の `/api/health`(起動トークン不要。抜粋):

```json
{"app_id": "nlm.coil-packing-tools", "display_name": "コイル梱包ツール", "version": "1.2.5",
 "app_root": "C:\\業務ツール\\コイル梱包ツール", "port": 8740, "pid": 1234, "ready": true}
```

- ポートは `config\app.json` の 8740(使えなければ 8741〜)。実際の番号は `/api/health` の `port`
- 実際の番号と停止用のトークンは `%LOCALAPPDATA%\CoilPackingTools\runtime\main.lock`(JSON: `port` `token` `pid`)
- `app_root` はランチャーが止める前に「本当にコイル梱包ツールか」を照合するのに使います

## 3. 止め方(要件 3.5・3.6)

**ランチャー側に個別の止め方は要りません。** exe は窓の ×、ブラウザ版は今ある `stop.bat` /
`POST /api/shutdown` が、そのまま停止の入口です(ランチャーの停止方法は「自動」のまま)。

| 起動ファイル | 止める入口 | 中で起きること |
|---|---|---|
| `コイル梱包ツール.exe` | **窓に「閉じて」と頼む**(× と同じ `WM_CLOSE`) | 統合画面の「終了」と同じ流れ: 3機能の画面に**保存していない入力**を訊く → あれば1つの確認 → 途中の処理(取り込みなど)があれば「中断して終了しますか」→ exe も Python も終わる。**どちらも無ければ確認は出ずに終わる** |
| `Start.vbs` / `start.bat` | `stop.bat`(→ `process_manager.py`)または `POST /api/shutdown` | **開いている統合画面に、保存していない入力を確かめてもらう**(下)→ 途中の処理が無ければ止める |

`POST /api/shutdown`(ヘッダ `X-Tool-Token: <main.lock の token>`、本文 `{"force": false}`)の答え:

| 答え | 意味 |
|---|---|
| 200 `{"stopped": true}` | 止めます(0.4 秒後) |
| 409 `{"reason": "asking", "running": [...]}` | 開いている画面に「確かめてから閉じて」と頼みました。**確かめが済めばコイル梱包ツールが自分で終わります**。画面に確認が出ていれば本人が答えます |
| 409 `{"reason": "refused", "running": [...]}` | 画面で本人が「閉じない」(キャンセル)を選びました(保存していない入力がある)。止めません |
| 409 `{"reason": "busy", "running": [...]}` | 途中の処理(資材計算の取り込みなど)があります。止めません |
| `{"force": true}` | 画面にも途中の処理にも訊かずに止めます(本人が中断を選んだときだけ) |

`process_manager.py` と `stop.bat` の戻り値: 0 = 止まった・もともと動いていない / **3** = 止めなかった(上の 409。統合 1.2.64 から。1.2.63 までは 2 で、`stop.bat` は 1 に丸めていた。「頼みました」のときは 15 秒まで
終わるのを待ってから返す)/ 1 = デスクトップ版が動いている(`stop.bat` はデスクトップ版を止めない。窓を前に出す ── `--force` のときは
前に出さない。前に出す仕組みは exe をもう一度起動するもので、ランチャーが窓を閉じた直後に `--force` で
呼ぶと、閉じかけの窓の代わりに新しく起動してしまうため)・
応答しない(統合 1.2.26 から、`--force` が無ければ PID で落とさずに 1 を返す。Windows の PID での停止は
その場で落とすので、取り込みの途中かも確かめずに落としていた)など。`stop.bat` は 0 以外なら理由を表示して一時停止し、3 か 1 を返します。
**`/nopause` を付けるか環境変数 `STOP_NOPAUSE=1` なら一時停止を飛ばします**(統合 1.2.64。ランチャー 1.8.9 は `STOP_NOPAUSE=1` を付けて呼ぶ)。
止めなかった理由は**標準出力の1行目**(`止めませんでした: 実行中の処理があります: 資材計算: 取り込み` など)。画面で確認中の途中の
知らせは標準エラーへ出します。

ランチャー 1.7.1 から、`stop.bat` が 0 以外で終わると**待たずに**、出力のはじめの行を理由として
「強制終了(中断)しますか」を利用者に訊き、「はい」なら `stop.bat --force` で呼び直します。
`process_manager.py` は止めなかった理由を**行の頭に**出します(例: `止めませんでした: コイル梱包ツールの画面で
「閉じない」が選ばれました(保存していない入力があります)`)。

**ほかの Python・exe・VBS は止めません。** 止めるのは `main.lock` に書いたコイル梱包ツールだけです
(答えないときだけ、記録した PID が**本当にこのツールか**確かめてから止める)。
PID は**番号と起動時刻の両方**で確かめます(統合 1.2.65)。印を書いた時刻より後に起動したプロセスは、番号を使い回した別の
プログラムなので止めず、残った印を片付けて「Start.vbs で起動できます」と出します(戻り値 0)。

### 保存していない入力の守り(統合 1.2.5)

1.2.4 までは、外から(ランチャー・`stop.bat`)止められると、**開いたままの画面の入力が訊かれずに消えました**。
画面の「終了」も、入力のあるなしに関わらず毎回「よろしいですか」を出すだけでした。

いまは「終了」・窓の ×・外からの停止のどれも、同じ確かめを通ります。

1. 入口は、開いている統合画面(毎秒「頼まれていないか」をたずねに来る)に頼みを出し、3 秒だけ返事を待つ
2. 画面は「確かめています」と返し、3機能の画面に保存していない入力を訊く(下の表)。あれば
   「まだ保存していない入力があります … 閉じると、この入力は消えます。閉じますか?」を出す
3. 無い・本人が「OK」→ 止める。本人が「キャンセル」→ 止めない。3 秒で済まなかった → 409 `asking` を返し、
   済んだところで入口が自分で止まる(頼みは 2 分で取り下げ)
4. 画面が無い(閉じた・開いていない)ときは、待たずに止める

画面を閉じたという合図(タブを閉じるときの `sendBeacon`)が届かなかったとき(ブラウザーが落ちた など)は、
最大 75 秒その画面が居るとみなします。そのあいだの停止は 409 `asking` になり、ランチャーは
「強制終了しますか」を訊きます(入力は失いません。all-tools と同じ)。

| 機能 | 保存していない入力として訊くもの |
|---|---|
| 梱包明細 | 7桁になっていない LOT No・「確定する」を押していない前工程実績数・空の丈があって送っていない重量・「修正して出力」を押していない出力済み修正(VER 0.13.23。以前は「出力」を押していない No指定)・設定の保存していない欄 |
| ペナラベル | 重量反映などのボタンを押していない新検番・重量・高さ・チップボール・「決定」を押していない全サイズの入力・「直す」を押していない位置合わせのずれ・設定の保存していない欄・マスタ管理の書き込んでいない行 |
| 資材計算 | 7桁になっていない LOT・**チェックリストへ積んでいない計算**・「計算」を押していないバリ揃えの本数・**記録していない発注票**・設定の保存していない欄・マスタ管理の書いていない行(計算と発注票はメモリにだけあり、止めると消えます) |
| ログ | 保存していない出力先・残す日数 |

### ツール側の入口(launcher_check.bat・launcher_stop.bat)は置きません

ランチャー 1.7.0 から、起動ファイルの隣に `launcher_check.bat`(起動確認)・`launcher_stop.bat`(終了)・
`launcher.json` があれば、ランチャーの推測より優先して使います(ランチャーの `docs/ツール側の入口.md`)。
**置くのは任意で、置かないツールはこれまでどおりランチャーが補います。**

コイル梱包ツールは all-tools と同じく**置きません**(上の 1〜3 のとおり、窓の × ・`stop.bat`・`/api/shutdown`・
`/api/health` で足りるため)。

- **1.2.4 を上書きで入れ替えた PC は、`launcher_stop.bat`・`launcher_status.bat` を消してください。**
  残っているとランチャー 1.7 は `launcher_stop.bat` を終了の入口として使います(念のため、そのときも
  `process_manager.py` は古い印 `--any` を読み捨てて、ふつうに止めます)。ランチャーの［設定］のその行に
  「ツールの入口: … 終了 launcher_stop.bat」と出ていれば残っています。`make_dist` で作り直したフォルダーに
  丸ごと入れ替えれば残りません
- `launcher_status.bat` はランチャーが使わない名前です(ランチャーが見るのは `launcher_check.bat`)

## 4. ランチャーの設定の勧め

| 起動ファイル | 画面 | ポート | 起動引数 | 止め方 |
|---|---|---|---|---|
| `コイル梱包ツール.exe` | アプリの窓(exe を選ぶと自動で決まる) | **空にする** | 空 | 自動 |
| `Start.vbs` | ブラウザー(自動) | 8740(app.json から入る) | 空(渡せない) | 自動(`stop.bat`) |

- **exe の行はポートを空にしてください。** ランチャー 1.7.1 からは exe を選ぶと空のままになります
  (隣の `config\app.json` のポート 8740 はブラウザ版のもの)。1.7.0 以前に登録した行で入っていれば、
  ［設定］の保存と `start_debug.bat --check` で知らせが出るので、消してください。exe とブラウザ版が同じ
  `config\app.json` を使うため、コイル梱包ツール側では分けられません
- 停止方法は「自動」のままにします。exe は窓に「閉じて」と頼み(× と同じ)、ブラウザ版は `stop.bat` を使います
- 1台の PC には **exe か Start.vbs のどちらか1つ** を登録します(同じアプリID は2行にできません。
  デスクトップ版とブラウザ版は同時には動きません)。PC ごとに配布先設定で選びます
- ランチャーを動かす Python と、ツールを動かす Python は同じもの(PATH の `python`)にしてください。
  Microsoft Store の Python は `%LOCALAPPDATA%` の下のファイルを Python ごとの場所に置き換えるため、
  別の Python から見ると停止用のトークン(`main.lock`)が見えないことがあります(そのときもランチャーは
  `stop.bat` で止められます。`stop.bat` はツールの Python で動きます)

### start.bat を勧めない理由

`start.bat` を登録すると、ランチャーは `--no-browser` を渡して自分の専用画面を開き、止めるときに
**その画面を先に閉じてから** コイル梱包ツールを止めます。画面が先に閉じられるので、上の
「保存していない入力の確かめ」を通りません。`Start.vbs` なら画面は閉じられず、確かめを必ず通ります
(止めたあとの画面には「終了しました」が出るので、タブは手で閉じます)。

## 5. 確かめたこと

ランチャーの実物のコード(1.7.1 の `launcher.health`・`process_manager.stop`)で、コイル梱包ツールのブラウザ版
(実物の入口と3機能)を起動・停止しました(Linux・Chromium)。1.6.4 でも同じ結果でした。
`stop.bat` の経路は、Linux では .bat を実行できないので、`stop.bat` と同じ出力・戻り値の代わりを使いました。

| 場面 | 結果 |
|---|---|
| 起動の確かめ(`/api/health` の `app_id` 照合) | 1.5 秒で確認 |
| 停止用トークンの読み取り(`main.lock`) | 読めた |
| 入力なしで停止(停止方法 自動) | 画面が頼みに答えてから止まった(1.0 秒。確認は出ない) |
| ペナラベルに打ちかけ → 画面で「キャンセル」 | 止めない(409)。次の停止で訊き直し、「OK」で止まる(1.6 秒) |
| `stop.bat` の経路: 打ちかけ → 画面で「キャンセル」 | `stop.bat` が 1 で断り、ランチャーは**待たずに**理由(「止めませんでした: … 閉じない …」)を受けた(2.4 秒) |
| 続けて「強制終了」(`stop.bat --force`) | 画面に訊かずに止まった(0.8 秒) |
| 画面を閉じたあとに停止 | 閉じた合図が届いていれば待たずに止まる(0.8 秒)。試験のブラウザーが合図を送る前に閉じたときは 409 `asking`(上の「合図が届かなかったとき」) |

`stop.bat`(`process_manager.py`)と画面(Chromium):

| 場面 | 結果 |
|---|---|
| 入力なしで「終了」 | 確認なしで止まる |
| 3機能に打ちかけ → `process_manager.py` | 画面に3機能の入力を並べた確認。「キャンセル」→ 戻り値 2・止まらない・入力は残る / もう一度 →「OK」→ 戻り値 0 |
| 打ちかけ → 「終了」 | 確認。「キャンセル」で止まらない・「OK」で止まる |
| 取り込みなどの最中に「終了」 | 「中断して終了しますか」。「キャンセル」で止めない・「OK」で中断して止める |
| 資材計算の帯の「終了」 | 統合画面の「終了」と同じ流れ(入力が無ければ確認なし) |
| 設定(ペナラベル・資材計算)・全サイズ・位置合わせ・ログの欄 | 打つ前は訊かない・打つと訊く |

デスクトップ版の窓(Linux の窓の通し試験 `tools/desktop_e2e.py`、42 項目): 窓の × で、打ちかけがあれば確認・
「キャンセル」で残る・入力が無ければ確認なしで exe も Python も終わる / 「終了」も同じ / デスクトップ版が
動いているあいだ `stop.bat` は止めずに戻り値 1。ランチャーが `WM_CLOSE` を送る経路は × と同じです。

- 試験: `tests/test_launcher_link.py`(入口の頼み・返事・戻り値)・`tests/test_launch_files.py`
  (起動ファイルを変えない・ランチャー専用の bat を置かない)

## 6. ランチャー側に伝えること(ランチャー 1.7.1 を読んで)

1. **README「現場のツールの登録のしかた」の coil-tools(旧名 coil-packing-tools)の行が 1.2.4 のままです。** 1.2.4 の
   `launcher_stop.bat` は 1.2.5 で取りやめました。all-tools の行と同じ書き方にしてください:
   exe 版 = `コイル梱包ツール.exe`・ポート**空**・停止は窓の ×(自動のまま) /
   ブラウザー版 = `Start.vbs`・停止は今ある `stop.bat`(自動で使う)。断られたときは 1.7.1 のとおり
   「強制終了しますか」→ `stop.bat --force` で止まります
2. **アプリの窓のツールの強制終了で、`stop.bat --force` を呼ぶのは窓が消えてからにしてほしい。** 1.7.1 は
   強制終了のとき、窓を閉じて 3 秒待ち、まだ消えていなければ `stop.bat --force` へ進みます。デスクトップ版が
   動いているときの `stop.bat` は(all-tools もコイル梱包ツールも)「窓を前に出す」ために exe をもう一度
   起動します。窓が閉じかけていると、新しく起動してしまいます。コイル梱包ツールは 1.2.5 で `--force` のときは
   起動しないようにしましたが、all-tools は同じ作りのままです。アプリの窓のツールでは、強制終了の次の手を
   PID(窓のプロセス)にするか、窓のプロセスが消えるのを待ってから `stop.bat` へ進むのが安全です

### 確かめきれていないこと

- Windows の実機で、業務ツール統合ランチャーの本体から起動・切り替え・終了すること
  (窓の確認が出ること、`stop.bat` の戻り値)
- Windows の自動試験(GitHub Actions)は請求の問題で止まっていて、1.2.5 の exe はまだ作られていません

## 7. 更新のため全 PC で止める(ランチャー 1.8.9・統合 1.2.64)

ランチャー 1.8.9 は、共有サーバーのツールのフォルダを上書きして更新する前に、全 PC でツールを止めます
(ふだんの［ツール停止］と同じ: `stop.bat` → 停止の API → プロセス)。処理中で断られたら利用者に知らせて 1 分ごとに
止め直し、待てないときは管理者が PC ごとに `stop.bat --force` を頼めます。依頼された点と、コイル梱包ツールの対応:

| 依頼 | 対応 |
|---|---|
| 1-(1) 止めた・動いていない → 0 | もとから(止めた・動いていない・残っていた印を片付けた) |
| 1-(2) 処理中で止めない → 0 以外(おすすめ 3)・標準出力の1行目に理由 | **3 にした**(1.2.63 までは 1)。1行目は `止めませんでした: <理由>`。画面で確認中の途中の知らせは標準エラーへ移した |
| 1-(3) `--force` で処理中でも止める | もとから(途中の処理・画面の確認を飛ばして止める)。デスクトップ版が動いているときは `stop.bat` では止めない(窓に「閉じて」と頼む経路) |
| 1-(4) `/nopause`・`STOP_NOPAUSE=1` で一時停止を飛ばす | **足した** |
| 1-(5) 道は `"%~dp0"`・全部 `"` で囲む | もとから `pushd "%~dp0"`。**半角の括弧があるフォルダ名でも切れないよう、道を括弧のブロックの中に書かないようにした** |
| 2. 書き込み先をツールのフォルダの外へ | DB・設定・作業状態・記録・ログは、もとから `%LOCALAPPDATA%` の下(`CoilPackingTools`・`PackingDetails`・`PackingPenaLabel`・`CoilMaterialTool`)。**梱包明細の CSV の出力先の既定がフォルダの中(`export\packing_details`)だったので外(`%LOCALAPPDATA%\PackingDetails\export`)へ移した**(前の場所の CSV は初回に写す)。資材計算の書き出し先の既定(いまは使っていない)も外へ。デスクトップ版の入口が `__pycache__` をフォルダの中に作っていたのを止めた。書き出し・記録・ログの置き場所に、相対の道などでフォルダの中を入れると保存しない |
| 3. 設定は 2 段 | もとから。既定はフォルダの中(`config\app.json`・コードの既定・配布設定)、現場で変えた値はフォルダの外(`settings.json`・`user_config.json`・`local.json`)。配布設定は `make_dist` で配布用フォルダに入り、版と一緒に上書きされる(起動時に、その PC にまだ無い項目だけ読む) |
| 4. 道を変えない | 起動ファイルの名前と置き場所は変えていない。`make_dist` は版を親フォルダ `機側用統合_VER…` にだけ入れ、一式は中の **`機側ツール`**(版の入らない名前。統合 1.2.66)に作る。配った先では `機側ツール` を決まった場所に置き、更新ではそこへ中身を上書きする(配布メモに書いた) |
| 5. 共有サーバーから実行 | `.venv` は作らない(PATH の Python か同梱の runtime)。フォルダの中のファイルを開いたままにしない(手元 DB は `%LOCALAPPDATA%`、共有の取り込み元は `%TEMP%` へ写してから読む)。デスクトップ版の exe は動いている間は使用中(exe の性質。ランチャーが止めてから上書きする) |

確かめ方(ランチャーの依頼のとおり):

- 処理の途中で `stop.bat` → 戻り値 3・1行目に理由(試験: `tests/test_launcher_link.py`。Linux では .bat を動かせないので、
  `stop.bat` の文面は `tests/test_launch_files.py` で固めてある)
- `stop.bat --force` → 処理の途中でも止まる(1.2.5 からの試験)
- フォルダを丸ごと上書きしても、データと現場の設定が残る(どれも `%LOCALAPPDATA%`。試験: `tests/test_outside_app_folder.py`)


## 8. 管理者以外停止モード(ランチャーを介さず、管理者の PC からほかの PC を止める。統合 1.2.67)

ランチャー経由で起動していない PC も含めて、更新の前にほかの PC のコイル梱包ツールを止める入口を**ツールの中**にも持つ。
業務ツール(python-web-tools VER4.8.129〜130)と同じ決まり。ランチャーの「更新のため全 PC で止める」(7)は据え置き。
**ただし同時には使わない。**

| 項目 | 決め(現場の指定) |
|---|---|
| お願いを出せる | 管理者パスワード(梱包明細の管理者パスワード。全ラインで共有)**かつ** この端末のアクセス権限に `Administrator`(共有の梱包資材マスタの「アクセス権限」表。ログインID・PC名の条件が合い、有効な行の「権限」欄。ログインID も PC名 も空の行は誰にも効かない) |
| 止める範囲 | お願いを出した PC 以外の、起動中の PC(ブラウザ版・デスクトップ版とも) |
| 保存していない入力・処理中 | 統合画面に「管理者が更新のため停止を求めています」の帯と残り時間を出し、利用者に任せる。残っているもの(3機能の画面の保存していない入力・取り込みなどの処理)が無くなれば自動で止まる(何も無ければ帯を 30 秒見せてから)。**5分たっても止まらなければ強制**で止める |
| 保存の持ち方 | 業務のデータ(明細・記録・発注・チェックリスト)には書かない。強制で止める前に、**その PC の手元の控え**(`%LOCALAPPDATA%\CoilPackingTools\data\停止控え\`)へ書く: 画面の保存していない入力の名前と打っていた値(変えた欄だけ・パスワードの欄は持たない)、資材計算の作業状態(LOT が入っているとき)。次の起動で、資材計算の作業は**そのまま戻し**、画面の入力は**統合画面に並べて見せる**(打ち直してもらう。LOT や重量を黙って欄へ戻さない)。知らせは利用者が「閉じる」まで出し続け、知らせた控えは `停止控え\戻した\` へ移して残す |
| 更新中 | お願いが出ているあいだ、お願いを出した PC 以外では**起動しない**(理由を待機画面・窓に出し、60 秒で閉じる) |
| ランチャー | お願いが出ているあいだ `stop.bat` は断る(`--force` でも。戻り値 1、1行目「止められませんでした: 管理者以外停止モード中のため…」) |
| 期限 | 解除を忘れても **1 時間で自動で解除**(「1時間延長」で延ばせる) |

使い方(統合画面の上の帯の「管理者停止」):

1. 理由と管理者パスワードを入れて「ほかの PC を止める」
2. 下の一覧で、各 PC が「止まりました」「強制で止めました」になるのを見る(「利用者を待っています」は残っているものを表示、
   「応答なし」は知らせが 3 分以上途絶えた PC)
3. **この PC のツールも閉じてから**、共有サーバーのツールのフォルダを上書きする
4. 新しい版で起動して確かめ、「更新が終わった(解除する)」(管理者パスワード)。1 時間で終わらないときは途中で「1時間延長」

しくみ:

- 共有の梱包資材マスタのフォルダ(資材計算の設定。配布設定で全 PC が同じ場所を見る)の `管理者以外停止\コイル梱包ツール\` に、
  お願い(`お願い.json`)と、動いている各プロセスの知らせ(`稼働中\<PC>__<ID>__<番号>.json`。1 分ごと・お願いへの答え)を置く。
  共有の SQLite には書かない。業務ツールは同じフォルダの `管理者以外停止\` 直下を使うので、中を分けて互いのお願いで止まらない
- 各プロセスは 5 秒ごとにお願いを見る。止め方は画面の「終了」・stop.bat と同じ道(デスクトップ版は窓ごと閉じる)
- 統合画面は 5 秒ごとに入口へたずね(入口のメモリだけ。共有は読まない)、お願いが出ていれば 3 機能の画面に保存していない入力を
  訊いて答える。**黙った画面を「残りなし」と取り違えない**: 裏に回ったタブ・最小化した窓はブラウザが 1 分に 1 回まで間引くので、
  10 分以内に問い合わせてきた画面の答えが届かないあいだは「確認を待っています」として止めない。保存していない入力を答えたあと
  黙った画面(凍った・固まった)は、その入力が残っているとして待つ(どちらも 5 分の期限は進み、期限で控えてから強制で止める)。
  閉じた画面は閉じた合図で待たなくなる
- 消えた入力の知らせは、利用者が「閉じる」を押すまで控えを片付けない(見る前に閉じた・落ちたら次の起動でもう一度出す)。
  資材計算の作業は戻した時点で控えから外す(二度戻すと、チェックリストへ積んだあとの作業を古い作業で上書きするため)
- ほかの管理者がほぼ同時にお願いを出すと、あとから書いた方が残る。書いたあとに読み直し、置き換わっていれば
  「ほかの管理者がほぼ同時に出した」と出す(この PC も止める側になる)
- **読めないときは「お願いは無い」にしない**: 見張りは前の判断のまま(期限は進む)、起動は止めずに記録に残す。
  読めないお願いは上書きしない。アクセス権限を読めないときは「Administrator ではない」と言わず、読めないと言って出さない
- **梱包資材マスタのフォルダを別の場所にしている PC には届かない**(配布設定で全 PC を同じ場所にしておく)。
  配布設定は初めて起動したときに読み込まれるので、**新しい PC の初めての起動だけは**、起動の確認が既定の場所を見る
- お願いには **1 時間の期限**がある(現場の決め。解除を忘れても、ほかの PC がずっと起動できなくならない)。更新が長引くときは
  管理者の画面の「1時間延長」で、いまから 1 時間に延ばす(お願いは同じまま)。期限で解除されると、動いている PC には
  「期限で自動で解除されました」と出る。**期限の 15 分前からは PC の時計でなく共有フォルダの時計で確かめる**(お願いの
  ファイルを書いた時刻と、試しに書いたファイルの時刻の差。PC の時計が進んでいても早く解除しない)。測れなければ PC の時計で決める
- お願いのファイルに署名は無い。共有のフォルダに書ける人なら、手で `お願い.json` を作っても止められる(共有のマスタを消せるのと同じ
  守り方: フォルダの書き込みの権限で守る)
- 帳票・印刷用の別のタブ(統合画面の外)の書き足しは訊かない(いつもの「終了」と同じ)
- **1.2.67 より前の版は応えない・一覧にも出ない。** 全 PC を 1.2.67 以降にするまでの更新は、ランチャーか stop.bat で止める
- 本体の組み立てに失敗して理由の画面のまま残った PC も、お願いで止まる
- 利用者が自分で終えたら「止まりました(利用者が終了しました)」を残す(一覧から消さない)。自分で終えるときは、いつもの「終了」と
  同じく保存していない入力を確かめてから終わるので、控えは書かない
- 共有に書けないあいだは記録をためない(最初の 1 回と直ったときだけ)
- **お願いを出した PC で解除できない**(その PC が壊れた・新しい版が起動しない)ときは、`管理者以外停止\コイル梱包ツール\お願い.json` を
  別の名前に変えると解除できる(起動を止めた画面にもこの道を出す)

確かめたこと: 試験 `tests/test_remote_stop.py`(パスワードと Administrator の両方が要る / 1 時間で解除・延長・PC の時計がずれていても共有フォルダの時計で決める / アクセス権限を読めなければ出さない /
重ねて出さない / 読めないお願いは上書きしない / 業務ツールのお願いでは止まらない / 更新中はお願いを出した PC 以外で起動しない・
読めなければ起動は止めない / stop.bat は `--force` でも断る / 何も残っていなければ帯を見せてから止まる / 保存していない入力・
処理中なら待ち、無くなれば止まる / 5分で控えてから強制・控えに失敗しても期限には止める / お願いを出した PC は止めない /
取り下げたら続ける / 読めなくなっても取り下げとは見ない / 画面の答えを待つ・閉じた画面は待たない / 控えは次の起動で一度だけ知らせ、
資材計算の作業は戻す・いま別の作業があれば戻さない・壊れた控えは残す)。ブラウザ版を実際に動かして(Chromium)、梱包明細の LOT に
打ちかけのままお願いを出す → 帯と残っているものが出る → 期限で強制で止まり控えが残る → 更新中は起動しない・stop.bat は断る →
